## v1からの訂正

**v1で唯一のP1として挙げた「レポートの記述が実装と食い違う」は誤りだった。撤回する。**
**あわせて「依頼の判定基準が実装と合っていない」という指摘も撤回する。**

結果として **V63 は P0・P1ともに0件**になる。判定「配布可能」は変わらない。

### 何を間違えたか

**誤り1：CSSの読み取り。**
`grep -noE "[^{}]*:focus[^{]*\{[^}]*\}"` で focus 関連のCSSを探したところ、
`:focus-visible` の行だけがヒットした。しかしV63の実際のCSSは**セレクタが2行にまたがっている。**

```css
/* 703-707行 */
:where(button,input,select,textarea,a,summary,[tabindex]):focus,
:where(button,input,select,textarea,a,summary,[tabindex]):focus-visible{
  outline:3px solid var(--accent)!important;
  outline-offset:3px!important;
  box-shadow:0 0 0 2px var(--panel),0 0 0 5px rgba(43,125,233,.28)!important;
}
```

**`:focus` にも付いている。** 私の正規表現は `{` を同じマッチ内に要求していたため、
1行目（`:focus,` で終わる行）を拾えず、2行目だけを見て
「`:focus-visible` にしか付いていない」と結論した。

**レポート §3.2 の「`:focus`と`:focus-visible`の両方で確認可能」は正確だった。**

**誤り2：フォーカスの測定環境。**
`button.focus()` 後に `outline-style: none` と測れたため、
「programmatic な `.focus()` では輪郭が出ない（それが `:focus-visible` の正しい挙動）」と説明した。
**これも誤り。**

原因は**ブラウザペインが背面にあり、ウィンドウ自体にフォーカスが無かったこと。**
`document.hasFocus()` が false のとき、`document.activeElement` は設定されていても
**`:focus` は一致しない**（CSSの仕様）。そのため輪郭が適用されていなかった。

ウィンドウにフォーカスがある状態で測り直した結果：

| 測り方 | outline-style | outline-width | `:focus` | `:focus-visible` |
|---|---|---|---|---|
| 実際のTabキー | **solid** | **3px** | **一致** | **一致** |
| `button.focus()`（programmatic） | **solid** | **3px** | **一致** | **一致** |

`document.hasFocus()` は **true**。

**つまり V63 は、依頼が示した判定基準（`button.focus()` 後に outline が `none` でないこと）を
そのまま満たしている。** 依頼の基準に問題はなく、**私の測定環境が原因だった。**

### 訂正後の判定

| 項目 | v1 | v2 |
|---|---|---|
| 総合判定 | 配布可能 | **配布可能**（変わらず） |
| P0 | なし | なし |
| P1 | 1件（レポートの記述） | **なし** |
| 誤認・対応不要 | 2件 | **4件**（上記2件を追加） |

**v1で「139・146行の `outline:none` が残っている」と書いた点も、実害の指摘としては不要。**
703行の `!important` が確実に上書きしており、しかも `:focus` と `:focus-visible` の両方を
カバーしているため、残っていても問題にならない。

### この失敗から得た確認手順

**フォーカスの見え方を判定するときは、先に `document.hasFocus()` を確認する。**
false なら、どんな実装でも `:focus` は一致せず輪郭は出ない。
**実装の欠陥と、測定環境の問題を区別できない。**

**CSSを正規表現で探すときは、セレクタが複数行にまたがる前提で書く。**
`:focus` を探すなら、`{` を同じマッチに含めない形にする。
