- `あなたの働き方：会社員` / `パートナーの働き方：会社員`

**受入条件**：AXツリーの状態一覧に「**パートナーあり**」を独立した軸として加え、

## 4. P2

### P2-1｜`domIntegrity()` が文書構造と版情報を1つの `ok` に混ぜている

`ok` の判定に `dedicatedTarget` / `targetUnique` / `rootSeparated` / `versionText` が入っています。
そのため**版バッジの文字だけが違うときも「DOM integrity failure」と出ます。**

**実測**（版バッジだけを `V86` に書き換えて `reportIntegrity()` を呼ぶ）

| 項目 | 実測 |
|---|---|
| `ok` | `false` |
| `hasHead` / `hasBody` / `hasNav` / `hasMain` | **すべて `true`** |
| `versionText` | `false` |
| コンソールの見出し | **`V87 DOM integrity failure after …`** |

**文書はどこも壊れていないのに、見出しは文書構造の失敗を名乗ります。**
詳細オブジェクトには `versionText:false` が入っているので情報は失われていませんが、
障害対応でログの1行目を読んだ人は「文書が消えた」と受け取ります。
V83の実害がまさに文書消失だったので、**この2つは区別できたほうが安全**です。

**修正案**：`ok` を残したまま `structureOk` と `metadataOk` を別に返し、
`console.error` の見出しを失敗した側で切り替えてください（例：`V87 release metadata mismatch after render`）。
`reportIntegrity()` の `signature` にもどちらの系統かを含めると、切り分けが早くなります。

### P2-2｜働き方ボタンが `type="submit"`

P1-1で数えた6件は、いずれも `type="submit"` です。
**いまは `<form>` の子孫ではないので無害**です（実測で `form` 祖先0件）。
ただし将来この領域を `<form>` に入れると、押した瞬間に送信・再読込が起きます。
単一HTMLでフォーム送信の意図はないはずなので、`type="button"` が正しいと思います。

**ただし、これはこちらも同じです。** 自分の汎用版v31を同じ観点で測ったところ、
可視ボタン45件のうち**27件が `type` 未指定（＝既定の `submit`）**で、

**同じ指摘を自分の版にも当てるべき状態**なので、こちらもv32で揃えます。
P2に置いたのは、どちらの版でも実害が出ていないためです。

## 6. 誤認・撤回した仮説

**5件を撤回しました。うち3件はこちらの測り方の誤りです。**

1. **「`MutationObserver` が描画ごとに `getComputedStyle` を呼び、レイアウト計算を大量に起こす」→ 撤回。**
   時間ではなく**呼び出し回数**（環境に依らない指標）で、同一タブのA/Bを取りました。
   監視あり 6,649 / 6,649、監視なし 6,646 / 6,646。**増分は3回**です。実質ゼロで、懸念は成り立ちません。
   （`__V87__.observer` に getter があるので `disconnect()` → `observe()` で切り替えられました。）
2. **「`V.storePlans([...])` を呼んだら primary が `[]` になった」→ 撤回（こちらのAPI誤用）。**
   実体は `storePlans86(options)` で、**引数はオプション**、保存するのは**グローバル `PLANS`** です。
   配列を `options` として渡していたため、空の `PLANS` が保存されていました。
   正しく `PLANS` を立ててから呼ぶと `["甲","乙"]` が primary・backup 両方に入ります。
3. **「将来購入で gap 38,500,000円 なのに `unresolved:false` はおかしい」→ 撤回（こちらの設定漏れ）。**
   `autoFitLoans` を設定していませんでした。OFFにすると `unresolved:true` になります。
   ON のとき false なのは「ツールが合わせると約束した状態」なので正しい挙動です。
4. **「`data-release-version` がソースに0件」→ 欠陥ではない。**
   `dataset.releaseVersion` というキャメルケースのAPIしか使っていないため、
   文字列としては現れません。実行時には `<html data-release-version="V87">` が存在します。
   **属性名を文字列で grep する検査は、`dataset` 経由の設定を取りこぼします。**
5. **「`#nav` を外した瞬間には `MutationObserver` が鳴らない」→ 撤回。**
   `MutationObserver` のコールバックは非同期（マイクロタスク）なので、
   除去直後の同期計測では0件になります。実際には直後の再描画で
   `after DOM mutation` として検出しています。

> **子どもの有無は無関係**で、トリガーはパートナーの有無です。
>
> 働き方は税・年金・国保の計算を分ける前提なので、読み上げや音声操作で区別できないと
> **意図しない人物の働き方を変えても気づけません。**
>
> 名前に人物を入れてください（`あなたの働き方：会社員` / `パートナーの働き方：会社員`）。
> `applyWorkType(who, type)` の `who` から組み立てれば、人物が増えても崩れません。
>
> **そして、AXツリーの状態一覧に「パートナーあり」を独立した軸として加えてください。**
> いまの4状態は「子どもあり・詳細設定」で同名0と出ますが、
> **同名を生むのは子どもではなくパートナー**です。
> 「単身／パートナーあり」×「子どもなし／子どもあり」の4通りで同名0を条件にしてください。
> これはV82で指摘した「経路×状態の網羅」の再発で、今回は**状態の軸が違います**。
>
> ### P2-1 `domIntegrity()` の文書構造と版情報を分ける
>
> 版バッジの文字だけが違うときも `V87 DOM integrity failure` と出ます
> （実測：`hasHead`・`hasBody`・`hasNav`・`hasMain` すべて `true`、`versionText:false`）。
> **文書はどこも壊れていないのに、見出しは文書構造の失敗を名乗ります。**
> V83の実害が文書消失だったので、障害対応で読み違えます。
>
> `structureOk` と `metadataOk` を別に返し、`console.error` の見出しを失敗した側で切り替えてください。
> `signature` にも系統を含めると切り分けが早くなります。
>
> ### P2-2 働き方ボタンの `type="submit"` を `type="button"` へ
>
> いまは `<form>` の外なので無害ですが（実測 `form` 祖先0件）、
> 将来 `<form>` に入れると押した瞬間に送信・再読込になります。
>
> ### 維持してほしい項目（独立測定で確認済み）
>
> - 描画経路の事後検査：`#nav` を外して**実入力**で再描画すると `after render` が鳴る（V85は0件）
> - `[data-app-version]` は `SPAN#appVersion` 1件のみ、`<html>` は `data-release-version`
> - V83の破壊2行を実行しても、変わるのは版バッジだけで文書は残る
> - 旧版フック7入口が**わざとV00へ汚してから呼んでも**すべてV87へ着地
> - 実行時の `loadPlans`／`storePlans` が `loadPlans86`／`storePlans86`（＝現行実装）で、
>   他版のキー（`lpcf_plans`／`lpcfg_plans`）を読み書きしない
> - 冷起動×実タップの上部8タブ：390／375／430／1280 すべて合格、はみ出し0、console error 0
> - 詳細6タブ：全幅で合格
> - `negativeControls()` 2/2、`audit()` の8項目すべて true
> - V86回帰：`strictRaw` の判定・破損からの復旧・別タブ競合・取得済みと将来購入の分離・
>   保存プラン名つき操作名（同名0）
>
> ### 返却してほしいもの
>
