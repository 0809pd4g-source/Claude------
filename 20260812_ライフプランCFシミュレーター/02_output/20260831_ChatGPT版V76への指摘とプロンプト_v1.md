## 3. P1-1　セクション1のバッジが、中身と合っていない

`ステップ1` と表示していますが、**このセクションにはリタイア年齢（ステップ2の項目）が入っています。**
説明文自身がそう書いています。

実測（`#s-input .v61-section` の中身）:

| セクション | バッジ | 実際に入っている項目 | 判定 |
|---|---|---|---|
| 1. 世帯と収入 | **`ステップ1`** | 世帯／子どもの人数／現在年齢／働き方／現在の年収／**リタイア年齢** | **ずれている** |
| 2. 毎月の家計と現在資産 | `ステップ1・2` | 基本生活費／年間の保険料／預金・現金／運用資産／NISA残高／NISA／DC | 正しい |
| 3. 住まいと長期前提 | **`ステップ2`** | 住宅購入を検討する／現在の家賃・住居費／**物価上昇率／運用利回り** | **ずれている** |

**同じ「複数ステップが混在する」状況を、3セクションで3通りに扱っています。**
セクション2が `ステップ1・2` と正しく書いているだけに、1と3が単一表記なのは
「このセクションはステップ1だけ」と読めてしまいます。

### 修正案（実際に当てて確認しました）

セクション1のバッジを `ステップ1・2` にすると、セクション2と同じ規則になります。

```html
<h3><span class="v76-section-step">ステップ1・2</span>1. 世帯と収入</h3>
```

セクション3は、下のP1-2の修正（長期前提をステップ2に含める）を入れれば
`ステップ2` が正しくなります。**2つの修正が噛み合います。**

## 4. P1-2　ガイドの3ステップが、アプリの要求を網羅していない

**ガイドどおりに全部入力しても、4段階目に到達しません。**

実測:

```text
ステップ1（年齢・年収・生活費）＋ステップ2（リタイア年齢・保険・現在資産・積立・住まい）
  → stage 2「家計の全体像を確認できます」

さらに 長期前提（物価上昇率・運用利回り）を入れて
  → stage 3「判断の準備が整いました」
```

`v61Completion()` はこうなっています。

```js
const decisionReady = householdReady && !!c.assumptions && childReady && housingDetailReady;
```

- `assumptions`（物価上昇率・運用利回り）… **ガイドの3ステップに一度も出てきません**
- `housingDetailReady` … 購入する場合は**物件価格・返済期間**が必要。ガイドは「住まい」だけ
- `childReady` … お子さんがいる場合は**生年**が必要。ガイドに記載なし

ガイドはステップ3を**確認画面（診断）**と説明しているので、
利用者は「ステップ2まで入れれば入力は終わり」と読みます。
実際にはそこで止まり、**何を入れれば次に進むのか、ガイドには書かれていません。**

### 購入世帯ではもっと目立ちます（実測）

| 操作 | `stage` | 見出し | 未入力 |
|---|---:|---|---|
| ガイド全項目＋長期前提（賃貸） | 3 | 判断の準備が整いました | — |
| **「住宅購入を検討する」をONにする** | **2** | **家計の全体像を確認できます** | **`housingDetails`** |

**チェックを1つ入れただけで段階が戻り**、ガイドが「住まい」としか書いていない
物件価格・返済期間を要求されます。このツールの中心的な用途が住宅購入の判断なので、
ここが分からないのは効きます。

### 修正案（実際に当てて確認しました）

ステップ2の項目に長期前提を加えるのが最小です。

```html
<div class="v76-guide-step" data-v76-step="2">
  <div class="v76-guide-main"><b>2</b><strong>資産・住まい</strong></div>
  <small><em>入力項目</em>リタイア年齢・保険・現在資産・積立・住まい・長期前提（物価上昇率・運用利回り）</small>
</div>
```

実測：この1行で **ガイドどおりに入れると stage 3「判断の準備が整いました」に到達**します。
1828〜375pxでガイド・ページの横はみ出しはいずれも0のままでした（文字が増えても崩れません）。

購入世帯・子どものいる世帯については、ステップ2の下に一言添えると誤解が消えます。

```html
<p class="v76-guide-note"><b>住宅購入を検討する場合は</b>物件価格と返済期間、
<b>お子さんがいる場合は</b>生年まで入れると「判断の準備が整いました」になります。</p>
```

## 5. P2-1　`guideMapAudit()` が、守るべき対応関係を検出できない

判定式がバッジを**集合**でしか見ていません。

```js
['ステップ1','ステップ1・2','ステップ2'].every(x => badges.includes(x))
```

**負試験（実測）**：セクション1と3のバッジを入れ替えても `ok` は変わりません。

| | `badges` | `guideMapAudit().ok` |
|---|---|---|
| 無改変 | `['ステップ1','ステップ1・2','ステップ2']` | true |
| **1と3を入れ替え** | `['ステップ2','ステップ1・2','ステップ1']` | **true（検出できない）** |
| 戻したあと | 元に戻る | true |

**この監査は今回の改修を守るために作られたのに、対応関係が壊れても通ります。**
「3つの文字列がどこかに存在するか」しか見ていないためです。

### 修正案（実際に当てて確認しました）

セクションの**位置ごと**に期待するバッジを比べます。

```js
function v76GuideMapAudit(){
  const flow=document.querySelector('#s-input .v76-guide-flow');
  const steps=flow?[...flow.querySelectorAll(':scope > .v76-guide-step')]:[];
  const expected=[
    ['1','基本情報','現在年齢','基本生活費'],
    ['2','資産・住まい','リタイア年齢','現在資産','長期前提'],
    ['3','診断','上部メニュー','見直し候補']
  ];
  const stepChecks=expected.map((e,i)=>{
    const el=steps[i],txt=(el&&el.textContent||'').replace(/\s+/g,' ').trim();
    return {step:e[0],ok:!!el&&e.slice(1).every(x=>txt.includes(x)),text:txt};
  });
  /* ★セクションの順番どおりに、期待するバッジと一致するかを見る。
       v76は集合（includes）で見ていたため、1と3を入れ替えても合格していた。 */
  const wantBadges=['ステップ1・2','ステップ1・2','ステップ2'];
  const gotBadges=[...document.querySelectorAll('#s-input .v61-section')]
    .map(s=>s.querySelector('.v76-section-step')?.textContent.trim())
    .filter(x=>x!==undefined);
  const badgeOk=wantBadges.length===gotBadges.length
    && wantBadges.every((w,i)=>gotBadges[i]===w);
  const r=flow&&flow.getBoundingClientRect();
  const overflow=flow&&r?Math.max(0,flow.scrollWidth-flow.clientWidth):null;
  return {
    ok:!!flow&&steps.length===3&&stepChecks.every(x=>x.ok)&&badgeOk
       &&!!flow.querySelector('.v76-guide-note')&&(overflow===null||overflow<=1),
    steps:steps.length,stepChecks,badges:gotBadges,expectedBadges:wantBadges,badgeOk,overflow
  };
}
```

実測：この版は**無改変で `ok:true`**、**1と3を入れ替えると `ok:false`** になりました。

## 6. 分かりやすさについての所見

ご質問の4点に、実物を見た印象で答えます。

1. **ステップ1の3項目が何か** … 明確です。「入力項目」ラベルが効いています。
2. **ステップ2で追加確認する項目が何か** … **不十分**（長期前提が抜けている・P1-2）。
3. **ステップ3が入力欄でなく上部メニュー「診断」であること** … 明確です。
   「確認画面」というラベルで入力と区別できています。**ここは良い工夫だと思います。**
4. **「2. 毎月の家計と現在資産」にステップ1と2が混在する理由** … 説明文で分かります。
   ただし**セクション1が同じ状況なのに単一表記**なので、規則が読み取れません（P1-1）。

文言の長さ・灰色の薄さについては、375pxまで折返し・文字切れ0で、**問題は見つかりませんでした。**

**設計として良いと思った点**を1つ挙げます。ステップ3を「入力ではなく確認画面」と
明示したことで、「入力が終わらないと診断が見られない」という誤解を避けられています。
こちらの版はこの区別を持っていないので、取り込みを検討します。
