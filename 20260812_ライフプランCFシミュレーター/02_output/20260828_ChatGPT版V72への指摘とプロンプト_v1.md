## P1-1　「どの枠を使うか」のラベルが縦書き状に潰れている（1280px以上）

**そちらの監査自身が検出している、実在の崩れです。**

### 実測（1440×900・資産形成のページ）

| | 値 |
|---|---:|
| ラベル「どの枠を使うか」の幅 | **13.7px** |
| 同 高さ | **131px** |
| 隣の `<select>` の幅 | 295px |
| 行（`.f`）の幅 | 365px |
| ほかのラベルの幅 | 210.7px |

**7文字が1文字ずつ縦に折り返っています。**

### 画面幅による違い

| 画面幅 | ラベル幅 | `layoutAudit().labelWidths` |
|---|---:|---|
| 1440×900 | **13.7px** | **false** |
| 1280×720 | **13.7px** | **false** |
| 1024×768 | 127px | true |
| 768×1024 | 162.5px | true |

**1280px以上で起きます。** 1024px以下ではカードの列数が減って行が広くなるため出ません。

### 原因（こちらで特定しました）

`.f` は `display:flex` です。ラベルは `min-width: 0` / `flex-basis: 0%` で、
**隣の `<select>` が選択肢の文字列（「つみたて投資枠から使い、あふれた分は成長投資枠」）に合わせて
295pxを要求する**ため、365pxの行では **365 − 295 − 38（単位のspan）= 約14px** しか残りません。

ほかの行は数値入力なので細く、この行だけが `<select>` の内容幅で押し負けます。

### 修正案（**実際に当てて確かめました**）

```css
/* 選択肢の文字列の長さで幅を決めさせない。
   ラベルには下限を与える（ほかの行は210.7pxなので、6em程度でも十分に読める）。 */
.f > select{ min-width: 0; }
.f > label { flex: 0 0 auto; min-width: 6em; }
```

| | 当てる前 | 当てた後 |
|---|---:|---:|
| ラベルの幅 | 13.7px | **75px** |
| ラベルの高さ | 131px | **19px** |
| `<select>` の幅 | 295px | 234px |
| **`layoutAudit().ok`** | **false** | **true** |

外すと元に戻ることも確認しています。

## P1-2　監査が390pxで、無改変のファイルに対して `false` を返す

### 実測（390×844・無改変）

| | 値 |
|---|---|
| `layoutAudit().ok` | **false** |
| `geometry` | **false** |
| `structure` / `mobileTabs` / `labelWidths` / `parentNav` | すべて true |

原因はシェルの高さです。

| ページ | 説明文の文字数 | 行数 | シェル高 |
|---|---:|---:|---:|
| 世帯・収入・生活 | 31 | 1 | 264.6 |
| **住宅とローン** | 32 | **2** | **286.2** |
| 教育費 | 29 | 1 | 264.6 |
| 資産形成 | 36 | 1 | 264.6 |
| ストレステスト | 31 | 1 | 264.6 |
| **用語・制度の解説** | 36 | **2** | **286.2** |

**説明文が390pxで2行に折り返す2ページだけ、21.6px（1行分）高くなります。**

判定式はこうなっています。

```js
const geometry = ['section.x','section.y','section.w',
                  'shell.x','shell.y','shell.w','shell.h','headHeight']
  .every(k => same(k));
```

**`shell.h` と `headHeight` の完全一致を求めているため、
説明文の長さが違う以上、狭い画面では原理的に成立しません。**

### これが問題である理由

**レイアウト崩れではありません。** 説明文が長ければ折り返すのは正しい挙動です。
問題は、**監査が390pxで合否の門として使えないこと**です。

こちらは最初、390pxで負試験を回して6件すべて「検出」と出ましたが、
**基準線がすでに `false` だったため、検出と地の失敗を区別できていませんでした。**
1024px（基準線が true）でやり直して、はじめて意味のある判定になりました。

### 修正案

`shell.h` と `headHeight` を、狭い画面では**許容差を持たせる**か、判定から外してください。

```js
/* 説明文の行数はページごとに違うため、狭い画面では高さの完全一致を求めない。
   高さの一致を求めるのは「同じ行数で描けるはずの幅」だけにする。 */
const narrow = window.innerWidth < 760;
const geoKeys = narrow
  ? ['section.x','section.y','section.w','shell.x','shell.w']
  : ['section.x','section.y','section.w','shell.x','shell.y','shell.w','shell.h','headHeight'];
const geometry = geoKeys.every(k => same(k));
```

**もう1つの選択肢は、説明文を1行に収める長さへ揃えること**です。
そのほうが見た目も揃いますが、文言を削ることになります。**どちらを採るかはご判断ください。**

## 4. 誤認・対応不要（こちらが疑って、確かめたら自分の誤りだったもの）

### ① 「最大幅の変更を検出できない」→ こちらの壊し方が効いていなかった

`sec.style.maxWidth='700px'` では**幅が969pxのまま変わりませんでした**（CSS側の指定に負けた）。
`setProperty('max-width','700px','important')` で当てると幅が700pxになり、
**監査は `false` を返し、`section.w` も `edu:700`／他は969 と正しく拾いました。**

**「検出できない」と書く前に、壊れているかを確かめる必要がありました。**

### ② 「保存プランを開くと年収が復元されない」→ `change` を投げていなかった

年収を700万に変える手で `input` だけを投げており、値が反映されていませんでした。
`change` も投げると `hBase = 7,000,000`／収入表も7,000,000／初年度給与も7,000,000。

保存の往復も正常です。

| | 実測 |
|---|---|
| 保存 → 変更 → 開き直し | 名前「回帰A」・年収6,000,000・収入表6,000,000・初年度給与6,000,000 |

### ③ 「年額／月額の切替が元に戻らない」→ 同じボタンを2回押していた

これは**トグルではなくセグメント式**（「年額」「月額換算」の2ボタン）でした。
正しく往復させると戻ります。
