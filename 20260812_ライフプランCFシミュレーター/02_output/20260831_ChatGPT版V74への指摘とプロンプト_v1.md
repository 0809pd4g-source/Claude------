## 4. こちらの仮説を1件、実測して取り下げました

**立てた仮説**：狭い画面の `geometryKeys` は V73 のまま `shell.h` と `headHeight` を除いている。

```js
const narrow = innerWidth <= 760;
const geometryKeys = narrow
  ? ['section.x','section.y','section.w','shell.x','shell.w']   // ← 2つを除いたまま
  : ['section.x','section.y','section.w','shell.x','shell.y','shell.w','shell.h','headHeight'];
```

製品側を直したのに検査を緩めたままなら、**将来 `min-height:2lh` を外しても気づけない**——
そう考えて、実際に外して確かめました。

```text
無改変              : ok=true    headHeight=[194.4]        shell.h=[300.5]
min-height:2lh を外す: ok=false   headHeight=[194.4,172.9]  shell.h=[300.5,278.9]
                       geometry=false   section.y 差 21.6px  ← 検出できている
戻したあと           : ok=true
```

**取り下げます。** `section.y` が同じ差を運ぶため、**2つを除いていても回帰は検出できます**。
（皮肉なことに、V73でこちらが「`section.y` が同じ情報を運んでいる」と指摘したのと同じ性質が、
今回は検査を守る側に働いています。）

## 5. P2（動作の欠陥ではありません）

### P2-1　コメントの記述が実態と合っていない

該当箇所のコメントが V73 のままです。

```js
/* 狭い画面では説明文がページごとに1〜2行へ自然に折り返すため、
   shell.h / headHeight の完全一致を合否条件にしない。位置・幅は引き続き測る。 */
const narrow = innerWidth <= 760;
```

**V74では `min-height:2lh` で2行に固定したので、「1〜2行へ自然に折り返す」はもう起きません。**
実測でも `headHeight` は 194.4 の1種類、`shell.h` は 300.5 の1種類です。

このままだと、次に読んだ人が
**「モバイルでは見出し高がページごとに違うのが正常」**と受け取り、
`min-height:2lh` を見た目の調整だと判断して外してしまう恐れがあります。

**提案（どちらでも構いません）**

案A：コメントを実態に合わせ、除外の理由を「保険」として書き直す。

```js
/* 狭い画面では、説明文を `#v72DetailDesc{min-height:2lh}` で2行分に固定しているため、
   shell.h / headHeight はページ間でそろう（V74で実測 194.4 / 300.5 の各1種類）。
   ここで2つを合否条件から外しているのは、端末のフォント設定で行高が変わったときに
   誤検出しないための保険であって、**高さが違ってよいという意味ではない**。
   高さの回帰は section.y が拾う（min-height を外すと geometry=false になることを確認済み）。 */
```

案B：そろっているので2つを戻し、判定を明示的にする。**実測では戻しても合格します**
（390pxで各1種類のため）。ただし端末のフォント設定差で脆くなる可能性はあるので、
こちらとしては**案Aを勧めます**。
