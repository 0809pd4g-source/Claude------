## 1. 総合判定：**条件付き配布可能**

保存・読込み・JSON往復・V61互換・パラメータ中心思想・プライバシーは**すべて成立している。**
配布を止めるほどの欠陥は、通常操作の範囲には見つからなかった。

ただし**保存が失敗したときに利用者へ何も伝わらない**（P0-1）。
通常は起きないが、プライベートブラウズなど localStorage が使えない環境では
**保存したつもりで消える。** ここだけ先に直せば「配布可能」になる。

**保存と復元が、入力値だけでなく結果まで一致した。**

## 3. P0（必須修正）

### P0-1. 保存が失敗しても、利用者に何も伝わらない

**保存したつもりで消える。** これが唯一の必須修正。

再現（2通りとも同じ結果）：

```js
// (a) 保存容量の超過を模す
Storage.prototype.setItem = function(k,v){
  if(k==='lpcf_v61_plans'){ var e=new Error('QuotaExceededError'); e.name='QuotaExceededError'; throw e; }
  return orig.apply(this,arguments);
};
// (b) localStorage 自体が使えない環境を模す
Storage.prototype.getItem = function(){ throw new Error('SecurityError'); };
Storage.prototype.setItem = function(){ throw new Error('SecurityError'); };
```

そのうえで「この入力を保存」を押す。

| | 実測 |
|---|---|
| 外へ漏れた例外 | **なし**（内部で処理されている） |
| 画面の生存 | **生存**（タブも押せる） |
| `window` の error イベント | **0件** |
| **利用者への知らせ** | **0件** |
| 保存の結果 | **保存されていない** |

- 期待値：保存できなかったことと理由が画面に出る
- 実値：**何も出ない。** ボタンを押した見た目の反応と、実際の結果が食い違う
- 利用者への影響：**プライベートブラウズや保存容量が逼迫した端末で、
  保存したつもりのプランが失われる。しかも失われたことに気づけない**
- 直し方：`storePlans()` を `try/catch` で囲み、失敗時に
  「保存できませんでした。ブラウザの保存領域が使えないか、容量がいっぱいです。
  『ファイルに書き出す（JSON）』で保存してください」と出す。
  **既にあるJSON書出しが代替手段になるので、そこへ誘導できる**

## 5. 誤認・対応不要

**私が一度は不具合と判断しかけたが、実際は問題なかったもの。**

- **「保存プランを開いても復元されない」→ 私の押し間違い。**
  カードを特定する処理が、2枚のカードを含む親要素の文字列を見ていたため、
  ケースAを探したつもりでケースBのボタンを押していた。
  正しく押すと**入力・結果とも完全に復元される。**
- **「不正JSONを読み込んでも何も言わない」→ 測るのが早すぎた。**
  `FileReader` は非同期なので、同じ呼び出しの中で確認すると何も起きていないように見える。
  待って確認すると**明確なエラーメッセージが出る。**
- **「console に null／NaN の警告が出る」→ 私の負試験が原因。**
  新しいタブで初期状態から開くと**console 0件。**
  QAレポートの「console error/warning 0件」は正しい。
- **「JSON-A の中身が JSON-B になっている」→ 私が同名で2回保存したため。**
  画面に「同じ名前で保存すると、確認後に上書きします」と明記されており、**仕様どおり。**
- **保存容量超過の負試験そのものは未実施。** この環境では10MB書き込んでも超過しなかったため、
  `setItem` が例外を投げる状況を作って代替した。**実機での超過は未検証。**

## 4.【P1】壊れた値を持つプランを開くと、画面に `null` が出ます

```js
localStorage.setItem('lpcf_v61_plans', JSON.stringify([{name:'不正値',
  params:{income:{hBase:'あいう'}, econ:{deposit:null}, family:{ageH:NaN}}}]));
```

読み込んで開くと、実行時エラー0件・画面は壊れない・数値欄にNaNは出ない（**ここは良い作りです**）。
しかしヘッダーが **「あなたnull歳〜100歳」** になり、プラン名も復元されません。

読込時に数値欄を検証し、不正なら既定値に置き換えたうえで
「一部の値が読めなかったため既定値にしました」と伝えてください。

なお **`年収="あいう"` のレコードは取り込まれます**が、
**必須フィールドが欠落したレコードは取り込まれません。**
型の検証だけが抜けているので、そこを揃えると一貫します。

## 7. こちらの誤りだったもの（参考）

検証の途中で不具合と判断しかけたものが4件あり、いずれも私の測り方の問題でした。同じ落とし穴を共有します。

- **「開いても復元されない」→ 私の押し間違い。**
  カード特定処理が、2枚のカードを含む親要素の文字列を見ていました
- **「不正JSONで何も言わない」→ 測るのが早すぎ。**
  `FileReader` は非同期です。待つと明確なエラーが出ます
- **「console に null／NaN の警告」→ 私の負試験が原因。**
  新しいタブで初期状態から開くと0件です
- **「JSON-A の中身が JSON-B」→ 同名で2回保存したため。**
  画面の「同じ名前で保存すると、確認後に上書きします」のとおりで、仕様どおりです

**保存容量超過の負試験そのものは未実施です。**
この環境では10MB書き込んでも超過しなかったため、`setItem` が例外を投げる状況を作って代替しました。
**実機での超過は未検証**であることを申し添えます。
