### P1-1 取得済み持ち家の現在借入

**再現しました。** 現在40歳・35歳取得・残債3,000万円・返済期間5年で：

| 項目 | v33 | v34 |
|---|---|---|
| `readiness().stage` | **3** | **1** |
| `housingReadiness()` | `na` | `insufficient` |
| 初年度ローン返済 | **0円** | 判断を止めるので表示しない |
| 初年度ローン残高 | **0円** | 同上 |
| 要約の返済総額 | 30,768,745円 | 同上 |
| 要約の完済年齢 | **39歳** | 同上 |

**同じ借入について、年次表は「返済0円・残高0円」、要約は「返済総額3,076万円・完済39歳」と言っていました。** 2つの表示が食い違っていたのに、どちらの側からも検査していませんでした。

v33の `ownedHousingReadiness` は「返済期間が1年以上か」しか見ていません。`years=5`・`elapsed=5` は1年以上なので通ってしまいます。**「0年を止める」を作ったとき、「もう終わっている」を同じ問題だと思っていませんでした。**

v34では `loanDecisionIssues(P)` を作り、次を阻止条件にしました。

1. 残存期間 `years - (ageH - buyAge)` が正
2. 金利段階が1件以上
3. 1段目の開始年が1
4. 開始年が厳密に増加
5. 金利が有限・0以上100未満
6. 借入額が有限・0以上

**マイナス金利も阻止に変えました。** v33は警告だけで段階3のままでした（金利−5%で返済総額1,287万円＜元本3,000万円）。

### P1-2 意思決定・保存・JSON取込の検証を一本化

**3件とも再現しました。**

| 負試験 | v33の実測 | v34 |
|---|---|---|
| `house.mgmtFee = -1,200,000` | 段階3・初年度住宅費 **−867,000円**・`commitPlans()` が **true** | 段階1・blocking「管理費」・保存 **false** |
| `econ.inflation = 1e307` | 段階3（`badResultsIn` は検出しているのに準備度が使っていない） | 段階1・blocking「試算の結果が数値になりません」・保存 false |
| JSON取込（不正なcurrent） | 通知なしで受理、`ageH` 41→40・`inflation` 1e307、段階3 | **拒否・PARAMSも保存プランも変化なし**・理由を通知 |

**v33は検査が3か所に散っていました。**

- `readiness()` … `badLoansIn` だけ
- `commitPlans()` … 数値・借入・資金・結果の4種
- JSON取込 … **何も検査していなかった**

そのため「保存はできないが診断は読める」と「取込だけ素通り」が同時に成立していました。v34は `decisionValidation(P, options)` を正本にして、`readiness()`・`commitPlans()`・JSON取込（currentとsaved plansの両方）が**同じ検査**を使います。

戻り値は `{ok, blocking, warnings, loanIssues, simulationIssues}` です。`blocking` は判断・保存・取込を止め、`warnings` は止めませんが「準備できた」とは言いません（金利15%超など）。

**描画のたびに再計算しないよう**、`readiness()` は計算済みの `SIM` を `options.sim` で渡します。

JSON取込は**先に全部を検査してから**反映します。1件でも駄目なら何も変えません（途中まで反映して止まらないように）。

### P2-1 pending と marker の結び付き

**再現しました。** 10年前を示す印（`at:0`）と無関係な pending で、v33は `十年前の保留候補` を現在の保存プランとして自動採用していました。

v34では印に `payloadHash`・`baselineHash`・`version`・`tab`・`at` を持たせ、

| 条件 | v34の挙動 |
|---|---|
| 指紋一致・新しい印 | 採用（「最新の内容かどうかを必ず確かめてから」と添える） |
| **指紋不一致** | **採用しない** |
| 印なし | 使わない |
| 正常な控えあり | **控えを優先** |
| 24時間より前・時刻不明 | 採用するが「**この候補は24時間より前のもの**です」と明示 |
| 旧形式の印（指紋なし） | 採用するが「**古い形式の印から戻したため、内容が最新とは限りません**」と明示 |

ご指摘のとおり、**古いという理由だけでは捨てていません**（最後に残った唯一の手掛かりかもしれないので）。ただし通常の最新保存と同じ顔では出しません。

## 5. 見てほしいところ

1. **`decisionValidation` の blocking と warnings の切り分け**。いまは金利15%超だけが warning です。他に「止めないが断定させない」に回すべきものはありますか。
2. **JSON取込の粒度**。1件でも駄目なら全部拒否にしています。「問題のあるプランだけ飛ばして残りを取り込む」ほうが親切という考えもありますが、部分適用は状態を読みにくくするので全拒否にしました。
3. **`NONNEG_PATHS` の網羅**。いまは住宅費・保険料・資産の16パス＋生活費テーブルです。抜けがないか。
4. **数値欄の残り**。`min` を付けていない27件はすべて変動率系（負が正当）のつもりですが、確認いただけると助かります。
