## A. リリースを止めるべき不具合

### A-1. V57自身の判定が「不合格」を返す（6/8・総合 false）

実ブラウザで `v57FinalAudit()` を実行した結果：

```
○ 中立タイトル      ｜ ライフプラン・シミュレーター｜多人数家計コア Phase 7 V56
○ 旧個別語句の非表示 ｜ なし
○ ID重複なし        ｜ なし
○ 本文スキップリンク ｜
○ 操作要素の名前     ｜ すべて設定済み
○ 計算値の有限性     ｜ 65年分
× 人物正本          ｜ 0
× 収入ストリーム正本  ｜ 0
→ passed 6 / total 8 ／ pass: false
```

**落ちている2件は、V57が「修正した」と主張しているまさにその箇所である。**
QAレポート第2節は「正本の人物・収入ストリームから年次計算行へ一方向に橋渡しし」と書いているが、
その正本が実行時に**0件**である。

- 再現手順：V57をブラウザで開き、コンソールで `v57FinalAudit()` を実行する
- 期待値：`pass: true`（正式リリース候補と称するため）
- 実値：`pass: false`、`人物正本 0`、`収入ストリーム正本 0`

### A-2. 「成人を追加」を押しても人物が増えない

依頼事項1（追加成人の年次収入・所得税・住民税・社会保険の増分を確認）は**実施できなかった。**
成人を追加できないためである。

- 再現手順：
  1. ヘッダーの「人物・扶養・持分」を開く
  2. 「＋ 収入のある成人を追加」を押す（「成人を追加」でも同じ）
  3. `v57FinalAudit()` を実行する
- 期待値：`人物正本` と `収入ストリーム正本` が増える
- 実値：**押す前 0／0 → 押した後 0／0**（両方のボタンで確認、変化なし）

**そのため依頼事項2（本人・配偶者の旧互換値と正本の二重計上）も判定できない。**
比較する正本の値が存在しない。

### A-3. 人物モデルが2つあり、つながっていない（原因候補）

画面に表示されている人物台帳は **V41世代の層**である。

```
v41-person-grid 「本人／本人／表示名／現在年齢／退職年齢」
v41-person-actions 「配偶者を追加／子どもを追加／扶養家族を追加」
```

一方、監査と（QAレポートが言う）新しい計算経路が読むのは V52以降の「正本」（`persons` / `incomeStreams`）で、
こちらは**0件**である。

**つまり利用者が見て編集する台帳と、計算が読む正本が別物になっている。**
画面には「本人」が居るのに正本は0人なので、A-1・A-2はこの1点で説明がつく。
「3人目以降が反映されない」以前に、**1人目も正本に入っていない。**

### A-4. 実行時の版表記が V57 にならない

- 静的な `<title>`：`ライフプラン・シミュレーター｜正式リリース判定版 V57`
- 実行時の `document.title`：**`…多人数家計コア Phase 6 V55`** →（数秒後）**`Phase 7 V56`** →（再度）**`V55`**

`document.title` への代入が**52箇所**あり、`TITLE` 定数も V52→V54→V55→V56 と再代入されている。
最終行（10523行目）で V57 を入れているが、その後に走る描画処理が `document.title=TITLE` で上書きする。

- 期待値：利用者に見える版表記が V57 で安定する
- 実値：V55 と V56 の間で揺れ、V57 にならない
- 影響：利用者が版を報告できない。不具合の切り分けができない

## D. 根本の問題：監査が品質を保証していない

A〜Cは個別の不具合だが、**なぜこれが「正式リリース候補」まで来たのか**が本質的な問題である。
`v57FinalAudit()` の8つの検査は、**検出したい欠陥を検出できない作りになっている。**

| 検査 | 実装 | なぜ通ってしまうか |
|---|---|---|
| **収入ストリーム正本** | `Array.isArray(gm.incomeStreams)` | **配列かどうかしか見ない。空配列でも合格。** 「3人目以降の収入が年次収支に届かない」という当の不具合を検出できない |
| **人物正本** | `gm.persons.length >= 1` | 1人以上あるかだけ。**年次計算行に届いているかを見ていない** |
| 旧個別語句の非表示 | `body.innerText` に含まれないか | **`<option>` は `innerText` に出ない。** 一覧を開けば見える語句を素通りさせる |
| 中立タイトル | `/ライフプラン/` を含み、特定2語を含まないか | **V55と表示されていても合格する** |
| 操作要素の名前 | 表示中で名前のないものが0件か | 実際には**81個ある**のに「すべて設定済み」を返す。`visible()` の判定が実態と合っていない |
| 計算値の有限性 | NaN・Infinity が無いか | 値が**正しいか**は見ていない。0でも一定でも合格 |

**「橋渡しを修正した」ことの検証が「配列かどうか」になっている。**
これは実装の有無を確認しているだけで、**数値が動いたことを確認していない。**
依頼文自身が「静的構文チェックだけで合格にしない」「年次キャッシュフローと人物別税額が同時に増えることを数値で確認する」
と書いているが、**監査はその確認をしていない。**

## E. 構造の問題（今回の原因の土台）

- **層が同居している**：V10／V14／V15／V25／V27／V41／V51／V52／V54／V55／V56／V57 の世代のコードとIDが並存
  （`v15QuickProperty`／`v25CompareProperty`／`v27PlanSelect`／`v41-person-grid`／`v56StabilityDialog`）
