# 依頼
私はターミナルで動くコーディング/文書作成エージェント「Claude Code」で、成果物プロジェクトを一定の規約で管理しています。まったく同じ運用を、あなた（Gemini。特に **Gemini CLI**）で再現できるかを判定してください。

各「仕組み」について、必ず次の4点を答えること：
(a) Gemini（CLI）に同等機能はあるか（Yes / 部分的 / No）
(b) あるなら具体的な設定方法（設定ファイルの場所・形式、コマンド名、記法）
(c) Claude Code との差異・制約
(d) 無い/弱い場合の最も近い代替手段
※「Web版Geminiでは不可でCLIなら可」のような動作環境の違いも明記すること。

## A. 管理規約（この運用自体を再現できるかも判定して）
- 全プロジェクトを1つのコンテナフォルダ（＝**1つの git リポジトリ**）に集約。
- 各プロジェクト = フォルダ `YYYYMMDD_プロジェクト名/`。直下は英語名で固定：
  - `01_input/`（入力原本・改変しない）／`02_output/`（成果物）／`03_scripts/`（スクリプト）／`04_reference/`（任意）
  - ＋ 管理文書2つ：`プロジェクト状況.md`（目的・前提・論点/スコープ・成果物・未確認事項・変更履歴）と `更新履歴.md`（成果物の版一覧の表。最新版は「太字＋（最新）」で明示）
- 成果物ファイル = `YYYYMMDD_名称_vN.拡張子`。改訂ごとに vN を +1、旧版は削除せず残す。試作は `02_output/_wip/` に隔離。
- コンテナ直下に `00_プロジェクトテンプレート/`（雛形）・`_ツール/`（横断ツール）・`_archive/`（統合済み/凍結プロジェクト）を置く。
- 記述原則：出典・根拠を明記／事実と推論を区別／未確認事項を隠さない／日付は絶対日付。
- 成果物の形式は目的から選ぶ（HTML/MD/PDF/xlsx/pptx/docx）。「とりあえずHTML」にせず、迷えばMDで中身を固めてから必要な形式へ展開（中身ファースト）。

## B. 再現したい「仕組み」
1. **自動読み込みの前提指示ファイル**：フォルダ階層に置いた指示ファイル（Claude Codeでは `CLAUDE.md`）を、そのフォルダで作業するたびに自動で文脈に読み込む（規約・命名・振る舞い）。Gemini の相当（`GEMINI.md`？）と、親→子への階層的マージ挙動は？
2. **セッションをまたぐ永続メモリ**：ユーザーの好み・運用ルールを保存し、次回以降のセッションで自動的に思い出す。Gemini の保存先・記法・呼び出し方（`/memory` 等）は？
3. **カスタム・スラッシュコマンド**：定型作業をコマンド化。例）
   - `/new-project <名称>`：テンプレ一式をコピーして新規プロジェクトを初期化
   - `/ship <ファイル>`：版を vN+1 に上げ、管理文書2点を自動更新
   - `/status`：管理文書から現在の状況を要約
   Gemini での定義方法（ファイル形式＝TOML等・置き場所・引数 `{{args}}` の渡し方）は？
4. **イベントフック（最重要の確認点）**：ファイル編集後に、条件（例：パスに `02_output` を含む）に応じて「管理文書2点を更新して」というリマインドを自動で差し込む（Claude Code の PostToolUse フック）。Gemini に同等の「ツール実行の前後で任意コマンドを走らせる」フック機構はあるか？無ければ最も近い代替（拡張機能・MCP・ラッパー等）は？
5. **ファイル操作・シェル・git**：フォルダ作成、ファイルの移動/リネーム、`git init`・コミットをエージェント自身が実行できるか。実行時の承認（許可）モデルは？
6. **大きな単一HTML成果物の安全な改訂**：数千行・1MB級の単一HTML（CSS/JS/データを1ファイル内包・外部依存なし）を、**全体書き直しせず差分（部分置換）で**安全に編集できるか。トークン上限・部分編集ツールの有無・大規模ファイルでの精度は？
7. **多形式の成果物生成**：目的に応じて出力形式を選ぶ運用のため、Markdown/HTML に加え **docx・pdf・pptx・xlsx** をエージェント自身が生成できるか（専用機能・スキル・ライブラリの有無）。

## C. 出力形式
1. 可否一覧表（列：仕組み / Gemini相当 / 設定場所・記法 / 制約 / 代替）
2. 「ゼロから同じ運用を Gemini で立ち上げる最短手順」（コマンド・ファイル例つき）
3. 「Claude Code に比べてできない・弱い点」の明示

## 使い方メモ
- 上の本文をコピーして Gemini（**CLI 推奨**。Web版だと 4・5・6 の多くが「不可」寄りになる）に貼る。
- 焦点は **B-4（イベントフック）**・**B-6（大規模単一HTMLの差分編集）**・**B-7（docx/pdf/pptx/xlsx の生成）**。この3点が Claude Code との差になりやすい。
- Gemini の回答は、この下に日付つきで追記していけば比較メモとして蓄積できる。
