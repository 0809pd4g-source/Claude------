# Gemini移行チェック用プロンプト

このプロジェクト管理の運用が Gemini（特に Gemini CLI）で再現できるかを、Gemini自身に判定させるためのプロンプト。下の「---」で囲まれた本文をコピーして Gemini に貼り付けて使う。

---

# 依頼
私はターミナルで動くコーディング/文書作成エージェント「Claude Code」で、成果物プロジェクトを一定の規約で管理しています。同じ運用を、あなた（Gemini。特に Gemini CLI）で再現できるか確認したいです。

以下の各「仕組み」について、必ず次の4点を答えてください：
(a) Gemini（CLI）に同等機能はあるか（Yes/部分的/No）
(b) あるなら具体的な設定方法（設定ファイルの場所・形式、コマンド名、記法）
(c) Claude Code との差異・制約
(d) 無い/弱い場合の、最も近い代替手段
また、Web版Geminiでは不可でCLIなら可、のような「動作環境による違い」も明記してください。

## 私の管理規約（この運用自体が再現できるかも判定して）
- 各プロジェクト = フォルダ `YYYYMMDD_プロジェクト名/`。直下に `01_入力/`・`02_成果物/`・`03_スクリプト/`・`04_参考/`（任意）＋ 管理文書2つ：
  - `プロジェクト状況.md`（目的・前提・論点/スコープ・成果物・未確認事項・変更履歴）
  - `更新履歴.md`（成果物の版一覧の表。最新版は「太字＋（最新）」で明示）
- 成果物ファイルは `YYYYMMDD_名称_vN.拡張子`。改訂ごとに vN を +1 し、旧版は削除せず残す。
- 記述原則：出典・根拠を明記／事実と推論を区別／未確認事項を隠さない／日付は絶対日付。
- 複数プロジェクトを1つのコンテナフォルダ（＝1つの git リポジトリ）に集約して管理。

## 再現したい「仕組み」
1. 自動読み込みの前提指示ファイル：フォルダ階層に置いた指示ファイル（Claude Codeでは `CLAUDE.md`）を、そのフォルダで作業するたびに自動で文脈に読み込む（規約・命名・振る舞いなど）。Geminiでの相当（例：`GEMINI.md`？）と、階層的に読み込む挙動は？
2. セッションをまたぐ永続メモリ：ユーザーの好みや運用ルールを保存し、次回以降のセッションでも自動的に思い出す仕組み。Geminiでの保存先・記法・呼び出し方は？
3. カスタム・スラッシュコマンド：定型作業をコマンド化する。例）
   - `/new-project <名称>`：テンプレ一式をコピーして新規プロジェクトを初期化
   - `/ship <ファイル>`：版を vN+1 に上げ、管理文書2点を自動更新
   - `/status`：管理文書から現在の状況を要約
   Geminiでの定義方法（ファイル形式・置き場所・引数の渡し方）は？
4. イベントフック：ファイル編集後に、条件（例：パスに `02_成果物` を含む）に応じて「管理文書2点を更新して」というリマインドを自動で差し込む（Claude Code の PostToolUse フック）。Geminiに同等のフック機構はあるか？無ければ最も近い代替は？
5. ファイル操作・シェル・git：フォルダ作成、ファイルの移動/リネーム、`git init` やコミットをエージェント自身が実行できるか。権限・承認モデルは？
6. 大きめの単一HTML成果物：数百行のHTMLを1ファイルで生成し、部分的に編集できるか。制約（トークン上限・部分編集の可否）は？

## 出力形式
1. 可否一覧表（列：仕組み / Gemini相当 / 設定場所・記法 / 制約 / 代替）
2. 「ゼロから同じ運用を Gemini で立ち上げる最短手順」
3. 「Claude Code に比べてできない・弱い点」の明示
