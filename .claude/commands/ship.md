現在のプロジェクトの成果物を確定（ship）する。対象：$ARGUMENTS

## 手順

### Step 0｜静的チェック（対象の拡張子に応じて実行）

引数のファイルの拡張子を見て、対応するチェッカーを**以降の手順の前に必ず**実行する。

**対象が `.html` の場合:**
```bash
python _agent/_基盤/_ツール/html_checker.py "<対象ファイルのパス>"
```

**対象が `.md` の場合（成果物 MD）:**
```bash
python _agent/_基盤/_ツール/md_checker.py "<対象ファイルのパス>"
```

判定（HTML・MD 共通）:
- **FAIL 1件以上** → チェッカーの出力を報告し、ここで停止する。修正完了後に改めて `/ship` を実行するよう伝える。
- **FAIL 0件・WARN あり** → WARN の内容をユーザーに提示し、「このまま確定してよいか」を確認してから続行する。
- **FAIL 0件・WARN なし** → そのまま Step 1 へ進む。

---

### Step 0.5｜管理文書の事後チェック（Step 3・4 完了後）

Step 3・4 で管理文書を更新したら、以下を実行して整合性を確認する。

```bash
python _agent/_基盤/_ツール/md_checker.py "<プロジェクトフォルダ>/更新履歴.md"
python _agent/_基盤/_ツール/md_checker.py "<プロジェクトフォルダ>/プロジェクト状況.md"
```

- **FAIL（（最新）が1行でない等）** → その場で修正して再確認する。
- **WARN** → 内容を Step 5 の報告に含める。

---

### Step 1｜対象プロジェクトの特定

カレント位置から上位に向かって `更新履歴.md` と `プロジェクト状況.md` を探し、対象プロジェクトを特定する。

### Step 2｜版番号の決定

- 既存最新版の改訂 → `vN+1` の新ファイルとして `02_output/` に保存し、旧版は残す。
- 新規成果物 → `v1` とする。
- ファイル名規約: `YYYYMMDD_名称_vN.拡張子`

### Step 3｜`更新履歴.md` を更新

- 新しい版の行を追加する。
- 最新版を **太字＋（最新）** に。直前の最新版の「太字＋（最新）」表記は外す。

### Step 4｜`プロジェクト状況.md` を更新

- 「成果物」欄と「変更履歴」（当日・絶対日付）を更新する。
- 必要なら「未確認・要確認事項」も更新する。

### Step 5｜報告

変更点（版・ファイルパス・要約）を報告する。HTML ファイルの場合はチェッカーの結果（FAIL/WARN 件数）も添える。
