CLAUDE.md のルールとチェッカー（html_checker.py / md_checker.py）を、インシデントログをもとに見直し・アップデートする。

## 手順

### Step 1｜ルール候補ログを読む

`_agent/_基盤/_ツール/ルール候補.md` を読み、状態が「未対応」の候補をすべて抽出する。
候補が 0 件の場合は「候補なし」と報告して終了する。

### Step 1.5｜フォルダ構成の点検

`python _agent/_基盤/_ツール/構成点検.py` を実行し、指摘（名前の似たプロジェクト・同じ目的の別ファイル・置き場所の違反・ルール文書のコピー）を把握する。指摘はルール候補と一緒に Step 4 で提示し、**移動・統合・削除は1件ずつ承認を得て、チェックポイントのコミットを作ってから**行う。誤検出は理由を添えて見送る。

### Step 2｜現状のルール・チェックと照合

以下を読んで現在のカバレッジを把握する:
- `CLAUDE.md`（HTML成果物の作業ルール A〜I・検証プロトコル）
- `_agent/_基盤/_ツール/html_checker.py`（ブロッカー・警告のリスト）
- `_agent/_基盤/_ツール/md_checker.py`（ブロッカー・警告のリスト）

### Step 3｜各候補を以下の3区分に仕分ける

| 区分 | 判断基準 | アクション |
|---|---|---|
| **チェッカー追加** | 機械的に検出可能（パターン・存在確認・件数） | html_checker.py または md_checker.py に追加 |
| **CLAUDE.md 追記** | 判断や手順が必要で自動化が難しい | 作業ルール（A〜I の後）または検証プロトコルに追記 |
| **見送り** | 重複・偽陽性が多い・費用対効果が低い | 候補の状態を「見送り」に更新し理由を記録 |

### Step 4｜ユーザーに仕分け結果を提示して承認を得る

変更内容の一覧（何をどこに追加するか）を示し、「適用してよいか」を確認する。

### Step 5｜承認後に変更を適用

1. チェッカーへの追加: `Edit` ツールで差分編集する
2. CLAUDE.md への追記: 既存ルールと重複しない位置に挿入する
3. `_agent/_基盤/_ツール/ルール候補.md` の更新: 対応した候補の状態を「対応済」に変更し「## 対応済みアーカイブ」へ移す

### Step 6｜動作確認

チェッカーを変更した場合は、既存のHTMLまたはMDファイルに対して実行し、意図した結果になるか確認する:

```bash
python _agent/_基盤/_ツール/html_checker.py <既存ファイル>
python _agent/_基盤/_ツール/md_checker.py <既存ファイル>
```

### Step 7｜報告

- 追加したルール・チェック（内容・追加先）
- 見送った候補（理由）
- 次回 `/review-rules` の推奨タイミング（候補が3件超えたら実行を推奨）
