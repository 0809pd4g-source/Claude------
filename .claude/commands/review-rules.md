CLAUDE.md のルールとチェッカー（html_checker.py / md_checker.py）を、インシデントログをもとに見直し・アップデートする。

## 手順

### Step 1｜ルール候補ログを読む

`_agent/_基盤/_ツール/ルール候補.md` を読み、状態が「未対応」の候補をすべて抽出する。
候補が 0 件でも終了せず、Step 1.5（構成点検）と Step 1.6（作業プロセスの振り返り）は実行する。

### Step 1.5｜フォルダ構成の点検

`python _agent/_基盤/_ツール/構成点検.py` を実行し、指摘（名前の似たプロジェクト・同じ目的の別ファイル・置き場所の違反・ルール文書のコピー）を把握する。指摘はルール候補と一緒に Step 4 で提示し、**移動・統合・削除は1件ずつ承認を得て、チェックポイントのコミットを作ってから**行う。誤検出は理由を添えて見送る。

### Step 1.6｜作業プロセスの振り返り（業務）

`_agent/_基盤/_タスク管理/作業時間ログ.md` の「## プロセス記録」のうち、前回の `/review-rules` 以降の行を作業の種類ごとにまとめ、種類ごとに次を出す（記録が1件もない種類は出さない）。
- **現状の手順**（記録から読み取れる流れ）と、件数・所要の幅
- **改善できる点**：手戻り・詰まりが繰り返し出た工程、時間がかかった工程（根拠の行を示す）
- **最善のプロセス案**：手順を何段かで。子エージェントに任せられる工程（入力と出力先が決まり、途中で判断が要らない）があれば印を付ける
- **反映先**：定常業務マニュアルの章、またはその作業のガイド（`01_定常業務/ルール・ガイド/`）
- **振り分け表の点検**：記録に出た作業の種類が `_agent/CLAUDE.md`「振り分け表」の行にあるか。無ければ、担当・読むもの（マニュアルは章番号を実際に開いて確かめる）・置き場所・点検を埋めた行案を出す。表の「読むもの」の章番号が、マニュアルの最新版で変わっていないかも確かめる

案は Step 4 でほかの候補と一緒に提示する。承認されたものは、その日の `daily` の「## マニュアル反映待ち」に書いて終業時に反映する。保留のものは `ルール候補.md`「ナレッジ・知見」に未対応として残す。

### Step 2｜現状のルール・チェックと照合

以下を読んで現在のカバレッジを把握する:
- `CLAUDE.md`（核ルール。HTMLは要点と参照先のみ）
- `_agent/_基盤/_ツール/HTML作成ガイド.md`（HTML成果物の作業ルール A〜I・検証プロトコル・レビューの規律）
- `.claude/agents/reviewer.md`（レビュー担当の点検項目）
- `_agent/_基盤/_ツール/html_checker.py`（ブロッカー・警告のリスト）
- `_agent/_基盤/_ツール/md_checker.py`（ブロッカー・警告のリスト）

### Step 3｜各候補を以下の3区分に仕分ける

| 区分 | 判断基準 | アクション |
|---|---|---|
| **チェッカー追加** | 機械的に検出可能（パターン・存在確認・件数） | html_checker.py または md_checker.py に追加 |
| **ルール追記** | 判断や手順が必要で自動化が難しい | 毎回要るものは CLAUDE.md、特定の作業でだけ要るものはその作業のガイド・マニュアル（HTMLなら HTML作成ガイド.md の A〜I の後）に追記。CLAUDE.md を太らせない |
| **見送り** | 重複・偽陽性が多い・費用対効果が低い | 候補の状態を「見送り」に更新し理由を記録 |

### Step 4｜ユーザーに仕分け結果を提示して承認を得る

変更内容の一覧（何をどこに追加するか）を示し、「適用してよいか」を確認する。

### Step 5｜承認後に変更を適用

1. チェッカーへの追加: `Edit` ツールで差分編集する
2. CLAUDE.md への追記: 既存ルールと重複しない位置に挿入する
3. `_agent/_基盤/_ツール/ルール候補.md` の更新: 対応した候補の状態を「対応済」に変更し「## 対応済みアーカイブ」へ移す

### Step 6｜動作確認

チェッカーを変更した場合は、既存のHTMLまたはMDファイルに対して実行し、意図した結果になるか確認する:

```bash
python _agent/_基盤/_ツール/html_checker.py <既存ファイル>
python _agent/_基盤/_ツール/md_checker.py <既存ファイル>
```

### Step 7｜報告

- 追加したルール・チェック（内容・追加先）
- 見送った候補（理由）
- 次回 `/review-rules` の推奨タイミング（候補が3件超えたら実行を推奨）
