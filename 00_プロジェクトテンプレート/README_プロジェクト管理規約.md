# プロジェクト管理規約（汎用テンプレート）

成果物中心の調査・可視化・仕様検討プロジェクトを、**版・根拠・前提・未確認事項をトレース可能な形**で進めるための共通ルール。新規プロジェクトはこのフォルダのうち `01_input`〜`04_reference`・`プロジェクト状況.md`・`更新履歴.md` をコピーして開始する（本READMEと `CLAUDE.md` はコピーしない）。

---

## 1. フォルダ構成規約

プロジェクトルート直下は以下で固定する。

```
YYYYMMDD_プロジェクト名/
├── 01_input/            … 入力資料（PDF・元データ・依頼スライド等）。原本は改変しない
├── 02_output/          … 成果物（HTML・仕様書・図表等）。版管理はファイル名で行う
├── 03_scripts/       … 変換・生成・検証用スクリプト
├── 04_reference/            … 調査結果・URLメモ・参考資料（任意。使うときだけ作成）
├── プロジェクト状況.md   … プロジェクトの現在地（目的・前提・論点・未確認事項）
└── 更新履歴.md          … 成果物の版・日付・変更内容の一覧
```

- フォルダは増やさず、原則この4区分（`01_input`〜`04_reference`）に収める。さらに必要なら `05_〜` と連番で追加。
- `04_reference` は任意。参照メモや外部リンク集など、入力原本でも成果物でもない資料の置き場。
- `01_input` の原本は編集しない（引用・加工はコピーを `02_output` 側に置く）。

## 2. ファイル命名規約

```
YYYYMMDD_名称_vN.拡張子
```

- 例：`20260716_マイナポ患者サマリー可視化_v8.html`、`20260717_臨床情報閲覧仕様書_v1.md`
- `YYYYMMDD` は**作成（またはシリーズ開始）日**。同一シリーズは日付を揃える。
- `vN` は整数版。改訂ごとに +1 し、**旧版は削除せず残す**（履歴として保全）。
- 最新版がどれか迷わないよう、`更新履歴.md` で常に「最新」を明示する。

## 3. 管理文書の運用

### 3.1 `プロジェクト状況.md`（現在地）
「今どこまで分かっていて、何が未確定か」を一目で追えるようにする。章立てはテンプレート参照。
- **目的**：何のためのプロジェクトか。
- **前提の整理**：参照元・出典と、**事実／推論／未裏取り**の区別を明記。
- **論点・スコープ**：対象／対象外を理由付きで。
- **成果物**：各成果物の概要と位置づけ。
- **未確認・要確認事項**：オープンな論点を箇条書きで残す。
- **変更履歴**：日付ごとの意思決定・進捗（絶対日付で記載）。

### 3.2 `更新履歴.md`（版一覧）
成果物の版を一元管理する表（`成果物 / 版 / 日付 / 変更内容`）。最新版は **太字＋（最新）** で示す。

## 4. 記述原則（品質のコア）

1. **出典・根拠を明記**：仕様記述には該当ページ・資料名を付す。根拠を示せない事項は「推論」「未確認」と明示。
2. **事実と推論を分ける**：入力資料に書かれている事実と、こちらの解釈・仮定を混ぜない。
3. **未確認事項を隠さない**：分からない・裏取りが必要な点は `未確認・要確認事項` に必ず残す。
4. **やったこと／やっていないこと**：成果物の末尾で対象範囲と非対象範囲を明示する。
5. **相対日付を使わない**：「先週」ではなく `2026-07-23` のように絶対日付で書く。

## 5. 新規プロジェクト開始手順

1. このフォルダのうち `01_input`〜`04_reference`・`プロジェクト状況.md`・`更新履歴.md` を `YYYYMMDD_新プロジェクト名/` としてコピー。
2. 本READMEと `CLAUDE.md` は**コピーしない**。規約の正本は本READMEとルートの `CLAUDE.md` で、ルートの `CLAUDE.md` はどのプロジェクトで作業していても読み込まれるため、コピーすると重複になる（規約を改訂したときにコピー側が古くなる）。プロジェクト固有のルールがあるときだけ、テンプレの `CLAUDE.md`（雛形）を元にそのプロジェクトの `CLAUDE.md` を作る。各サブフォルダの `_フォルダ説明.md` は削除してよい。
3. `プロジェクト状況.md` の見出し `〈…〉` を埋める（目的・前提・スコープ）。
4. 入力資料を `01_input/` に置く。
5. 成果物を `02_output/` に `_v1` から作成し、改訂のたびに `更新履歴.md` と `プロジェクト状況.md` を更新。
