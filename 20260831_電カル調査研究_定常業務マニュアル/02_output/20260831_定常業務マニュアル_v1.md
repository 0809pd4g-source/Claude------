## 1. 週次サイクル全体像

以下は **金曜スタート** の2週サイクル例（8/28週の場合）。

| 曜日 | 主な作業 |
|---|---|
| 金（8/28） | 三者定例・進捗連絡会議・開発課題検討会・WBS会議の各後処理 |
| 月（8/31） | 三者定例ラップアップ会議・進捗連絡会議・開発課題検討会の各前後処理 |

| 水（9/3午前） | WBS資料作成・Rev依頼、ONS返送（水曜） |
| 木（9/3） | 三者定例の事前連携（14:00）・Rev取り込み |
| 金（9/4） | 三者定例最終格納（13:00）・次サイクルへ |

## 6. ONS（台帳管理）

### 6-1. 受領（毎週月曜・水曜）

- [ ] 厚労省Teamsにて基金側からONS台帳更新の連絡を受領する
- [ ] 基金側の台帳ファイル（スレッド上のリンク先）から厚労省側の台帳ファイルに更新内容を反映する
  - ステータス欄は **「ACN回答作成」** とする
  - 新規事項について分類を行う：
    - **回答案を作成できる** → そのまま作成
    - **次回ONS読合せで厚労省に回答方針確認が必要** → 回答欄に `★厚労省回答方針確認` と記載する

### 6-2. 返送（毎週火曜 → 水曜）

- [ ] 火曜：厚労省と回答案の読合せを行う
- [ ] 基金に共有する内容がFIXしたら、翌水曜に基金側の台帳ファイルに転記する
- [ ] 受領時と同じスレッドで確認依頼を行う
- [ ] **「回答済」等のクローズ行はグレーに塗りつぶす**

## 7. 資料作成

### 7-1. 案件起票の流れ

1. WBS等で厚労省と要求事項を確認する
2. **案件台帳に起票する**
   - 厚労ACN内Rev中は更新欄に `（確認中）` と記載する
   - TODO由来の起票であれば、TODO発生元会議の厚労省スレッドで起票を報告する（過去の開発課題検討会スレッドの記載を参照）
3. 次の**開発課題検討会資料の案件台帳更新概要ページ**に更新内容を記載する（画像は案件の更新の場合）
4. 「電カル共有改修案件一覧および要求事項詳細」PPTファイルにて要求事項詳細のスライドを作成する（厚労省内部用）

### 7-2. WBS資料

#### TODO・確認事項一覧スライド
- 翌週が期日のTODO、その他厚労省に状況確認したいTODOを掲載する
- スレッド等で厚労省の確認事項になっている件、継続的に状況共有したい件を掲載する
- **アップデート部分は青字で記載する**

#### 個別アジェンダ（週次スケジュール）
- 火曜まで：方針確定（自分の中で定まらない場合は本田さんに相談）
- 水曜：資料作成・Rev依頼
- 木曜：Rev取り込み

## 8. 注意事項まとめ

| 項目 | 注意点 |
|---|---|
| ファイル格納全般 | 厚労省シェアポ格納前に**必ずプロパティを削除する** |
| 三者定例資料 | 末尾のラップアップページは厚労省シェアポ側には連携しない |
| 議事要旨 | Rev未完であれば事前連携時に含めない |
| 三者定例ラップアップ送付 | 本田さんの送付可確認後に送付する |
| ONS新規事項 | 回答方針確認が必要なものは回答欄に `★厚労省回答方針確認` と記載 |
| WBS資料（次週ファイル） | 古いアジェンダは削除するが、TODO・確認事項一覧スライドは残す |
| ONS月次報告週（第2週） | リマインドのメンション先・刈り取り対象に比嘉さんを追加 |
