## 0. 本仕様書の位置づけ

本書は、電子カルテ情報共有サービスの **臨床情報一覧**（傷病名・感染症・検査・薬剤アレルギー等・その他アレルギー等）の閲覧表示を、**同じ画面・同じ表示ルールで再現できる**ことを目的とした仕様書である。表示項目・表示順・表示条件・FHIR要素との対応（マッピング）を、出典ページ付きで整理する。

**対象**：臨床情報一覧の閲覧表示仕様（データ項目・表示ルール・FHIRマッピング）。技術解説書「5.3 臨床情報登録・閲覧サービス」（p64〜90）、「5.4 患者サマリー登録・閲覧サービス」（p91）、機能17の同意区分（p141）を根拠とする。

## 1. 臨床情報の全体像と保存期間

### 1.1 臨床情報の5区分

臨床情報は、本サービスを通じて全国の医療機関等および患者本人が取得・閲覧できる（p64）。区分は以下の5つ。

| 情報区分 | 登録対象 | データ保存期間（通常） | 長期保存 |
|---|---|---|---|
| 傷病名 | 診断をつけた傷病名 | 本サービス登録日から5年間 | 対象 |
| 感染症 | 5項目の検体検査結果 | 本サービス登録日から5年間 | 対象 |
| 検査 | 救急・生活習慣病に関わる43項目の検体検査結果 | 本サービス登録日から1年間 もしくは 直近3回分 | 対象外 |
| 薬剤アレルギー等 | 薬剤アレルギー等 | 本サービス登録日から5年間 | 対象 |
| その他アレルギー等 | 薬剤以外のアレルギー等（食品・飲料、環境等） | 本サービス登録日から5年間 | 対象 |

（出典：表17、p64）

**感染症5項目の内訳**（p64 表17内）：梅毒STS、梅毒TP抗体、HBs、HCV、HIV。

**検査43項目**：具体名は本文に列挙されず、「電子カルテ情報共有サービス対応JLACコード表」に収載される（p79〜82）。救急フラグ・生活習慣病フラグで識別する（p80 表23）。

### 1.2 保存期間の起算・更新・長期保存（p64）

- 起算日は「**本サービスにデータを登録した日付**」。診療開始日や検体採取日ではない。
- 同一の `Bundle.identifier` を付与して更新すると、過去の同一識別情報データは一式削除・上書きされ、起算日も最新登録日に更新される。
- 検査の「1年間もしくは直近3回分」の意味：直近3回分は期間にかかわらず保持。4回目以降の過去データは登録から1年経過で自動削除。
- 傷病名・感染症・薬剤/その他アレルギーは通常5年。医師等の判断で **長期保存フラグ（LTS）** を付与すると、より長期に保存可能（無作為設定を避ける実装が必要）。

### 1.3 臨床情報一覧の表示期間ルール（重要・p68 注記）

臨床情報一覧サンプル末尾の注記を原文引用する（p68）。

> ※臨床情報では、登録から５年以内（長期保存を除く）の情報を表示しています。
> ただし、処方情報については登録から100日間もしくは直近3回分、検査情報については直近３回分を表示しています。
> ※検査情報および感染症情報における基準値は、同一の検査項目であっても使用される試薬や検査機器、測定方法、性別等の違いによって異なる場合があります。
> ※現在、電子カルテ情報共有サービスでは、診療情報提供書/退院時サマリーからの処方情報抽出機能を停止しております。

補足（本書の整理）：処方情報は臨床情報としての抽出が停止中（p2, p68）。処方は別サービス（電子処方箋管理サービス）経由で患者サマリーに供給される（p91）。したがって **臨床情報一覧の再現において処方情報欄は「抽出停止中」状態で扱う**。

## 2. 閲覧の前提

### 2.1 同意区分と閲覧できる対象情報（p141 表36）

臨床情報の取得には、顔認証付きカードリーダによる本人確認と同意が必要。同意が得られた時点から24時間に限り取得要求が可能（p141）。同意区分と閲覧対象は以下。

| 同意区分 | 顔認証付きカードリーダ表示 | 閲覧できる対象情報（臨床情報分） |
|---|---|---|
| 手術・傷病名・感染症情報 | 過去の手術情報・傷病名情報・感染症検査結果を当機関に提供することに同意しますか。 | 傷病名情報／感染症情報 |
| 診療・お薬情報 | 過去の診療情報（感染症を除く検査結果、アレルギー等）・お薬情報を当機関に提供することに同意しますか。 | 検査情報／薬剤アレルギー等情報／その他アレルギー等情報 |
| 健診結果報告書 | 過去の健診情報を当機関に提供することに同意しますか。 | （健診情報／臨床情報外） |

（出典：表36、p141。電子レセプト抽出情報・電子処方箋抽出情報は臨床情報の範囲外のため本書では省略）

臨床情報一覧の各区分見出しには「**閲覧同意：あり／なし**」が表示される（p68 サンプル）。

### 2.2 患者サマリー（マイナポータル）との関係（p91）

患者サマリーは以下を組み合わせて構成される（p91）。

- 療養上の計画・アドバイス
- 指導日（登録または更新日）時点での傷病名
- 臨床情報登録・閲覧サービス経由の 感染症／薬剤アレルギー等／その他アレルギー等／検査情報
- 電子処方箋管理サービス経由の 院内・院外処方箋情報

患者サマリーは **患者本人向け**（マイナポータル）で、医療機関が直接取得・閲覧することはできない（患者本人が同意のうえ画面提示することは可）。その詳細技術仕様は別冊の技術解説書に委任（p91）。

## 3. 表示共通ルール

以下は全区分に共通、または複数区分にまたがる表示ルール（出典：p69〜72 表18ほか）。

### 3.1 出力制御（レコードとして表示する条件）

| 区分 | 表示対象の状態 | FHIR要素 |
|---|---|---|
| 傷病名 | unconfirmed（未確認）／confirmed（確認済み）のみ | `Condition.verificationStatus.coding.code` |
| 感染症・検査 | preliminary（暫定）／final（最終）／corrected（訂正）のみ | `Observation.status.coding.code` |
| 薬剤/その他アレルギー | active（現存）のみ（resolved・inactive等は非表示） | `AllergyIntolerance.clinicalStatus.coding.code` |

（出典：p69, p70, p71, p87）

### 3.2 医療機関名の表示と【廃】（全区分共通・p69〜71）

- 登録医療機関名は「医療機関等マスタに基づく施設名称」を表示。
- **帳票出力日時点で廃止となっている医療機関には、名称の先頭に `【廃】` を付与**する。
- FHIR要素：各リソースの `extension:eCS_InstitutionNumber.value`（保険医療機関番号）。

### 3.3 日付形式と並び順

| 区分 | 日付形式 | 並び順 |
|---|---|---|
| 傷病名 病名開始日 | YYYY年／YYYY年MM月／YYYY年MM月DD日／YYYY年MM月DD日hh時mm分 | 新しい順 |
| 傷病名 終了日 | YYYY年MM月DD日／〃hh時mm分 | 終了病名欄に記載 |
| 感染症 検体採取日時 | YYYY年MM月DD日／〃hh時mm分 | 新しい順 |
| 薬剤/その他アレルギー 登録日 | YYYY年MM月DD日 | 新しい順 |
| 検査 採取日時 | YYYY年MM月DD日／〃hh時mm分 | **古い順**（最新・前回・前々回の3列） |

（出典：p69〜72）

### 3.4 長期保存（LTS）表示

`meta.tag:lts.code`＝LTS が設定されている場合、長期保存欄に「○」を表示（傷病名・感染症・アレルギー各区分共通、p69〜71）。

## 4. 情報区分別 データ項目・FHIRマッピング

各区分の「出力項目 → FHIRPath → 表示ルール（備考）」を示す（出典：表18、p69〜72）。

### 4.1 傷病名

| 出力項目 | FHIRPath | 表示ルール |
|---|---|---|
| （出力制御） | `Condition.verificationStatus.coding.code` | unconfirmed／confirmed のみ表示 |
| 傷病名 | `Condition.code` | 病名管理番号コードの表示名称（display値）。ダミーコードはtext値 |
| 前置修飾語 | `Condition.code.extension:diseasePrefixModifier` | 「前置修飾語＋傷病名＋後置修飾語」で連結。順序はMEDIS接続位置区分に準拠 |
| 後置修飾語 | `Condition.code.extension:diseasePostfixModifier` | 同上 |
| （の疑い） | `Condition.verificationStatus.coding.code` | unconfirmed の場合、傷病名の後に「の疑い」を表示。修飾語コード27000001併記時は重複回避で非表示 |
| 病名開始日 | `Condition.onsetDateTime` | 日付形式は§3.3。新しい順 |
| 終了日 | `Condition.abatementDateTime` | 終了日ありは「終了病名」欄に記載 |
| 主病名 | `Condition.extension:eCS_DiagnosisType.coding.code` | 【Principal】の場合、先頭に「主」を表示 |
| 告知状況 | `Condition.meta.tag:uninformed.code` | UNINFORMED設定時は「未告知」と表示 |
| 臨床的状態 | `Condition.clinicalStatus.coding.code` | active：存続／unknown：不明／remission：寛解／resolved：治癒 |
| 登録医療機関名 | `Condition.extension:eCS_InstitutionNumber.value` | §3.2（【廃】付与） |
| 長期保存 | `Condition.meta.tag:lts.code` | LTS設定時「○」 |

（出典：p69）

傷病名の取扱い補足（p73）：

- 疑い傷病名は `verificationStatus="unconfirmed"` で表現するのが原則。`diseasePostfixModifier=27000001（の疑い）` での表現は非推奨だが、設定時はPDF帳票上「●●の疑い」と出力される。
- 転帰区分は `clinicalStatus`：resolved（軽快/治癒）／remission（寛解）／active（存続）／unknown（不明）の4区分。resolved・remission設定時は `abatementDateTime`（終了日等）の登録が必須。

## 5. 検査コード・定性値・単位の仕様

### 5.1 JLAC10 / JLAC11（p79〜82）

- 感染症5項目・検査43項目は JLAC10 または JLAC11 のいずれも使用可。新規採用はJLAC11を推奨。
- `Observation.code.coding.code` にJLACコード、`.display` にFHIR識別文字列を設定。画面・帳票の項目名はサービス側で「FHIR項目名称」に自動変換して表示（実装側は変換不要）。
- JLAC11は17桁（測定物・識別・材料・測定法・結果単位）。測定法不明時の特例：JLAC10は13〜15桁目「999」、JLAC11は「000（その他の測定法）」（p83）。
- 標準マスタコードに加え、医療機関固有のローカルコード併記を強く推奨（未併記はWarning、p83）。

### 5.2 定性値パターン（p85 表24）

| CodeSystem（URI 末尾） | コード値 → 表示名称 |
|---|---|
| JP_PosNegHold_CS | 1:陽性／2:陰性／3:判定保留 |
| JP_Urine_Code_CS | 1:－／2:±／3:＋／4:2＋／5:3＋／6:4＋／7:5＋ |
| JP_BldABO_CS | 1:A／2:B／3:AB／4:O |
| JP_BldRh_CS | 1:＋／2:－ |

定性値は `Observation.valueCodeableConcept` に設定。マスタで許容されない定義外コードは、登録可だが臨床情報一覧のXML/PDFには反映されない（p85）。

### 5.3 単位・基準値（p83, p84）

- 単位：JLACコード表の「表示用単位」を `valueQuantity.unit`、「XML用単位」を `valueQuantity.code`（UCUM）に記述。
- 基準値：数値結果は `referenceRange` の記述必須（未記述はバリデーションエラー）。正常値範囲のみを記述し、複数範囲の同時登録は不可（2種類以上はエラー）。
- 注記：単位方針は見直し中で「表示される単位は今後変更の可能性」（p71〜72, p83）。

### 6.2 セクション構成と順序

1. **傷病名**（閲覧同意：あり／なし）
   - 「病名」表：病名開始日／主・傷病名（【疑】〜／〜の疑い）／臨床的状態／登録医療機関名（【廃】）／長期保存
   - 「終了病名」表：病名開始日／終了日／主・傷病名／臨床的状態／登録医療機関名／長期保存
2. **感染症情報**（閲覧同意：あり／なし）
   - 検体採取日時／検査（項目）／基準値／結果／登録医療機関名／長期保存
3. **薬剤アレルギー等情報**（閲覧同意：あり／なし）
   - 登録日／薬剤名／重症度／症状／登録医療機関名／長期保存
4. **その他アレルギー等情報**（閲覧同意：あり／なし）
   - 登録日／カテゴリ／アレルギー／重症度／症状／登録医療機関名／長期保存
5. **検査情報**（閲覧同意：あり／なし）
   - 「最新・前回・前々回」の3列。各列に 採取日時／実施機関、行に 検査項目／基準値／結果（＋H/L評価、中間/確定ステータス）
6. **処方情報**（閲覧同意：あり／なし）
   - **現在抽出停止中**（§1.3、p68 注記）。欄は存在するが内容は表示されない前提。

## 7. 登録タイミング（閲覧鮮度に影響する前提・p65）

閲覧側の鮮度に直結するため、登録期限の目安を記載（外来診療、p65）。

- 感染症および検査：**次回診療日中**（夜間登録も可）
- 傷病名・薬剤アレルギー・その他アレルギー：今後検討のうえ別途公表予定
- 入院中発生分：**退院日当日中**（結果未確定の検査等は退院患者の次回診療日中まで）
- 登録期限超過でもエラーにはならないが、速やかな登録が望まれる。
- 傷病名は未告知フラグ未付与のまま登録すると、患者本人が未認知の傷病名がマイナポータル上で閲覧可能となるおそれがあるため、必ず医師の判断を経て登録する（p65）。
