# 1. プロジェクトの目的

マイナポータルの患者サマリーについて、次の3つを可視化・比較するモックアップを作成する。

1. 9月リリース前の表示
2. 9月リリース後の表示
3. あるべき姿（改善案・確定仕様ではない）

主な対象情報：

- 患者サマリ本体
- 検査情報
- 処方情報
- 薬剤アレルギー等／その他アレルギー等／感染症情報

特に、医療機関承継のタイミングと各情報の登録時点によって、患者サマリ上に検査・処方が表示されるかどうかを確認できるようにする。

# 2. 確定している業務仕様

## 2.1 患者サマリの医療機関コード

- 初回登録時に、その登録時点の医療機関コードで登録する。
- 医療機関承継が発生しただけでは、登録済み患者サマリのコードは変わらない。
- 閲覧時にはコードを再変換しない。
- 登録済み患者サマリを編集し、更新・再登録した場合は、**再登録時点の医療機関コード**になる。
- 初回登録と再登録の間に承継があれば、再登録時に旧コードから新コードへ置き換わる。
- v19では、再登録日が閲覧日より後の場合、その将来の再登録を現在の閲覧結果には反映しない。

## 2.2 検査情報の医療機関コード

- 検査情報も9月リリースの新旧コード紐づけ対象。
- 検査実施日から検査登録日までの間に承継がある場合、9月リリース後は登録時に新コードとなる。
- 登録済み検査情報を承継時・閲覧時に再変換しない。
- 患者サマリコードと検査コードは独立して保持する。

## 2.3 処方情報の医療機関コード

- 処方情報は電子処方箋管理サービスの扱う情報。
- 9月リリースの新旧医療機関コード紐づけ対象外。
- 電子処方箋管理サービスに記録された医療機関コードを使用する。
- 患者サマリや検査のコード変換処理を処方へ適用しない。
- 通常のシミュレーションでは処方日時点の旧／新コードを自動設定する。
- 例外検証用として旧コード固定・新コード固定も選択可能だが、警告対象とする。

## 2.4 患者サマリ上の表示条件

### 患者サマリ一覧

- 閲覧日から遡って直近過去180日分を対象とする。
- 現在のモックでは、期間判定日を指導日として暫定設定している。

### 検査情報

以下をすべて満たす場合に患者サマリ詳細へ表示する。

1. 検査情報が存在する。
2. 閲覧日時点で登録済みである。
3. 検査実施日が指導日から過去30日以内である。
4. 患者サマリの医療機関コードと検査コードが一致する。

### 処方情報

以下をすべて満たす場合に患者サマリ詳細へ表示する。

1. 処方情報が存在する。
2. 処方日が指導日から過去30日以内である。
3. 患者サマリの医療機関コードと処方コードが一致する。
4. 院外処方である。

処方取得可能日はデータとして保持できるが、現時点では表示判定に使わない。

## 2.5 プロフィール情報

以下は患者サマリの医療機関コード抽出とは別に扱い、全期間分を表示対象とする。

- 薬剤アレルギー等
- その他アレルギー等
- 感染症情報

薬剤アレルギー等と処方情報・薬剤情報を同一視しない。

## 2.6 「非表示」と「データ非存在」の区別

以下を独立して管理する。

- `patientSummaryVisible`：患者サマリ自体が一覧に表示されるか
- `visibleOnPatientSummary`：検査・処方が患者サマリ詳細に表示されるか
- `existsInRecord`：個別情報として存在するか

患者サマリ上に表示されないことは、情報の削除・消失を意味しない。

# 3. 未確定のまま維持する仕様

以下は推測で確定しない。

1. 30日前当日を対象に含むか
2. 180日前当日を対象に含むか

- 差がちょうど30日：`BOUNDARY_UNCONFIRMED`
- 差がちょうど180日：`BOUNDARY_UNCONFIRMED`
- 差が0日：期間内
- 複数理由：`reasons`配列に全件保持

# 4. あるべき姿（targetレーン）の考え方

「あるべき姿」は改善案であり、確定仕様・9月リリース内容ではない。

採用した方式：

- 確認済みの承継コードを同一集合として検索
- 各情報に記録された原コードは上書きしない
- 処方箋サービス側の処方コードも変更しない
- 閲覧時の照合処理で承継関係を考慮する
- `verified=true`の直接承継関係だけを同一扱いする
- 旧・新コード双方で同じ情報を取得した場合は`recordId`で重複排除する
- 承継マッピングで解消するのは`CODE_MISMATCH`だけ
- 期間外、未登録、院内処方、データなしは解消しない

照合方法：

- `EXACT`
- `SUCCESSION_MAPPING`
- `NONE`
- `UNCONFIRMED`

`matchMethod`はシミュレーター解説用で、患者向け実画面には表示しない。

医療機関名の改善案：

- 現行名称と受診時名称が異なる場合：`新しい病院（受診時：古い病院）`
- 同じ場合：名称を1つだけ表示

複数回承継は設計のみ。v19では直接1回承継だけを実装する。
