# Antigravity 立ち上げ指示プロンプト（個人用・1層版）

Antigravity を **個人用ワークスペース**として立ち上げるための指示。
**業務（`_agent/`・電カル・JLAC・タスク管理・活動ログ等）は一切持ち込まない**＝情報ガバナンス上、業務情報はClaude Codeに閉じ込める方針。したがって業務下位ルール（二層目AGENTS.md）・Knowledge業務情報・daily/タスクは**作らない**。

## 渡し方（2系統）
1. **先に共有資産をコピー**（AI非依存・そのまま動く）
   - チェッカー → `Antigravityプロジェクト/_ツール/` に `html_checker.py` `md_checker.py` `容量整理.py`
   - テンプレ → `Antigravityプロジェクト/00_プロジェクトテンプレート/`
   - 参考 → Claude側 `CLAUDE.md` を `_移植元_CLAUDE.md` として置く（※業務部分 `_agent/CLAUDE.md` は**コピーしない**）
2. **下の「===== ここから =====」〜「===== ここまで =====」をコピーして Antigravity のチャットに貼る**

# 依頼
この Antigravity ワークスペースを、**個人プロジェクト専用**の作業環境として立ち上げてください。別エージェント「Claude Code」で使っているプロジェクト管理規約のうち、**個人用に必要な部分だけ**を移植します。**業務用の仕組み（`_agent/`・タスク管理・日次ログ等）は作らないでください。** フォルダ規約・管理文書・Pythonチェッカーは共通資産として流用します（別途コピー済み）。

## 0. まず調査（いきなり作らない）
- 参考の `_移植元_CLAUDE.md` を読み、移植すべき個人用ルールを把握する（**業務系の記述は取り込まない**）。
- このワークスペースの現状（既存 `AGENTS.md`・コピー済み `_ツール/*.py`・`00_プロジェクトテンプレート/`）を確認する。
- 作成計画を提示し、私の承認を得てから作る。

## 1. 目標の構成
```
（ワークスペース直下）
├── AGENTS.md                 ← 個人用ルール（1層のみ・12,000字以内）
├── _ツール/                  ← Pythonチェッカー（コピー済み）
├── 00_プロジェクトテンプレート/
├── _archive/                 ← 任意（終了・統合したProject退避）
└── YYYYMMDD_プロジェクト名/    ← 個人プロジェクト
     ├── 01_input/ 02_output/ 03_scripts/ 04_reference/
     ├── プロジェクト状況.md
     └── 更新履歴.md
```
**`_agent/` は作らない。**

## 2. 機構対応表（Claude Code → Antigravity）
| Claude Code | Antigravity |
|---|---|
| `CLAUDE.md` | ルート `AGENTS.md`（1層。12,000字上限に注意） |
| 冗長なHTML作業ルール・検証プロトコル | **Skill（SKILL.md）**に切り出し、HTML作業時だけロード |
| スラッシュコマンド（/ship 等） | **Workflow** |
| 横断の恒久知識・好み・判断基準 | **Knowledge Items**（git内MD。※業務情報は入れない） |
| ブラウザ統合テスト | **ネイティブbrowser＋Artifacts**（スクショ/録画）で自己検証 |
| html_checker.py / md_checker.py / 容量整理.py | **そのまま流用**（`_ツール/` 配下をターミナル実行） |

## 3. 作ってほしいもの
### (A) ルート `AGENTS.md`（12,000字以内）
- **フォルダ構成**：上記ツリー。各プロジェクト `YYYYMMDD_プロジェクト名/`（`01_input/`原本・`02_output/`成果物・`03_scripts/`・`04_reference/` ＋ `プロジェクト状況.md`＋`更新履歴.md`）。
- **命名・版管理**：成果物＝`YYYYMMDD_名称_vN.拡張子`。改訂で vN+1、旧版はgit履歴に委ね作業ツリーは最新＋確定版。最新は `更新履歴.md` で明示。
- **管理文書2点の役割分担**：`更新履歴.md`＝版の台帳（表）、`プロジェクト状況.md`＝意思決定・進捗（文章）。二重記載しない。
- **情報の正本マップ**（二重管理防止・各情報は正本を1つ）：
  - Project固有の決定・前提・論点・次アクション → その Project の `プロジェクト状況.md`
  - 成果物の版 → `更新履歴.md`
  - 壁打ちの未確定仮説・将来案 → 該当Projectの `プロジェクト状況.md`「未確認事項」（Project外の一般的知見は Knowledge に**未確定と分かる形**で）
  - 横断の恒久知識・好み・判断基準 → **Knowledge Items**
  - 新規Knowledgeファイル/フォルダは原則作らない（既存正本へ統合を優先）。
- **2ユースケース**：A=壁打ち→整理（`02_output/..._v1.md`）、B=作成依頼→成果物（形式は目的から選ぶ：読む→MD、見せる→単一HTML、配る→PDF…）。
  - **壁打ち救済**：成果物を作らず終わる壁打ちでも、結論・決定・前提・知見が出たか確認し、正本マップに従い既存正本へ**最小反映**（新規ファイルを作らない／未確定は確定保存しない／価値なしは保存しない）。
- **セッション開始**：既存Projectなら `プロジェクト状況.md`＋`更新履歴.md` を読む／新規はテンプレをコピー／冒頭で宣言（📂Project ／ 📋状況あり・なし ／ 🎯モード＝壁打ち/作成依頼）。
- **セッション終了**：`プロジェクト状況.md` 変更履歴を当日分追記／成果物を出したら `更新履歴.md` 更新／恒久的に役立つ学びがあれば Knowledge に最小追記。
- **記述原則**：出典・根拠を明記／事実と推論を区別／未確認を隠さない／絶対日付。
- **容量管理**：中間版は間引き（git復元可）。`python _ツール/容量整理.py --apply`。
- 詳細（HTML作業・検証）は Skill に委譲する旨を1行で明記。

### (B) Skill「html-work」（SKILL.md・HTML作業時のみロード）
- 単一ファイル・外部依存なし／色はCSS変数／版番号はJS定数1箇所／既存は差分編集／相互リンクは版フォルダ方式／`<title>`とH1の表記一致。
- 3層検証：静的＝`python _ツール/html_checker.py <file>`（FAIL0）／ブラウザ＝Antigravityネイティブでコンソール0・スクショ・ダーク/モバイル確認／計算系＝スモークテスト。

### (C) Workflows
- `new-project`（テンプレ複製で `YYYYMMDD_{{args}}/` を初期化）
- `ship`（版上げ＋`更新履歴.md`/`プロジェクト状況.md` 更新。前に `md_checker.py`/`html_checker.py` を実行しFAIL0）
- `status`（`プロジェクト状況.md`/`更新履歴.md` から現状要約）

### (D) Knowledge 初期化
- 個人用の恒久知識（好み・判断基準・再利用できる知見）だけを対象に、最小限で開始。**業務情報は入れない。**

## 4. 進め方・検証・制約
1. 調査結果と作成ファイル一覧・各要点を**先に提示**→承認後に作成。
2. `AGENTS.md`/`SKILL.md` が**12,000字以内**か数えて確認。超える分は Skill へ退避。
3. 作成後：`python _ツール/md_checker.py AGENTS.md`（PASS確認）、Workflowsが `/` で出るか確認。
4. 「Claude個人運用との差分（できた/できない/代替した点）」を一覧報告。
5. 制約：**業務の仕組みは作らない**／新規ファイル最小化（既存正本へ統合優先）／二重管理しない／恒久知識はAI非依存のMD・gitで保持／コンテキスト肥大化を避ける（詳細はSkillで必要時ロード）／Pythonチェッカーは再実装せず流用。
