# 依頼
私はターミナルで動くコーディング/文書作成エージェント「Claude Code」で、成果物プロジェクトを一定の規約で管理しています。まったく同じ運用を、あなた（ChatGPT）で再現できるかを判定してください。

ChatGPTには複数の使い方があるので、少なくとも次を区別して答えること：
- **ChatGPTアプリ**（ブラウザ/デスクトップ。Projects・メモリ・Canvas・Code Interpreter[データ分析] を含む）
- **OpenAI Codex CLI**（ターミナルで動くエージェント。ローカルのファイル/シェル/git 操作が前提）

各「仕組み」について、必ず次の4点を答えること：
(a) 同等機能はあるか（Yes / 部分的 / No）。**どの使い方（アプリ / Codex CLI / Code Interpreter）で可能か**を明記。
(b) あるなら具体的な設定方法（設定ファイルの場所・形式、コマンド名、記法）
(c) Claude Code との差異・制約
(d) 無い/弱い場合の最も近い代替手段

## A. 管理規約（この運用自体を再現できるかも判定して）
- 全プロジェクトを1つのコンテナフォルダ（＝1つの git リポジトリ）に集約。
- 各プロジェクト = フォルダ `YYYYMMDD_プロジェクト名/`。直下は英語名で固定：
  - `01_input/`（入力原本・改変しない）／`02_output/`（成果物）／`03_scripts/`（スクリプト）／`04_reference/`（任意）
  - ＋ 管理文書2つ：`プロジェクト状況.md`（目的・前提・論点/スコープ・成果物・未確認事項・変更履歴）と `更新履歴.md`（成果物の版一覧の表。最新版は「太字＋（最新）」で明示）
- 成果物ファイル = `YYYYMMDD_名称_vN.拡張子`。改訂ごとに vN を +1、旧版は削除せず残す。試作は `02_output/_wip/` に隔離。
- コンテナ直下に `00_プロジェクトテンプレート/`（雛形）・`_ツール/`（横断ツール）・`_archive/`（統合済み/凍結プロジェクト）を置く。
- 記述原則：出典・根拠を明記／事実と推論を区別／未確認事項を隠さない／日付は絶対日付。
- 成果物の形式は目的から選ぶ（HTML/MD/PDF/xlsx/pptx/docx）。「とりあえずHTML」にせず、迷えばMDで中身を固めてから必要な形式へ展開（中身ファースト）。
- 容量管理：旧版は git 履歴で保全し、作業ツリー(`02_output`)は最新＋確定版のみ。中間版の間引き・重複バイナリ排除・`git gc` を再利用スクリプト（`_ツール/`）で回す。

## B. 再現したい「仕組み」
1. **自動読み込みの前提指示ファイル**：フォルダ階層に置いた指示ファイル（Claude Codeでは `CLAUDE.md`）を、そのフォルダで作業するたびに自動で文脈に読み込む（規約・命名・振る舞い）。ChatGPT/Codex の相当（Codexの `AGENTS.md`？／アプリの Projects のカスタム指示？）と、親→子への階層的マージ挙動は？
2. **セッションをまたぐ永続メモリ**：ユーザーの好み・運用ルールを保存し、次回以降のセッションで自動的に思い出す。ChatGPTのメモリ機能／Projectsの指示／Codexでの永続化の保存先・記法・呼び出し方は？
3. **カスタム・スラッシュコマンド**：定型作業をコマンド化。例）
   - `/new-project <名称>`：テンプレ一式をコピーして新規プロジェクトを初期化
   - `/ship <ファイル>`：版を vN+1 に上げ、管理文書2点を自動更新
   - `/status`：管理文書から現在の状況を要約
   Codexでの定義方法（カスタムプロンプト/コマンド・置き場所・引数の渡し方）、アプリでの代替（GPTs/Projects）は？
4. **イベントフック（最重要の確認点）**：ファイル編集後に、条件（例：パスに `02_output` を含む）に応じて「管理文書2点を更新して」というリマインド/コマンドを自動で差し込む（Claude Code の PostToolUse フック）。Codex に同等の「ツール実行の前後で任意コマンドを走らせる」フック機構はあるか？無ければ最も近い代替は？
5. **ファイル操作・シェル・git**：フォルダ作成、ファイルの移動/リネーム、`git init`・コミットをエージェント自身が実行できるか。実行時の承認（許可）モデルは？（Codex CLI前提。アプリでは不可か？）
6. **大きな単一HTML成果物の安全な改訂**：数千行・1MB級の単一HTML（CSS/JS/データを1ファイル内包・外部依存なし）を、全体書き直しせず差分（部分置換）で安全に編集できるか。トークン上限・部分編集ツールの有無・大規模ファイルでの精度は？
7. **多形式の成果物生成**：目的に応じて出力形式を選ぶ運用のため、Markdown/HTML に加え **docx・pdf・pptx・xlsx** をエージェント自身が生成できるか（Code Interpreter・ライブラリの有無）。

## C. 出力形式
1. 可否一覧表（列：仕組み / 使える使い方（アプリ/Codex CLI/CI） / 設定場所・記法 / 制約 / 代替）
2. 「ゼロから同じ運用を立ち上げる最短手順」（**Codex CLI版**と**アプリ版**をそれぞれ）
3. 「Claude Code に比べてできない・弱い点」の明示

## 使い方メモ
- 本命は **Codex CLI**（ファイル/シェル/git が前提のB-4/5/6が実現しやすい）。**アプリ単体**だと 4・5・6 は「不可」寄り、7（多形式生成）は Code Interpreter で可。
- 焦点は **B-4（イベントフック）／B-6（大規模単一HTMLの差分編集）／B-7（docx等の生成）**。
- ChatGPTの回答は、この下に日付つきで追記していけば比較メモとして蓄積できる（Gemini版とも並べて比較可能）。
