# 議事録・逐語録 共通ルール

横断的に適用するルール集。個別プロジェクト固有のフォーマット（JLAC専用ヘッダー等）はここに書かない。
最終確認: 2026-09-28

## 1. ファイル管理

| 種別 | 配置場所 | 命名 |
|---|---|---|
| 逐語録 | `02_output/` | `YYYYMMDD_逐語録_会議名_v1.md` |
| 議事録 | `02_output/` | `YYYYMMDD_議事録_会議名_v1.md` |
| 音声・元データ | `01_input/` | 原本のまま保存（改変しない） |

**⚠️ Claudeが生成した逐語録・議事録は、次工程のインプットになる場合でも `02_output/` に置く。`01_input/` や `_agent/_input/` には入れない。**

## 2. 逐語録の作成ルール

### 2-1. インプット処理

- **フィラー除去**: 「えー」「あの」「えっと」「まあ」等は削除する
- **専門用語補正**: 自動書き起こしが誤認した専門用語を正しく修正する（例：「じゃ連」→「JAREN」）
- **文意が取れない箇所**: `[聞き取り不明]` と明記し、推測で埋めない

### 2-2. 話者表記

- **話者が特定できる場合**: `（氏名）` または `（組織　氏名）` を各発言に付ける
- **話者が不明・不確かな場合**: `（話者不明）` と書き、推測で組織・氏名を断定しない
  - 自動書き起こしの `spk_1` 等の話者IDを過信しない
  - 文脈から推測した場合は `（おそらく○○）` と明示する
- **過去インシデント**: spk_4を誤ってACと判定→厚労省所属の誤りが発覚（2026-09-11）

### 2-3. 末尾付記

逐語録末尾に「論点サマリー表」を付けると議事録作成の効率が上がる。

```
| 議題 | 議論内容の要点 | 決定事項 | 宿題・懸案 |
```

## 3. 議事録の作成ルール

### 3-1. 基本構造

```
日時・参加者・資料
↓
サマリーテーブル（全議題 × 決定事項 × 宿題事項）
↓
凡例
↓
議事本体（議題ごとに詳細）
```

サマリーテーブルは**必ず冒頭に置く**（読み手が全体像を掴むため）。

### 3-2. 参加者の記載

- 「敬称略」と明記する
- 同一組織は1行にまとめる: `組織名　氏名A、氏名B`
- 議事録担当者には `（記）` を付ける
- **参加者の所属が不明・不確かな場合は推測で断定しない。「所属不明」と書くか、ユーザーに確認する**

### 3-3. 決定事項・宿題事項

- **決定事項**: 議論の中で結論が出た箇所に**インライン**で挿入する（末尾にまとめる形式もあるが、インラインが標準）
- **宿題事項**: 必ず「担当」と「期限」をセットで記載する。不明な場合は「未定」と書く

  ```
  宿題内容。【担当：○○、期限：○○】
  ```

- 「誰が・いつまでに・何をするか」が書かれていない宿題は不完全とみなす

### 3-4. 事実と推論の区別

- 逐語録や配布資料に根拠がある内容 → そのまま記載
- Claudeが文脈から推測した内容 → `（推測）` と明示、または記載しない
- **議事録には推測・補完を混入させない**

---

## 4. 発言者の帰属（フォーマット未指定時のデフォルト）

フォーマットが指定されていない場合は、以下をデフォルトとして使い、依頼主の会議スタイルに合わせて調整する。

- 段落の末尾: `内容文章（組織名　氏名）` ← **標準**
- 段落の冒頭: `（組織名　氏名）内容文章` ← 一部会議で採用

フォーマット指定がある場合はそれに従う。**指定がない場合は末尾形式をデフォルトとし、ユーザーに確認してから変更する。**

---

## 5. 話者・参加者の誤判定を防ぐ

過去インシデントから抽出した防止策：

1. **自動書き起こしの話者ID（spk_N）は「仮ラベル」**。文脈・敬語の向き・呼称から正しい話者を判断する
2. **逆算で確認**: 「この人がこの発言をする理由があるか？」を考える
3. **迷ったら記載しない**: 不確かな所属を断定して書くより `（所属確認中）` と置いておく
4. **ユーザーが提供した参加者リストが最優先**: 逐語録から推測した結果よりも、ユーザーが明示した情報を採用する
5. **ユーザーの手書きメモ（OneNote等）があれば必ず照合してから確定する**: 逐語録だけでは発言者・宿題担当が誤判定されることがある。メモとの照合で修正してから版を確定させる（2026-09-28 BIツール会議で複数箇所の発言者ずれを照合で発見）

## 6. 逐語録→議事録の連携フロー

```
音声ファイル / 自動書き起こし（01_input/）
    ↓ Claudeが整形
逐語録 v1（02_output/）  ← 時刻・話者・フィラー除去済み
    ↓ Claudeが要約・整理
議事録 v1（02_output/）  ← 決定事項・宿題事項を整理
    ↓ ユーザーが確認・修正（参加者所属・手書きメモとの照合）
議事録 v2（02_output/）  ← 参加者所属修正・内容精緻化・確定
```

- 逐語録と議事録は**別ファイル**。議事録は逐語録を基に作るが、逐語録の中に議事録を混在させない
- 議事録v1で参加者情報に誤りがあれば、ユーザー確認後にv2として修正版を作成する
- **ユーザーが手書きメモ（OneNote・紙メモ等）を持っている場合は、議事録確定前に提供を求めて照合する**

## 7. 議事録の丸め方ルール

逐語録から議事録に圧縮する際の基準。

### 省略してよいもの
- 「承知した」「了解した」等の**単純な相槌・受領確認**（発言として残す情報がない）
- 会議冒頭の**音声確認・接続確認**
- 「以上です」「ご説明申し上げます」等の**形式的な前置き・締め**

### まとめてよいもの
- 同一話者の**連続する複数発言**は、話題が同一の場合に限り1段落にまとめる。**話題が変わったら同一話者でも段落を切る**
- 資料に沿った**技術説明・スライド説明**は「当日資料の内容説明は割愛」として要点のみに圧縮する
- 質疑応答は**問い→答え**の対で整理し、問いが複数の議題にまたがる場合は議題ごとに切り分ける

### 残すべきもの
- **決定事項・宿題・合意**：たとえ一言であっても省略しない
- **懸念・保留・反対意見**：「問題になる可能性がある」等のリスク発言は要約して残す
- **数値・固有名詞・期限**：「5か月間」「24個のマート」「今週中」等は正確に残す
- **〔聴取不明〕箇所**：推測で補完せず、そのまま残す

## 8. レビュー観点（作成時のセルフチェック／Rvポイント）

議事録は**本田さんがRvする前提**で作る。渡す前に 8-1・8-2・8-3 で自己チェックし、結果を添える。

### 8-1. 基礎チェック（全文書共通）

出典：ユーザー提供のチェックリスト（`_agent/_input/20261006_文書作成チェックリスト_スクリーンショット.png`、2026-10-06）。

| 分類 | チェック項目 | 議事録での見方 |
|---|---|---|

| 内容 | ふわっとしない（雰囲気日本語をさける） | 「検討する」「対応する」で終わらせず、何をするかを書く |
| 内容 | 平仄（へいそく） | 同じものは同じ書き方にする（用語・表記・粒度・文末）。用語は `電カル共有_用語集.md` §7 |

| 表現・テクニック | 「とおり」の表記 | 接続詞・形式名詞の用法はひらがな（「下記のとおり」「説明のとおり」） |
| 表現・テクニック | ビュレットの階層 | 問い・話題の起点＝1段目（●）、応答＝2段目（➢）。見出し・小項目の直下に2段目を置かない。表の決定・宿題は1件でも「•」を付け、該当なしは「―」（•なし）。※9/15正式版も表の「•」が不統一だったので、ひな型をそのまま真似しない（2026-10-06 ユーザー指摘） |

| 見た目 | フォント | ひな型どおり（JLAC議事録：Meiryo UI） |
| 見た目 | 文字サイズ | ひな型どおり（JLAC議事録：本文10.5pt、表10pt） |
| 見た目 | 見出しの泣き別れ | 見出し・小項目だけがページ末に残らないようにする（Wordの「次の段落と分離しない」） |
| 見た目 | 半角・全角 | 英数字は半角、記号は全角（「（）」「：」「～」）。見出し番号「１．」は全角 |

### 8-2. 本田さんのRv観点

出典：20260915 JLACセンター打合せ議事録の本田さんRv（見え消し：挿入251・削除190。`_agent/04_マスタ・プロファイル管理/JLAC/20261006_JLACセンター打ち合わせ/04_reference/` に原本）。2026-10-06 整理。

| # | 観点 | 直し方の例（9/15 Rv） |
|---|---|---|
| 1 | 問いと答えをかみ合わせる | 答えに合わせて問いを書き直す（「どのような項目が課題を抱えているか」→「パネル検査は具体的に何を指すのか」） |
| 2 | 答えは問いへの結論だけ | 補足・内情・言い訳・注記を削る（「製品情報に精通しておらず時間を要している」は削除） |
| 3 | あいまいな指示語を具体化する | 「9月版のマスタ」→「電カル共有用JLACマスタの9月公開版」、「本日」→「9/15中」、「資料」→「資料名＋スライド番号」。日付は「9/2に提出いただいた」のように入れる |
| 4 | 事実・用語を正確にする | 意味の取り違えを直す（「一部製品名がなくなった」→「材料コードの見直しで一部レコードが削除された」）。用語を統一する |
| 5 | 決定は受けた側の「承知した」で成立させる | 提案した側の発言から【◎決定】を外し、受けた側の「承知した。【◎決定】」を足す。一方的な発言・検討レベル・次回日程は決定にしない |
| 6 | 宿題は実際に動く側・具体的な期限で書く | 担当・期限を実態に合わせる（JLAC／9月15日→厚労省／9月30日）。中身は具体的な行動にする（「資料を確認」→「スライド10～12を確認」） |
| 7 | 発言の流れを補い、話者ごとに分ける | 抜けた問い（「いつ頃公開予定か」）や説明を足す。1段落に混ざった2人分の発言は分ける |
| 8 | こちら（厚労省・AC）側の言い方を整える | 外部に誤解される言い方を直す（「厚労省の確認を経ずに公開」→「受領したマスタのまま公開」）。相手への依頼の形にする（「問題ないと考える」→「問い合わせを受けた際に確認させていただきたい」）。非公表情報・自己評価は配布先を考えて書くか判断する |
| 9 | 文体をそろえる | 体言止めにしない（「〜なし」→「〜はない」）。前置きを短くする |
| 10 | 表と本文を一致させる | 表の決定・宿題は本文の【◎決定】【★宿題】と1対1にし、表では1文に抽象化する |
| 11 | Rv反映後に読み直す | 見え消しを承諾した後の消し残り（「〜ため、として」「ないない」「までにまでに」）を確認する |

### 8-3. 機械的に確認できること

- 用語集 §7 の「使わない表記」が残っていないか（文字列検索で数える）
- 表の決定・宿題の件数と、本文の【◎決定】【★宿題】の件数が一致するか
- 話者が不確かな箇所は黄色ハイライトで残し、件数を報告する
- ビュレット：見出し・小項目の直後に2段目（➢）が来ていないか。表の項目に「•」の有無が混ざっていないか

レビュワーの特性（誰が何を見るか）は `_agent/_ツール/関係者プロファイル.md` に書く。新しいRv済みファイルを受け取ったら、前後の差分から 8-2 に観点を追記する。
