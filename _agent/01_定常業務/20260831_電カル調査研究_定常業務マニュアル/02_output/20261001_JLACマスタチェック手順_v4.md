## 3. 月次チェック手順

### Step 0：全行にチェックロジック適用（重複検出のため）

- チェックロジック（KA-01〜KA-M3、39件）を全行に対してかける
- **目的**：コード重複・構造エラーを見落とさないため（既存行も含めて一括チェック）
- 結果を「作業Excel」に出力し、問題箇所にコメントを記入する

### Step 1：既存行の確認（前月との差分チェック）

- 新規追加でない行（前月マスタに存在する行）について：
  - **Step 0で大量エラーが出ても一旦無視**（既存行のエラーは既知のものが多い）
  - **前月マスタとの差分がないかを確認**する
- 差分がある場合の判断：

| 差分の種類 | 判断 |
|---|---|
| 適用終了日 `99999999` → 特定の日付に変更 | **問題なし**（マスタ更新で切り替えが生じるため） |
| 適用終了日の日付が不自然（遠い未来・1日等） | **要確認**（おおよそ15日前後が想定、1日等は要確認） |
| 適用終了日以外の変更 | **要確認**（誤作業の可能性） |
| 行の削除 | **指摘する**（削除は想定外のため） |
| 適用終了日のバックデート | **要確認**（詳細判断基準：後日確認） |

> **見直し前コードについて：** 6月に一気に見直しを実施。古いコードは適用終了日を設定して放置（削除しない）。

### Step 2：新規追加行の確認

- 新規追加行（前月マスタに存在しない行）について：
  - **Step 0のチェックロジック結果を全件確認する**（問題が潜在する可能性があるため無視しない）
  - 新規行の見つけ方：基本的にExcelの下部に追加される（メールも要確認）

### Step 3：JLACセンター向けコメント記載（毎月1日の初回提出分のみ）

- 疑義事項をJLACセンター向けにコメントとして作業Excelに記載する
- **本田さんRv後（10/7まで）** にJLACセンターへ疑義を連携する

### 最終化（CSV化）時の注意

- 「**並び順**」列のフィルターで**昇順**にしてからCSV化する

## 7. ダミーコード（「その他」のコード）の作り方（2026-10-07 本田さんKT）

- 「その他」に分類されるコードは、**既存のコードから作る**
- JLAC11の測定法コード（**13〜15桁**）が **000** のものは「その他」に分類される（JLAC10では **999**）
- 作り方：
  1. 既存のJLAC11コードの13〜15桁を **000** に置き換える
  2. 置き換えた結果から**重複を除いた一覧**を作り、「その他」のコード一覧とする
- このコードを**ダミーコード**という。**ダミーコード＝『その他の測定法』コード**（JLAC11の13〜15桁目が000のコード。用語集の表記は「その他の測定法」コード）。チェックロジックの KA-33・KA-34 と関係する
- 関連：日本衛生検査所協会打合せ（10/6）後の方針に「その他の測定法でマッピングすることであれば可能か」の検討がある

### 7-1. 作成ツールでの作り方

使うもの：`電子カルテ情報共有サービス対応JLACコード表作成ツール_20250127.xlsx` の「ダミーコード生成用」シート（本田さん共有）

1. 「★共有項目JLACコード(原本)」に、その月のマスタを**全件**貼り付ける
2. 「ダミーコード生成用」で次の行を除く
   - **AI列が `A` の行**（2回目以降に出てきた000コード）
   - **JLAC11コード（M列）が空の行**（000版を作れないため。ツールのままだと「000」だけの行が出る）
   - 本田さんメモの「AL列：A排除」は、AI列で `A` を除けば結果は同じ。ALだけで絞ると `AB` の行が残るので、**AI列で必ず絞る**
3. 残った行のAP〜BS列を**値で**貼り付け、000コードの一覧にする
4. **マスタにすでにある000コードと同じものを除く**（原本にもともと「その他」があるため。重複させない）
5. 適用終了日を確かめる：同じグループに有効な行（99999999）があるのに000コードに終了日が付いていたら `99999999` に直す（KA-34）

### 7-2. 各列の決まり方（ツールの式）

| 列 | 値 |
|---|---|
| JLAC11コード | 元のJLAC11コードの13〜15桁を000にしたもの（`LEFT(M,12)&"000"&RIGHT(M,2)`） |
| JLAC10コード | 元のJLAC10コードの13〜15桁を999にしたもの |
| 測定法(JLAC11)・検査方法(JLAC10-測定法) | 「その他の測定法」（固定） |
| 販売名称 | 空欄 |
| それ以外（名称・FHIR識別文字列・単位・並び順・適用開始日・適用終了日など） | 000にまとまる行のうち**いちばん上の行**の値を写す |

- 測定法だけが違う複数のコードは、1つの000コードにまとまる。例：`V2259000021200002` には「HIV-1+2抗体(定性)」と「HIV-1+2抗体・p24抗原(定性)」がまとまり、FHIR識別文字列は上にある「HIV-1+2抗体(定性)」になる。**この決め方でよい**（2026-10-07 ユーザー判断。9月公開版も同じ決め方になっている）
- 適用終了日もいちばん上の行の値が写るため、いちばん上の行が終了したコードだと000コードにも終了日が付く。10/6提出版のKA-34（3件・終了日20260812）はこの形

### 7-3. ⚠️ 32列のマスタ（表示用単位2・XML用単位2あり）で使うときの注意

| 問題 | 内容 | 対処 |

### 8-3. 実行のしかた

1. ツールのHTMLをEdgeかChromeで開く
2. 5つのファイルをまとめて枠にドラッグ＆ドロップする。どのファイルが何かはツールが自動で判定し、画面に表示する。**表示が合っているか必ず見る**
3. 「設定を確認する」を確認する。通常は変更しない。次の2つだけは、JLACセンターのメールを見て合わせる
   - **新規行の開始行**：「8367行目以降が新規」のようにメールに書かれている行番号
   - **今回の公開日**：通常はその月の15日
   - JLACセンターから修正の連絡（連携済みの変更・メール本文の連携事項など）があれば「今月の個別対応（任意）」に入れる。前月の値は流用せず、その月の連絡から書き直す。入れた内容は `YYYYMM提出分/04_reference/` にテキストで残す（かけ直すときに同じ設定を使うため）
4. 「チェックを実行」を押す
5. 結果画面で「要確認」の黄色い枠を読み、ファイルをダウンロードする

### 8-4. 出てくるファイル

| ファイル | 誰向け | 中身 |
|---|---|---|
| 確認事項一覧（送付用） | JLACセンター | 関係者と合意した形式。確認用シートのAG列にJLACセンター向けコメント、その後ろに提出の原本 |
| 確認事項一覧（ACN確認用） | 社内（本田さんRv用） | チェック結果一覧・その他の指摘事項・ツールの通知・確認用シートのAH列以降（新規/既存・該当チェックID・前月の結果・差分区分）。**JLACセンターには送らない** |
| チェック結果報告（md） | 社内 | 確認事項・ロジック別の結果・既知のエラーのまとめ |

- 保存先は `YYYYMM提出分/02_output/`。名前は `YYYYMMDD_JLACマスタ確認事項一覧_[ACN確認用_]JLACセンターYYYYMMDD提出版_vN.xlsx`
- ⚠️ ACN確認用のシート構成は調整中（2026-10-07時点）。決まったらこの節に追記する

### 8-5. ツールの判定のしかた（結果を読むときの前提）

- **新規行**（前月に同じJLAC11コードが無い行）：すべての結果をコメントにする
- **既存行**：前月から変わって生じた問題、行の削除だけをコメントにする
- **既知**（前月にも同じ問題がある）：コメントせず件数だけ記録する。前月に了承して公開済みのため
- **参考**：判定材料が不完全なもの（コード表の版の違いなど）。コメントせず、目で確認する
- 既知かどうかは**指摘の文面が前月と同じか**で決まる。前月から不一致の行でも、値が変わると新しい指摘として出る（10/6再提出のKA-08の5行がこれ。説明を書くときに誤りやすい）

### 8-6. 送付までの流れ

1. ツールを実行する（8-3）
2. ACN確認用で論点を整理し、本田さんにRvを依頼する。見てほしいシートと見なくてよいシートを依頼文に書く
3. Rvの結果を反映する。同じ月に再提出があればツールをかけ直す。2回目のRvでは、前回のRvで終わっていない論点を引き継ぐ。同じ論点の続きには新しい番号を付けず、元の番号の下に書く
4. 送付用をJLACセンターへ送る（毎月7日頃まで）。**送る前に、コメント・変更履歴・ファイルのプロパティを削除する**（定常業務マニュアル Section 11）
5. 送付用・ACN確認用は**Excel本体で開いて、修復のメッセージが出ないことを確かめてから**渡す

### 8-7. ダブルチェック（任意・Claude Codeがあるとき）

ツールとは別に、Excelの関数だけで同じ判定をして結果を突き合わせる仕組みがある。ツールの結果に疑問があるとき、またはツールを直したときに使う。

- `python 00_共通/03_scripts/make_doublecheck.py <ACN確認用xlsx> <出力xlsx> [YYYYMM提出分]` で作る。入力ファイル名・新規開始行・公開日はスクリプトの冒頭で毎月書き換える
- Excelで開いて計算させ、「照合」シートがすべて一致なら、ツールの結果と同じ
- 一致しない項目は、検算式とツールのどちらが正しいかを原因まで調べる（過去には両方の誤りが見つかっている）

### 8-8. 困ったとき・ツールを直すとき

- 結果に疑問があるときは、出てきた「チェック結果報告」を添えて管理者に相談する
- チェックロジック39件は関係者と合意したものなので、**勝手に変えない**。改善したい点は `00_共通/02_output/*_チェックロジック改善提案_vN.md` に書く
- ツールを直す手順（版の上げ方・試験のしかた）は `JLACマスタ月次チェック/CLAUDE.md` にある
