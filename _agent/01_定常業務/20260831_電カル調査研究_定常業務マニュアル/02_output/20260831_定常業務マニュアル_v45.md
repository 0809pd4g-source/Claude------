### 議事要旨（案）のチェックのしかた（4章・5章共通）

手順1の「コメント案」は、ツールで指摘の候補を出してから、人が採否を決めて作る。

**ツール**：`_基盤/_ツール/議事要旨チェック/check_gijiyoshi.py`（Python。Claude Code環境で動かす）

```
python check_gijiyoshi.py --minutes 議事要旨(案).pptx --date 2026-10-05 --out 結果.md
    [--materials 会議資料.pptx 会議資料_厚労省側.pptx] [--ledger 課題・TODO管理台帳.xlsx]
    [--prev 前回の議事要旨.pptx] [--transcript 逐語録.md] [--notes 逐語録ベースの議事録.md]
    [--annotate コメント入り.pptx]
```

- 必須は議事要旨（案）と会議日だけ。ほかを渡すほど照合が増える（渡さなかった照合は飛ばす）。台帳は読むだけで保存しない
- `--annotate` を付けると、指摘の箇所に黄色のハイライトとコメント枠を入れたpptxを別ファイルで作る（元のファイルは変えない）
- 照合すること：台帳との照合（件数・期限・担当・記載漏れ）、会議資料との照合（アジェンダ・参照・案件名）、前回のToDo、逐語録、体裁・表記（英数字のフォント・句読点など）。結果は「要修正／要確認／参考」に分かれる

**採否の決め方**（2026-10-07〜08 ユーザー決定）
- 課題・ToDo台帳は**会議前の記載を正**とする。照合するのは、**会議後に追記された内容**（「M/D 会議名にて…」の追記や、会議で発生したToDoの起票）が議事要旨・逐語録と食い違っていないかだけ
- 台帳の中だけの食い違い（会議と関係のない進捗欄どうし等）や、議事要旨に出てこない案件の資料内だけの名称のゆれは、指摘しない
- 会議後の追記・起票が会議の結果と違う場合は「要確認」とし、議事要旨には貼らず、ACN内の確認事項として出す
- 台帳との照合は**一次Rvのときだけ**でよい（最終の突合は機構側が行う。確定版を受け取った後に台帳を再照合しない）
- 10/5分で採用されたもの：件数、延伸前の期限（台帳の会議前の値）、句読点、ID採番の競合、資料の更新・取り下げの記載漏れ、英数字のフォント違い。採用されなかったもの：案件名の表記差、軽微な語句の重複、逐語録ベースのToDo漏れ候補（根拠がClaude作成の議事録のもの）
- 人の判断で付けるコメント（ToDoの削除範囲・時期尚早・会議で依頼がなかったToDoなど）はツールでは判定しない。ツールが並べる逐語録の該当箇所を見て判断する

### 7-1. 台帳管理フロー（週次）

#### 受領（毎週月曜・水曜）
- [ ] 厚労省Teamsにて基金側からONS台帳更新の連絡を受領する
- [ ] 基金側の台帳ファイル①（スレッド上のリンク先）から厚労省側の台帳ファイル②に内容を転記する
  - **新規起票**の場合：①の該当行を②に丸ごとコピーする
  - **更問**（過去質問への追加質問）の場合：②の過去問い合わせ該当行に転記する
  - 転記後、①のL列「回答状況」を **「厚労省確認中」** に変更する
  - 転記後、②のM列「回答状況」を **「ACN回答作成」** に変更する

#### 受領後の一時切り分け

**Step 1：過去に既出かどうか確認する**
- Excel（台帳②）で過去の回答事例を確認する
- 既出のものは過去の回答を参考に回答案を作成する

**Step 2：新規事項は以下で分類する**
- 回答案を作成できそう → 回答案を作成し、回答状況を `読み合せ` に変更する
- 回答方針確認が必要 → 方針案を含む回答案を作成し、回答状況を `回答方針確認` に変更する

> **基金確認・厚労確認の使い分け（本田さんより）**
> - **基金確認**：システム仕様の確認が必要なもの・ベンダテスト・運用テスト系
> - **厚労確認**：回答の落としどころを検討するためのディスカッションが必要なもの（前例がない質問・FHIR関連等）
> - ★回答方針確認にする場合も、**オープンクエスチョンにせず**、考えられる対応策・落としどころの提案を準備しておくこと

### 7-2. ONS問合せ会議（毎週火曜 14:15–15:00）

#### 会議前

**金曜（事前着手推奨）**
- [ ] 水曜受領分のうち未着手の回答案を確認し、着手可能なものから回答案作成を開始する
- [ ] **特にB（回答方針確認）区分**はRvに時間がかかるため、金曜中に本田さんRv依頼まで進めることを目指す（本田さんRv → 向井さんRvの2段階があるため月曜以降では火曜に間に合わないリスクあり）

**月曜〜火曜（最終仕上げ）**
- [ ] 新規起票等を厚労省ファイルに反映する
- [ ] ONS回答案を作成し、Rvを進める（下記フロー参照）
- [ ] エスカレ事項を検討する（→本田さんに確認）

**回答案作成フロー（ケース別）**

| ケース | フロー |
|---|---|
| **A. 回答案を作成できるもの** | 回答案作成 → 本田さんRv → 向井さんRv → 回答状況を `読み合せ` に変更 → 会議内で読み合せ |
| **B. 回答方針の確認が必要なもの** | 方針案を含む回答案作成 → 本田さんRv → 向井さんRv → 回答状況を `回答方針確認` に変更 → 会議内で読み合せ・方針決定 |

> **注意（本田さんより）**：★回答方針確認にする場合も、オープンクエスチョンで終わらせず、考えられる対応策・落としどころの提案を必ず準備しておくこと。

#### 読み合わせスクリプトの作成（会議前・毎週）

厚労省はFHIRや技術に詳しくない前提で、読み合わせる件ごとに説明スクリプトを用意する（2026-10-06〜）。詳しい作り方・注意点は `_agent/_基盤/_ツール/ONS回答作成ガイド.md`。

**1件の型（全件同じ構成にそろえる）**
1. **何についての質問か**（一言）：サービス（文書送受信／臨床情報／健診文書）、文書の種類（診療情報提供書・退院時サマリー・健康診断結果報告書）、IF（例：CIS-IF-101）、技術解説書の機能番号を特定できる範囲で補足する
2. **ご質問**：ベンダの質問を平易な言葉で言い直す（文章で）
3. **回答案**：台帳に入れた最終の回答案の要点を文章で言う。最後に根拠（技術解説書等のページ）を一言
4. 基金（機構）への連携事項がある件は、回答案の後に連携事項と「この返し方で問題ないか」の確認依頼を入れる

**書き方のポイント**
- スクリプトは**台帳に入った最終の回答案**から作る（途中の案から作ると、根拠や言い回しがずれる）
- 用語は回答文と同じ言葉を使う（例：「患者共有フラグ」を「印」などに言い換えない。言い換えると別のものに聞こえる）。初めて出る用語は「何についての質問か」の中で一文で説明する
- 対象の範囲が限られる言葉は限定を付ける（例：「検査項目」→「感染症の検査（感染症5項目）」）
- 似た分野の質問は続けて読み、冒頭に「共通の分野の質問です」と一言入れる（例：#534・#536 緊急時の同意）。各件の型はそろえたまま
- 想定される質問（答え方と根拠）を表で用意する。回答から外した注意点・未確認の点はここに入れる

**読む順**
- ONS問合せの各件（番号順。似た分野はまとめる）→ 開発進捗連絡会議が書面開催の週は、資料の読合せ（Section 7-4）→ 締め


#### 会議中
- [ ] 議事メモを記載する
- [ ] 共有事項の説明を行う

#### 会議後
- [ ] 基金ファイルに変更点を反映・報告する
- [ ] Plannerに発生したTODOを記載する
- [ ] **台帳綺麗化**（2026-10-05 黒川さんより移管。担当：中澤）：読み合わせた回答の回答欄を整理し、M列を「**ONS回答済(YYYYMMDD)**」に変更する。**YYYYMMDDは機構への連携日（通常は翌日の水曜）を入れる**。完了後、本田さんにRv依頼の投稿をする。
  - 条件付き書式により、**連携日になるまでグレーアウトしない**（連携日になると自動でグレーになる）。当日の日付を入れるとすぐグレーになるので注意
  - 本田さんのRvでOKが出たら、M列はそのままでDX機構へ連携する（→7-1「返送（毎週水曜）」。機構へのコメントは①のK列、【回答案】は付けない）
  - 条件付き書式（「ONS問い合わせ」シート、適用先 B2:Q1000、3つ目のルール。2026-10-06変更・本田さん了承）：`=AND(ISNUMBER(FIND("ONS回答済",$M2)),IFERROR(DATE(MID($M2,FIND("ONS回答済",$M2)+7,4),MID($M2,FIND("ONS回答済",$M2)+11,2),MID($M2,FIND("ONS回答済",$M2)+13,2))<=TODAY(),TRUE))`。日付なしの「ONS回答済」、日付が読み取れない行は従来どおりグレー
  - 投稿先：`2026年度_電子カルテ情報共有サービス > 02_電カル共有調査研究`
  - 文案例：`Honda, Keiko さん / 本日のONSで読合せた回答〇件につきまして、回答欄綺麗化のうえ、M列を「ONS回答済(YYYYMMDD)」（連携日）へと変更しております。DX機構への連携（明日実施予定）の前に、念のためご確認いただけますと幸いです。`

### 7-4. 開発進捗連絡会議（書面開催・書面確認分）の読合せ

- [ ] 資料を投影し、さらっと確認する（細かく読み上げなくてよい）
  - 話し方の例：「赤字部分が更新点です。今回はスケジュールは○○がアップデートです。新規の障害・課題は特段報告ありません。」
- [ ] 最後に厚労省からコメントがないかを確認しつつ、スレッド投稿を宣言する
  - 話し方の例：「資料は以上になります。こちらで基金さんに確認完了と報告させていただきます。」

#### 会議後

  - 宛先：Nakazato, Yuri（CC: 08_富士通 09_NTTD）

    > 今回、特段のコメントはございません。
    > 今後ともよろしくお願いいたします。

  - 厚労省からコメントがあった場合は「今回、特段のコメントはございません。」の代わりに、コメントの内容を書く（文面は本田さんに確認）

### 8-3. terminology月次更新：収載マスタ版数の回答（毎月）

> **ポイント**：2026-10-06に黒川さんから中澤へ移管（黒川さんKT）。約半年前から、DX機構（芳原さん）から毎月「NTTデータで取得した最新terminologyに収載されているマスタの版数を教えてほしい」というメールが来るので、毎月回答している。目的は、NTTデータ（ND）が取り込むマスタの版数を確認すること。

**手順（スクリプトを使う場合・推奨）**
1. 依頼メールで、対象のterminologyの版（例：Ver. 2.2609.0）を確認する
2. `python _agent/_基盤/_ツール/terminology版数確認.py 2.2609.0` を実行する（前月版を自動でダウンロードして比較。比較する版は2つ目の引数で指定可）
3. 出力された表の「版」をメールの表に書き、「更新」が★の行を赤字にする。健診マスタは別途確認する
4. 出力の最後の「参考：回答対象外のCodeSystemの変化」に**増えた・消えたファイル**があれば、回答表に入れるべきマスタが増減していないかを確認する（必要ならスクリプトの MAPPING を直す）
5. メール文案を作成 → 本田さんにRv依頼 → Rv完了後に芳原さんへ返信する

**確認するファイルの選び方（ロジック）**
- 回答表の行は毎月同じ（前月の回答表を正とする）。行ごとに、パッケージ内のCodeSystemのファイルを1対1（JLACは4ファイル）で決めてある（下の表の「確認するファイル」）
- 決め方：①回答表の左端の識別子（diseasekanricodes・modifiers・allergenYCM 等）がそのままファイル名に含まれるものを選ぶ → ②候補が複数あるときは、ファイルの `title` が回答表の「名称」と一致するものを選ぶ
  - 修飾語：候補が3つある（`diseasenamecodes-modifiers`＝MEDIS病名 修飾語管理番号／`diseasename-exchangecodes-modifiers`＝修飾語交換用コード／`condition-disease-modifier-receipt`＝レセプト電算用修飾語マスター）。「修飾語マスタ」は標準病名（MEDIS）側の管理番号を指すと判断して `diseasenamecodes-modifiers` を選んだ（2026-10時点では3つとも5.18.0で結果は同じ）
  - 用法：候補が2つある（`mhlw-medication-usage-jami`＝電子処方箋管理サービス 標準用法コード／`jp-medication-usage-jami`＝JP Core JAMI 16桁用法、1.1.1）。名称「電子処方箋管理サービスの…用法マスタ」と一致する `mhlw-` を選んだ
  - JLAC：JLAC10/JLAC11 × 基本（corelabo）/感染症（infectionlabo）の4ファイル。4つとも同じ版であることを確認する
  - YJ：`medicationcode-yj`（全件）と `medicationcode-yj-Active`（アクティブのみ）がある。名称「個別医薬品コード（YJコード）リスト」に合わせて全件の方を選んだ
- **健診マスタはパッケージに含まれないため、毎月個別に確認する**（2026-10-06 黒川さん確認）
- J-FAGYの回答表の行は食物（`jfagy-food-allergen`）のみ。非食物・非医薬品（`jfagy-non-food-non-medication-allergen`）は**回答表に無いので対象外**（スクリプトの参考出力に版の変化が出ても回答には入れない）

**手順（手作業の場合）**
1. 依頼メールで、対象のterminologyの版（例：Ver. 2.2609.0）を確認する
2. https://std.jpfhir.jp/ → terminology（Ver.2系列）のページ → 指定の版のページから、パッケージ（`jpfhir-terminology.r4-<版>.tgz`）をダウンロードする（大江先生が公開しているもの）
3. ダウンロードしたファイルを解凍し、各マスタのファイル（CodeSystemのjson）の中身から版（`version`）を確認する
4. 前月の版の回答と比べ、更新されたマスタを赤字にする
5. メール文案（版数の表つき）を作成 → 本田さんにRv依頼 → Rv完了後に芳原さんへ返信する
