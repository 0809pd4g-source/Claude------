## 1. 概要・背景

JLACセンターが毎月1日に電カル共有向けのJLACマスタ（JLAC10/JLAC11コード対応表）を提出する。厚労省側（ACN担当）が内容をチェックし、疑義があればJLACセンターへ連携・修正を経て、15日頃に正式公開する。

**公開までの流れ（毎月）：**

| 時期 | 担当 | 作業 |
|---|---|---|
| N-2月末 | JLACセンター | 付番委員会でコード採択 |
| N-1月第1・2週 | JLACセンター | JSMLのHPで公開するマスタの整備 |
| N-1月第3・4週 | JLACセンター | 電カル共有向けマスタ整備 |
| N月1日 | JLACセンター | 電カル共有向けマスタ提出 |
| N月第1週 | **厚労省（ACN）** | **提出されたマスタのチェック** ← 本手順 |
| N月第2週 | JLACセンター | チェック結果の確認・反映 |
| N月15日頃 | 厚労省 | 電カル共有向けマスタの一般公開 |

> 今年度（令和8年度）は自動化推進中。令和9年度では早期提供を目指す。

## 3. 月次チェック手順

### Step 0：全行にチェックロジック適用（重複検出のため）

- チェックロジック（KA-01〜KA-M3、39件）を全行に対してかける
- **目的**：コード重複・構造エラーを見落とさないため（既存行も含めて一括チェック）
- 結果を「作業Excel」に出力し、問題箇所にコメントを記入する

### Step 1：既存行の確認（前月との差分チェック）

- 新規追加でない行（前月マスタに存在する行）について：
  - **Step 0で大量エラーが出ても一旦無視**（既存行のエラーは既知のものが多い）
  - **前月マスタとの差分がないかを確認**する
- 差分がある場合の判断：

| 差分の種類 | 判断 |
|---|---|
| 適用終了日 `99999999` → 特定の日付に変更 | **問題なし**（マスタ更新で切り替えが生じるため） |
| 適用終了日の日付が不自然（遠い未来・1日等） | **要確認**（おおよそ15日前後が想定、1日等は要確認） |
| 適用終了日以外の変更 | **要確認**（誤作業の可能性） |
| 行の削除 | **指摘する**（削除は想定外のため） |
| 適用終了日のバックデート | **要確認**（詳細判断基準：後日確認） |

> **見直し前コードについて：** 6月に一気に見直しを実施。古いコードは適用終了日を設定して放置（削除しない）。

### Step 2：新規追加行の確認

- 新規追加行（前月マスタに存在しない行）について：
  - **Step 0のチェックロジック結果を全件確認する**（問題が潜在する可能性があるため無視しない）
  - 新規行の見つけ方：基本的にExcelの下部に追加される（メールも要確認）

### Step 3：JLACセンター向けコメント記載（毎月1日の初回提出分のみ）

- 疑義事項をJLACセンター向けにコメントとして作業Excelに記載する
- **本田さんRv後（10/7まで）** にJLACセンターへ疑義を連携する

### 最終化（CSV化）時の注意

- 「**並び順**」列のフィルターで**昇順**にしてからCSV化する

## 7. ダミーコード（「その他」のコード）の作り方（2026-10-07 本田さんKT）

- 「その他」に分類されるコードは、**既存のコードから作る**
- JLAC11の測定法コード（**13〜15桁**）が **000** のものは「その他」に分類される（JLAC10では **999**）
- 作り方：
  1. 既存のJLAC11コードの13〜15桁を **000** に置き換える
  2. 置き換えた結果から**重複を除いた一覧**を作り、「その他」のコード一覧とする
- このコードを**ダミーコード**という。**ダミーコード＝『その他の測定法』コード**（JLAC11の13〜15桁目が000のコード。用語集の表記は「その他の測定法」コード）。チェックロジックの KA-33・KA-34 と関係する
- 関連：日本衛生検査所協会打合せ（10/6）後の方針に「その他の測定法でマッピングすることであれば可能か」の検討がある

### 7-1. 作成ツールでの作り方

使うもの：`電子カルテ情報共有サービス対応JLACコード表作成ツール_20250127.xlsx` の「ダミーコード生成用」シート（本田さん共有）

1. 「★共有項目JLACコード(原本)」に、その月のマスタを**全件**貼り付ける
2. 「ダミーコード生成用」で次の行を除く
   - **AI列が `A` の行**（2回目以降に出てきた000コード）
   - **JLAC11コード（M列）が空の行**（000版を作れないため。ツールのままだと「000」だけの行が出る）
   - 本田さんメモの「AL列：A排除」は、AI列で `A` を除けば結果は同じ。ALだけで絞ると `AB` の行が残るので、**AI列で必ず絞る**
3. 残った行のAP〜BS列を**値で**貼り付け、000コードの一覧にする
4. **マスタにすでにある000コードと同じものを除く**（原本にもともと「その他」があるため。重複させない）
5. 適用終了日を確かめる：同じグループに有効な行（99999999）があるのに000コードに終了日が付いていたら `99999999` に直す（KA-34）

### 7-2. 各列の決まり方（ツールの式）

| 列 | 値 |
|---|---|
| JLAC11コード | 元のJLAC11コードの13〜15桁を000にしたもの（`LEFT(M,12)&"000"&RIGHT(M,2)`） |
| JLAC10コード | 元のJLAC10コードの13〜15桁を999にしたもの |
| 測定法(JLAC11)・検査方法(JLAC10-測定法) | 「その他の測定法」（固定） |
| 販売名称 | 空欄 |
| それ以外（名称・FHIR識別文字列・単位・並び順・適用開始日・適用終了日など） | 000にまとまる行のうち**いちばん上の行**の値を写す |

- 測定法だけが違う複数のコードは、1つの000コードにまとまる。例：`V2259000021200002` には「HIV-1+2抗体(定性)」と「HIV-1+2抗体・p24抗原(定性)」がまとまり、FHIR識別文字列は上にある「HIV-1+2抗体(定性)」になる。**この決め方でよい**（2026-10-07 ユーザー判断。9月公開版も同じ決め方になっている）
- 適用終了日もいちばん上の行の値が写るため、いちばん上の行が終了したコードだと000コードにも終了日が付く。10/6提出版のKA-34（3件・終了日20260812）はこの形

### 7-3. ⚠️ 32列のマスタ（表示用単位2・XML用単位2あり）で使うときの注意

| 問題 | 内容 | 対処 |
|---|---|---|

| 行が足りない | ツールの式は7,152行目まで | 10月版は13,531行。式を延ばす |

### 7-4. 9月公開版で確かめたこと（2026-10-07）

- 9月公開版の000コード1,179件を元の行と突き合わせた：名称・FHIR識別文字列など11項目は**いちばん上の行と一致**（材料(JLAC10)の3件だけ、同じグループの別の行と一致）
- JLAC10コード（999版）：同じ000コードにまとまる行でJLAC10コードが違うグループが129件あり、9月公開版では先頭行以外の行の999版を使っているものが36件、どの行の999版とも違うもの（JLAC10の付け替えの経緯と推測）が25件あった。新しく作るときに起きたらツールが要確認として示す
- 適用開始日：1,049件は元の行のうちいちばん早い開始日と同じ。128件は `00000000`（最初の版からある000コードで、元の行が後から変わっても開始日はそのまま）
- 9月に新しく作った3件（LDL-C、`C6011000025000056` ほか）は、元の行と同じ **20260915**。新しい組み合わせなら、元の行がその月の新しい行だけなので、いちばん上の行を写すと開始日はその月の15日になる（KA-M1を満たす）
