# JLACマスタ月次チェック 月次実行（1回実行）の使い方

> 作成日: 2026-10-15
> プロジェクト: JLACマスタ月次チェック（00_共通）
> 対象：Claude Code（または Node.js・Python・Excel のあるPC）で月次チェックを行う担当者。HTML版のツールだけを使う場合は、手順書（定常業務マニュアルのJLACマスタチェック手順 8章）を見る
> 設計：`02_output/_wip/20261009_月次チェック1回実行化_設計案_v1.md`。試験の記録：`02_output/_wip/20261015_1回実行化_試験結果_v1.md`

## 結論・要点

- 1コマンドで、設定の点検 → チェックツールでの判定（送付用・ACN確認用・報告・明細）→ ダブルチェック（Excelでの計算まで）→ 前月からの引継ぎの確認 → 「月次実行の結果.md」まで出る
- 毎月書くのは `YYYYMM提出分/04_reference/今月の設定.txt` の1ファイルだけ（スクリプトの書き換えは要らない）
- 判定はチェックツール（最新版HTMLの jlac-core）のまま。ツールv21から、指摘ごとの「判定の根拠」と「説明文の下書き」がACN確認用の「指摘の根拠」シートに出る
- 2026年11月分は、今のやり方（`run_check.mjs` に引数）と並行して流し、結果を突き合わせる（2026-10-09 ユーザー決定）

## 1. 準備（毎月）

1. `YYYYMM提出分/` を作り、`01_input/` に提出ファイル・前月公開版CSV・JLAC10/JLAC11コード表を置く（月次の `CLAUDE.md`「新しい月の始め方」）
2. `04_reference/今月の設定.txt` を作る。**前月の設定ファイルは見本として読むだけ**にし、値はその月のJLACセンターのメールから書き直す（見本：`202610提出分/04_reference/20261015_今月の設定_202610提出分_1006再提出.txt`）
3. 前月の月フォルダに「翌月への引継ぎ」があれば、`前月からの引継ぎ:` に指定する（11月分は `../202610提出分/04_reference/20261015_翌月への引継ぎ_202610提出分.txt` を `04_reference` にコピーして名前を書く）
4. **Excelをすべて閉じる**（ダブルチェックの計算でExcel本体を使うため。起動中だと計算を飛ばす）

## 2. 今月の設定.txt の書き方

「キー: 値」の形。`#` で始まる行は読まない。複数行の値は「キー: <<<」の次の行から「>>>」の行まで。ファイル名は `01_input`（17桁コードリストは `../20260930_JLACマスター新旧対応表確認/01_input` も）から探す。`.txt` で終わる値は `04_reference` からファイルの中身を読む。

| キー | 必須 | 中身 |
|---|---|---|
| 対象月 | 必須 | YYYYMM。月フォルダの名前と同じでないと止まる（前月の設定の流用を防ぐ） |
| 提出ファイル／前月公開版／JLAC10コード表／JLAC11コード表 | 必須 | ファイル名。同じ月に提出が2つあっても、どれを使うかがここに残る |
| 17桁コードリスト／17桁コードリストの取得日 | 任意 | 無いとKA-08を確認しない。取得日はYYYYMMDD |
| 提出日 | 必須 | YYYYMMDD。対象月と違うと止まる |
| 公開日 | 必須 | YYYYMMDD（通常はその月の15日）。15日以外なら「公開日が15日でない理由」が無いと止まる |
| 新規行の開始行 | メールにあれば必須 | メール本文に「行目」があるのに空なら止まる |
| JLACセンターの連絡（メール本文） | 推奨 | 本文を貼る（根拠の記録と、開始行の入れ忘れの点検に使う） |
| 連携メモ／連携済みの変更／Rv用の見解／別シートの理由 | 任意 | 今までの `04_reference/*.txt` をそのまま指定できる |
| 共有対象外のシート／削除行は依頼済み（はい・いいえ）／確認したいJLAC11コード | 任意 | 今月の個別対応 |
| 前月からの引継ぎ | 推奨 | 「JLAC11コード ｜ 期待する状態 ｜ メモ」の1行1件のファイル。状態は 含まれる／含まれない／有効な行がある／1行だけ／適用開始日 YYYYMMDD／適用終了日 YYYYMMDD／列なし 見出し名（コード欄は「（列）」） |
| ツールの版 | 任意 | 空か「最新」なら最新版。版を固定したいときはファイル名 |
| 判断の線引き／000コードの適用開始日／17桁コードリストの取り直し | 任意 | **本田さんの判断待ち。決まるまで「今のまま」（書かなければ今のまま）**。下の3章 |

## 3. 判断待ちの切り替え（本田さん未決定）

| キー | 今のまま（既定） | 切り替えると |
|---|---|---|
| 判断の線引き | 何も変えない | 「案」：ACN確認用の「指摘の根拠」に「判断の区分（案）」列を出す（重複・削除行・000コード・コメントがあるがロジックに当たるもの＝本田さんに上げる案、ほか＝通常どおり一次Rv）。判定・送付用は変わらない |
| 000コードの適用開始日 | 何も変えない | 「その月の15日」：今は記録のみ（1回実行では000コードの候補をまだ作っていない） |
| 17桁コードリストの取り直し | 取得日が空なら注意を出すだけ | 「毎月」：取得日が無い、または提出日の前月1日より古いと止まる |

## 4. 実行

```
powershell -ExecutionPolicy Bypass -File 00_共通\03_scripts\月次実行.ps1 -Month 202611提出分
```

- 任意の引数：`-Settings <設定ファイル>`（既定は `04_reference\今月の設定.txt`）、`-OutDir <出力先>`（既定は `02_output`。試しに流すときは別のフォルダにする）、`-SkipDoublecheck`、`-TimeoutMinutes 15`（Excelでの計算の上限）
- 設定に直すところがあると、`[止める]` の一覧を出して、**何も実行せずに**止まる（終了コード2）。直してからもう一度実行する
- 出力（`02_output`、名前は `YYYYMMDD_名称_vN`。同じ名前の最大の番号＋1を自動で付け、上書きしない）：送付用・ACN確認用・チェック結果報告・月次実行の明細（json）・ダブルチェック（xlsx）とその照合結果（json）・**月次実行の結果（md）**

## 5. 結果の読み方と、その後の作業

1. 「月次実行の結果.md」を上から読む。冒頭に、ダブルチェックが済んでいるか・不一致があるかが出る。**不一致があれば、検算式とツールのどちらが正しいかを原因まで調べ、それまで説明文を確定しない**
2. ACN確認用の「送付前確認事項_一次Rv」を整える。候補ごとに説明文の下書きの代表1件が入っている。全件は「指摘の根拠」シート（判定の材料から決まった型で作った下書き。そのまま確定した説明として使わない）
3. 結果mdの「前月からの引継ぎの確認」で未反映のものは、一次Rvに「残指摘〔前月の依頼から〕」として手で足す
4. 本田さんにRvを依頼する（見てほしいシート・見なくてよいシートを書く）
5. Rvを反映したら、送付用とACN確認用のコメントのずれを確かめる：`node 00_共通\03_scripts\monthly_run.mjs sync --send <送付用.xlsx> --acn <ACN確認用.xlsx>`（違う行を一覧にする。読み取りだけ）
6. `python _agent\_基盤\_ツール\送付前チェック.py <送付用.xlsx> --clean` で送付用を作って送る（PowerPoint・Word・Excelを閉じてから）
7. 送付を確定したら、翌月用の「翌月への引継ぎ」を `04_reference` に書く（削除・修正を依頼したコード、ACNで追加したコード）

## 6. Excelが起動中だったとき（ダブルチェックの計算を飛ばしたとき）

結果mdの冒頭に「ダブルチェックの照合が済んでいません」と出る。Excelをすべて閉じてから、次を順に流す（ファイル名は出力にあるもの）：

```
（ダブルチェックのxlsxをExcelで開き、数式を再計算〔Ctrl+Alt+F9〕して保存して閉じる）
python 00_共通\03_scripts\read_doublecheck.py <ダブルチェック.xlsx> <ダブルチェック.照合.json>
node 00_共通\03_scripts\monthly_run.mjs report --state <月次実行の明細.json> --dc <ダブルチェック.照合.json>
```

- report は新しい番号の「月次実行の結果.md」を書く（前の結果は上書きしない）

## 7. 困ったとき

- 「ファイルの役割」で止まる：設定に書いたファイルが、ツールの判定では別の種類（例：前月公開版に今月の提出ファイルを書いた）。ファイル名を見直す
- 前月の基準がxlsx（前月公開CSVでない）の月：ダブルチェックは自動で外れる（`make_doublecheck.py` は前月公開CSVの月だけに対応）
- ツールの判定を直したいとき：月次の `CLAUDE.md`「ロジック変更時」の手順。直したら `node 00_共通\03_scripts\test_monthly_run.mjs --json <明細.json>` と `selftest.mjs` も流す
- Node.js・Python・Excelが無いPC：HTML版のツール（手順書8章）を使う。ダブルチェック・引継ぎの確認はこの入口だけ

## やったこと・やっていないこと

- やったこと：入口（`月次実行.ps1`・`monthly_run.mjs`）、設定ファイルと点検、ツールv21の根拠と説明文の下書き、ダブルチェックの設定ファイル化（式は変えていない）、照合の読み取り、前月からの引継ぎの確認、送付用とACN確認用のずれの確認の使い方を書いた
- やっていないこと：000コードの候補づくりを入口に入れること、コメントの調整ファイル、二次Rvシートの自動引継ぎ、HTML版の画面での根拠の表示（設計案の後回し分）。Excel（COM）での計算は、試験の間Excelが起動していたため通しで確かめていない（試験結果の記録を参照）
