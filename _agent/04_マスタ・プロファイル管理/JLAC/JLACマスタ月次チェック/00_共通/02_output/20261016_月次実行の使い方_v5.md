# JLACマスタ月次チェック 月次実行（1回実行）の使い方

> 作成日: 2026-10-15（v2〜v5：2026-10-16）
> プロジェクト: JLACマスタ月次チェック（00_共通）
> 対象：Claude Code（または Node.js・Python・Excel のあるPC）で月次チェックを行う担当者。HTML版のツールだけを使う場合は、手順書（定常業務マニュアルのJLACマスタチェック手順 8章）を見る
> 設計：`02_output/_wip/20261009_月次チェック1回実行化_設計案_v1.md`。試験の記録：`02_output/_wip/20261016_1回実行化_試験結果_v2.md`

## 結論・要点

- 1コマンドで、設定の点検 → チェックツールでの判定（送付用・ACN確認用・報告・明細）→ 既知の指摘の仕様確認資料 → ダブルチェック（Excelでの計算まで）→ 前月からの引継ぎの確認 → 「月次実行の結果.md」まで出る
- 毎月書くのは `YYYYMM提出分/04_reference/今月の設定.txt` の1ファイルだけ（スクリプトの書き換えは要らない）
- 判定はチェックツール（最新版HTMLの jlac-core）のまま。ツールv21から、指摘ごとの「判定の根拠」と「説明文の下書き」がACN確認用の「指摘の根拠」シートに出る
- 2026年11月分は、今のやり方（`run_check.mjs` に引数）と並行して流し、結果を突き合わせる（2026-10-09 ユーザー決定）

## 1. 準備（毎月）

1. `YYYYMM提出分/` を作り、`01_input/` に提出ファイル・前月公開版CSV・JLAC10/JLAC11コード表を置く（月次の `CLAUDE.md`「新しい月の始め方」）
2. `04_reference/今月の設定.txt` を作る。**前月の設定ファイルは見本として読むだけ**にし、値はその月のJLACセンターのメールから書き直す（見本：`202610提出分/04_reference/20261015_今月の設定_202610提出分_1006再提出.txt`）
3. 前月の月フォルダに「翌月への引継ぎ」があれば、`前月からの引継ぎ:` に指定する（11月分は `../202610提出分/04_reference/20261016_翌月への引継ぎ_202610提出分.txt`（HIVの000コード3件の適用開始日を8月更新の20260813にした版。20261015_の版は使わない） を `04_reference` にコピーして名前を書く）
4. **Excelをすべて閉じる**（ダブルチェックの計算でExcel本体を使うため。起動中だと計算を飛ばす）

## 2. 今月の設定.txt の書き方

「キー: 値」の形。`#` で始まる行は読まない。複数行の値は「キー: <<<」の次の行から「>>>」の行まで（「>>>」を書き忘れると止まる）。ファイル名は `01_input`（17桁コードリストは `../20260930_JLACマスター新旧対応表確認/01_input` も）から探す。`.txt` で終わる値は `04_reference` からファイルの中身を読む。

| キー | 必須 | 中身 |
|---|---|---|
| 対象月 | 必須 | YYYYMM。月フォルダの名前と同じでないと止まる（前月の設定の流用を防ぐ） |
| 提出ファイル／前月公開版／JLAC10コード表／JLAC11コード表 | 必須 | ファイル名。同じ月に提出が2つあっても、どれを使うかがここに残る。前月公開版の名前に前月のYYYYMM（例：11月分なら「202610」）が無いと「注意」が出る |
| 17桁コードリスト／17桁コードリストの取得日 | 任意 | 無いとKA-08を確認しない。取得日はYYYYMMDD |
| 提出日 | 必須 | YYYYMMDD。対象月と違うと止まる |
| 公開日 | 必須 | YYYYMMDD（通常はその月の15日）。15日以外なら「公開日が15日でない理由」が無いと止まる |
| 新規行の開始行 | メールにあれば必須 | メール本文に「行目」があるのに空なら止まる |
| JLACセンターの連絡（メール本文） | 推奨 | 本文を貼る（根拠の記録と、開始行の入れ忘れの点検に使う） |
| 連携メモ／連携済みの変更／Rv用の見解／別シートの理由 | 任意 | 今までの `04_reference/*.txt` をそのまま指定できる |
| 共有対象外のシート／削除行は依頼済み（はい・いいえ）／確認したいJLAC11コード | 任意 | 今月の個別対応 |
| 前月からの引継ぎ | 推奨 | 「JLAC11コード ｜ 期待する状態 ｜ メモ」の1行1件のファイル。状態は 含まれる／含まれない／有効な行がある（適用終了日99999999の行がある。旧い行が残っているコードの追加・000コードはこれで書く）／1行だけ／適用開始日 YYYYMMDD／適用終了日 YYYYMMDD／列なし 見出し名（コード欄は「（列）」） |
| 血液型の期待／血液型の行 | 任意 | 血液型（ABO・Rh）の38行の状態（全行あり／全行なし／一部だけ）を毎月、結果mdに情報として出す。2027年1月〜3月末に使われる版から外す予定で、**どの版から外し、どの版で戻すかは調整中（個人の残論点.md K009）**。決まったら「血液型の期待: 202701提出分=外す, 202704提出分=残す」のように書く（書いた月だけ、期待と違えば⚠️）。書いていない月は「一部だけ」（一部の行だけが欠けた・終了した）のときだけ⚠️。行はJLAC11コードの測定物（5桁）で、既定は「K1001,K1006」（ABO 16行・Rh 22行） |
| ツールの版 | 任意 | 空か「最新」なら最新版。版を固定したいときはファイル名 |
| 判断の線引き／000コードの適用開始日／17桁コードリストの取り直し | 任意 | **本田さんの判断待ち。決まるまで「今のまま」（書かなければ今のまま）**。下の3章 |

## 3. 判断待ちの切り替え（本田さん未決定）

| キー | 今のまま（既定） | 切り替えると |
|---|---|---|
| 判断の線引き | 何も変えない | 「案」：ACN確認用の「指摘の根拠」に「判断の区分（案）」列を出す（重複・削除行・000コード・コメントがあるがロジックに当たるもの＝本田さんに上げる案、ほか＝通常どおり一次Rv）。判定・送付用は変わらない |
| 000コードの適用開始日 | 何も変えない | 「その月の15日」：今は記録のみ（1回実行では000コードの候補をまだ作っていない） |
| 17桁コードリストの取り直し | 取得日が空なら注意を出すだけ | 「毎月」：取得日が無い、または提出日の前月1日より古いと止まる（前月1日ちょうどは通る） |

## 4. 実行

**実行するフォルダ**：`JLACマスタ月次チェック/`（このフォルダの1つ上。`00_共通` と `YYYYMM提出分` が並んでいるところ）。PowerShell で `cd` してから次を流す。

```
powershell -ExecutionPolicy Bypass -File 00_共通\03_scripts\月次実行.ps1 -Month 202611提出分
```

- 任意の引数：`-Settings <設定ファイル>`（既定は `04_reference\今月の設定.txt`）、`-OutDir <出力先>`（既定は `02_output`）、`-SkipDoublecheck`、`-TimeoutMinutes 15`（Excelでの計算の上限）
- **実行中はExcelを開かない**（計算はこの処理が起動した画面の無いExcelで行う。時間切れのときは、そのExcelだけを止める）
- 出力（名前は `YYYYMMDD_名称_vN`。同じ名前の最大の番号＋1を自動で付け、上書きしない）：送付用・ACN確認用・チェック結果報告・月次実行の明細（json）・**既知の指摘の仕様確認（xlsx）**・ダブルチェック（xlsx）とその照合結果（json）・**月次実行の結果（md）**

### 4-1. 終了コード（止まったときの読み方）

| 終了コード | 意味 | すること |
|---|---|---|
| 0 | 最後まで流れた | 「月次実行の結果.md」を読む（ダブルチェックを飛ばした場合も0。結果mdの冒頭に理由が出る） |
| 2 | 設定の点検で止まった。**何も実行していない** | 画面の `[止める]` を直して流し直す |
| 1 | ツールの実行、または結果のまとめでエラー | 画面の最後の数行（エラーの文）を、月次実行の明細・設定ファイルと一緒に管理者（Claude Code）に渡す。出力の一部ができていることがあるが、使わずに流し直す（番号は自動で次に進む） |

### 4-2. 2026年11月の並行運用（今のやり方と突き合わせる）

並行のあいだは、**1回実行の出力を `02_output` 以外に出す**。旧来の `run_check.mjs` は、指定した名前のファイルがあっても確かめずに上書きするため、同じフォルダに出すと片方を消してしまうことがある。

```
powershell -ExecutionPolicy Bypass -File 00_共通\03_scripts\月次実行.ps1 -Month 202611提出分 -OutDir 202611提出分\02_output\_wip\月次実行
```

今のやり方（`run_check.mjs` に `--json <明細.json>` も付けて流す）と、次で比べる。いずれも「FAIL 0」なら一致。

```
# 送付用・指摘明細・通知・コメント（json は旧来の --json の出力と、1回実行の「月次実行の明細」）
python 00_共通\03_scripts\compare_outputs.py <旧の送付用.xlsx> <新の送付用.xlsx> <旧の明細.json> <新の月次実行の明細.json>
# ACN確認用（v21で足した・変えた3シートを外し、版番号と作成日の表記だけをそろえる）
python 00_共通\03_scripts\compare_outputs.py <旧のACN確認用.xlsx> <新のACN確認用.xlsx> --skip "指摘の根拠|このファイルの説明|送付前確認事項_一次Rv" --replace "v20=v21|確認事項一覧_<旧の実行日>=確認事項一覧_<新の実行日>"
```

- `--skip` と `--replace` は「|」（半角の縦棒）で区切って複数書く。`--replace` は「旧=新」で、**版番号の表記（v20=v21）と実行日（送付用の名前に入る日付）だけに使う**。それ以外を置き換えると、違いを隠してしまう
- 旧も新もツールv21で流した場合は `--replace` は要らない（作成日だけが違えば、その分だけ書く）
- 「送付前確認事項_一次Rv」は、v21で候補ごとに説明文の下書きの代表1件が足されるため、上の比較では外している。下書きを除いて同じかを見るときは、管理者に頼む（試験では `【説明文の下書き（代表1件…】` の段落を消して比べた）

### 4-3. 根拠の試験（ツールを直したとき）

`node 00_共通\03_scripts\test_monthly_run.mjs --json <10/6再提出分の月次実行の明細.json> --json2 <10/1提出版の月次実行の明細.json>`。明細jsonは、`202610提出分/04_reference` の2つの設定（`20261015_今月の設定_202610提出分_1006再提出.txt`・`…_1001提出.txt`）で `node 00_共通\03_scripts\monthly_run.mjs run --month 202610提出分 --settings <設定> --out <一時フォルダ>` を流すと、一時フォルダにできる（`202610提出分/02_output` には出さない）。

## 5. 結果の読み方と、その後の作業

1. 「月次実行の結果.md」を上から読む。冒頭に、ダブルチェックが済んでいるか・不一致があるか・比較できる項目が10月分（54項目）より減っていないかが出る。**不一致があれば、検算式とツールのどちらが正しいかを原因まで調べ、それまで説明文を確定しない**
2. 結果mdの冒頭に「⚠️ 血液型（ABO・Rh）の行を本田さんに上げる」が出たら、本田さんへの確認事項として一次Rvに足す（一部の行だけが欠けた・終了した、または設定した期待〔残す・外す〕と違う）。「全行あり」「全行なし」は、外す版・戻す版が調整中のあいだはどちらもありうるため、3章の情報を見るだけでよい
3. ACN確認用の「送付前確認事項_一次Rv」を整える。候補ごとに説明文の下書きの代表1件が入っている。全件は「指摘の根拠」シート（判定の材料から決まった型で作った下書き。そのまま確定した説明として使わない）
4. 結果mdの「前月からの引継ぎの確認」で未反映のものは、一次Rvに「残指摘〔前月の依頼から〕」として手で足す
5. 本田さんにRvを依頼する（見てほしいシート・見なくてよいシートを書く）。あわせて「既知の指摘の仕様確認」（`make_known_review.py` の出力。既知としてコメントしなかった指摘を論点ごとにまとめたもの）で、仕様か誤りかの判断を依頼する。対象は使用中の行と、今月終了した行・内容が変わった行（前月も同じ内容で終了済みの行だけ外す）。前月に判断済みの論点と変わっていなければ、変わった点だけ伝えればよい
6. Rvを反映したら、送付用とACN確認用のコメントのずれを確かめる：`node 00_共通\03_scripts\monthly_run.mjs sync --send <送付用.xlsx> --acn <ACN確認用.xlsx>`（違う行を一覧にする。読み取りだけ）
7. `python _agent\_基盤\_ツール\送付前チェック.py <送付用.xlsx> --clean` で送付用を作って送る（PowerPoint・Word・Excelを閉じてから）
8. 送付を確定したら、翌月用の「翌月への引継ぎ」を `04_reference` に書く（削除・修正を依頼したコード、ACNで追加したコード）

## 6. Excelが起動中だったとき（ダブルチェックの計算を飛ばしたとき）

結果mdの冒頭に「ダブルチェックの照合が済んでいません」と出る。Excelをすべて閉じてから、次を順に流す（ファイル名は出力にあるもの）：

```
（ダブルチェックのxlsxをExcelで開き、数式を再計算〔Ctrl+Alt+F9〕して保存して閉じる）
python 00_共通\03_scripts\read_doublecheck.py <ダブルチェック.xlsx> <ダブルチェック.照合.json>
node 00_共通\03_scripts\monthly_run.mjs report --state <月次実行の明細.json> --dc <ダブルチェック.照合.json>
```

- report は新しい番号の「月次実行の結果.md」を書く（前の結果は上書きしない）

## 7. 困ったとき

- 「ファイルの役割」で止まる：設定に書いたファイルが、ツールの判定では別の種類（例：前月公開版に今月の提出ファイルを書いた）。ファイル名を見直す
- 前月の基準がxlsx（前月公開CSVでない）の月：ダブルチェックは自動で外れる（`make_doublecheck.py` は前月公開CSVの月だけに対応）
- ツールの判定を直したいとき：月次の `CLAUDE.md`「ロジック変更時」の手順。直したら `node 00_共通\03_scripts\test_monthly_run.mjs --json <明細.json>` と `selftest.mjs` も流す
- Node.js・Python・Excelが無いPC：HTML版のツール（手順書8章）を使う。ダブルチェック・引継ぎの確認はこの入口だけ

- やったこと（v4）：血液型（ABO・Rh）の行の確認（設定のキー2つ・結果mdでの表示・本田さんに上げる扱い）と、引継ぎファイルの参照先（20261016_の版）を足した
- やったこと（v3）：入口に「①-2 既知の指摘の仕様確認資料」（`make_known_review.py`）を足し、出力と5章の作業（本田さんへの依頼）に書き足した（2026-10-16 ユーザー依頼）
