# 作業前提：プロジェクト管理規約

このプロジェクトは共通の管理規約に従う。作業開始時にこの前提を読み込むこと。詳細は同梱の `README_プロジェクト管理規約.md`。

## フォルダ・命名
- 直下に `01_input`（原本・改変しない）／`02_output`／`03_scripts`／`04_reference`（任意）＋ `プロジェクト状況.md` ＋ `更新履歴.md`
- 成果物ファイル＝ `YYYYMMDD_名称_vN.拡張子`。改訂ごとに vN を +1、旧版は削除せず残す

## 管理文書の更新（重要・既定運用）
- **成果物を新規作成・改訂したら、明示指示がなくても同じ作業の中で必ず両方を更新する：**
  - `更新履歴.md`：版の行を追加し、最新版を **太字＋（最新）** に
  - `プロジェクト状況.md`：成果物・変更履歴（必要なら未確認事項）
- セッション開始時は、既存プロジェクトなら両文書を読んでから最新版の続きに入る

## 記述原則
出典・根拠を明記／事実と推論を区別／未確認事項を隠さない／成果物末尾に「やったこと・やっていないこと」／日付は絶対日付で記載

## フォルダ構成（2026-10-06〜）
JLACマスタの確認は毎月発生するため、毎月使うものと月ごとのものを分けている。
```
JLACマスタ月次チェック/
├── CLAUDE.md（このファイル：実行手順・ロジック管理ルール）
├── 00_共通/
│   ├── 02_output/  チェックツール_vN.html（ロジックの正本）、チェックロジック改善提案_vN.md
│   ├── 03_scripts/ run_check.mjs、selftest.mjs、make_doublecheck.py、compare_outputs.py ほか
│   └── 更新履歴.md・プロジェクト状況.md（ツールの版・改修の経緯）
└── YYYYMM提出分/（例：202610提出分）
    ├── 01_input/  今月の提出ファイル、前月公開版CSV、コード表
    ├── 02_output/ 確認事項一覧（送付用・ACN確認用）、チェック結果報告、ダブルチェック
    ├── 04_reference/ 今月の個別対応メモ・Rv用見解・別シートの理由・連携済みの変更
    └── 更新履歴.md・プロジェクト状況.md
```
- **新しい月の始め方**：`YYYYMM提出分/` を作り（01_input・02_output・04_reference と管理文書2点）、提出ファイル・前月公開版CSV・コード表を01_inputに置く。前月の04_referenceの設定ファイルは、今月の内容に書き換えて作る（前月の値をそのまま流用しない）
- 業務としての月次フロー（KT内容・インプットのダウンロード先等）は定常業務マニュアル側の `20261001_JLACマスタチェック手順_v1.md`（`_agent/01_定常業務/20260831_電カル調査研究_定常業務マニュアル/02_output/`）
- 成果物の命名は従来どおり `YYYYMMDD_名称_vN.拡張子`。17桁コードリストは `../20260930_JLACマスター新旧対応表確認/01_input/` にある

## このプロジェクト固有：JLACマスタチェックの実行とロジック管理
- ロジックの正本は `00_共通/02_output/` の最新版 `*_JLACマスタチェックツール_vN.html` 内の `<script id="jlac-core">` だけ。チーム（ブラウザ）とここ（Node.js）で同じコードを使う。ロジックを別の場所に書き写さない。
- チェック依頼を受けたら：入力Excelを `YYYYMM提出分/01_input/` に置き、`node 00_共通/03_scripts/run_check.mjs --xlsx <送付用xlsx> --internal <ACN確認用xlsx> --md <報告> [--newrow <JLACセンター連絡の新規開始行>] [--notes/--sheetreason/--shared/--memo/--watch …] <入力xlsx…>` で実行する（出力先は `YYYYMM提出分/02_output/`、出力名は `YYYYMMDD_JLACマスタ確認事項一覧_[ACN確認用_]JLACセンターYYYYMMDD提出版_vN.xlsx`）。改善案はロジックに入れず `*_チェックロジック改善提案_vN.md` に追記する（ロジックは関係者合意済みのため勝手に変えない）（17桁コードリストは `../20260930_JLACマスター新旧対応表確認/01_input/` にもある）。
- ロジック変更時：ツールを vN+1 にコピー → jlac-core を差分編集 → `VERSION`・`CHANGELOG` を更新 → `node 00_共通/03_scripts/selftest.mjs [--month YYYYMM提出分]` → 旧版・新版に同じ入力を流して `python 00_共通/03_scripts/compare_outputs.py` で差分が意図どおりか確認 → `html_checker.py` → ブラウザ確認（launch.json「JLACマスタチェックツール」）。
- 出力Excelは Excel本体で開けること（修復ログが出ないこと）を確認してから渡す。openpyxlで原本ブックを丸ごと保存しない（外部データ接続が欠落して修復を求められる）。
- 確認結果のダブルチェック：`python 00_共通/03_scripts/make_doublecheck.py <ACN確認用xlsx> <出力xlsx> [YYYYMM提出分]` で作り、Excel本体（COM）で全数式を計算・保存してから「照合」シートの不一致を確認する（入力ファイル名・新規開始行・公開日はスクリプト冒頭で毎月差し替え）。不一致は検算式とツールのどちらが正しいか必ず原因まで調べる。
- `check_jlac_monthly.py`・`selftest_check_jlac_monthly.py` は凍結した参照実装（更新しない。2026-10-06のフォルダ再編後はパスが合わず、そのままでは動かない）。
