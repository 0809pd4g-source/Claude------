# 作業前提：プロジェクト管理規約

このプロジェクトは共通の管理規約に従う。作業開始時にこの前提を読み込むこと。詳細は同梱の `README_プロジェクト管理規約.md`。

## フォルダ・命名
- 直下に `01_input`（原本・改変しない）／`02_output`／`03_scripts`／`04_reference`（任意）＋ `プロジェクト状況.md` ＋ `更新履歴.md`
- 成果物ファイル＝ `YYYYMMDD_名称_vN.拡張子`。改訂ごとに vN を +1、旧版は削除せず残す

## 管理文書の更新（重要・既定運用）
- **成果物を新規作成・改訂したら、明示指示がなくても同じ作業の中で必ず両方を更新する：**
  - `更新履歴.md`：版の行を追加し、最新版を **太字＋（最新）** に
  - `プロジェクト状況.md`：成果物・変更履歴（必要なら未確認事項）
- セッション開始時は、既存プロジェクトなら両文書を読んでから最新版の続きに入る

## 記述原則
出典・根拠を明記／事実と推論を区別／未確認事項を隠さない／成果物末尾に「やったこと・やっていないこと」／日付は絶対日付で記載

## このプロジェクト固有：JLACマスタチェックの実行とロジック管理
- ロジックの正本は `02_output/` の最新版 `*_JLACマスタチェックツール_vN.html` 内の `<script id="jlac-core">` だけ。チーム（ブラウザ）とここ（Node.js）で同じコードを使う。ロジックを別の場所に書き写さない。
- チェック依頼を受けたら：入力Excelを `01_input/` に置き、`node 03_scripts/run_check.mjs --xlsx <送付用xlsx> --internal <ACN確認用xlsx> --md <報告> [--newrow <JLACセンター連絡の新規開始行>] <入力xlsx…>` で実行する（出力名は `02_output/YYYYMMDD_JLACマスタ確認事項一覧_[ACN確認用_]JLACセンターYYYYMMDD提出版_vN.xlsx`）。改善案はロジックに入れず `*_チェックロジック改善提案_vN.md` に追記する（ロジックは関係者合意済みのため勝手に変えない）（17桁コードリストは `../20260930_JLACマスター新旧対応表確認/01_input/` にもある）。
- ロジック変更時：ツールを vN+1 にコピー → jlac-core を差分編集 → `VERSION`・`CHANGELOG` を更新 → `node 03_scripts/selftest.mjs` → 旧版・新版に同じ入力を流して `python 03_scripts/compare_outputs.py` で差分が意図どおりか確認 → `html_checker.py` → ブラウザ確認（launch.json「JLACマスタチェックツール」）。
- 出力Excelは Excel本体で開けること（修復ログが出ないこと）を確認してから渡す。openpyxlで原本ブックを丸ごと保存しない（外部データ接続が欠落して修復を求められる）。
- 確認結果のダブルチェック：`python 03_scripts/make_doublecheck.py <ACN確認用xlsx> <出力xlsx>` で作り、Excel本体（COM）で全数式を計算・保存してから「照合」シートの不一致を確認する（入力ファイル名・新規開始行・公開日はスクリプト冒頭で毎月差し替え）。不一致は検算式とツールのどちらが正しいか必ず原因まで調べる。
- `check_jlac_monthly.py`・`selftest_check_jlac_monthly.py` は凍結した参照実装（更新しない）。
