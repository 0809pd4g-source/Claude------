# 成果物フォーマット選定ガイド

作成依頼を受けたら、**「とりあえずHTML」に決め打ちしない**。目的・利用者から**出力形式を先に選ぶ**。「HTMLで作ったが、普通のテキストの方が見やすかった」という手戻りを防ぐための型。

---

## 迷ったら（早見表）

| こういうとき | おすすめ形式 |
|---|---|
| 読むだけ・軽く共有・あとで編集する | **Markdown(.md) / プレーンテキスト** |
| 見せる・触らせる・可視化・単一ファイルで配布 | **単一HTML** |
| 体裁を固定して配布・印刷・提出（改変されたくない） | **PDF**（または docx→PDF） |
| 表・計算・フィルタ・集計 | **スプレッドシート(.xlsx / .csv)** |
| 口頭で提示・スライド | **PowerPoint(.pptx)** |
| 相手が Word で編集・回覧する文書 | **Word(.docx)** |

ひとことで：**読むだけ→MD／見せる・触らせる→HTML／配る・固定→PDF／数える→表計算／話す→スライド／相手が編集→Word**。

---

## 目的別の目安（詳しめ）

| 目的・使い方 | 形式 | 理由 |
|---|---|---|
| メモ・下書き・手順書・仕様の素・台帳の中身・議事 | MD / テキスト | 軽い・差分が見やすい・どこでも開ける・検索が楽 |
| ダッシュボード／ポータル／可視化／説明サイト（タブ・検索・図・ダーク・単一配布） | 単一HTML | 自己完結・オフライン・インタラクティブ |
| 正式な報告書・提出物・印刷（レイアウト厳密） | PDF（or docx→PDF） | 体裁固定・改変防止 |
| 数値の整理・集計・並べ替え | xlsx / csv | 計算・フィルタ・ピボット |
| 会議・プレゼン | pptx | スライド提示 |
| 相手が手を入れる文書 | docx | 編集・回覧しやすい |

---

## コツ：中身ファースト → 形式は後から展開できる

- 迷ったら**まず Markdown で中身を固める**。MD は HTML / PDF / docx へ変換しやすい。
- 「見せ方」が必要になった段階で **HTML化**、「配布・提出」が必要になった段階で **PDF化**。
- 逆（いきなりHTMLで作り込む → やっぱりテキストが良かった）は手戻りが大きい。
- 同じ内容を複数形式で持つのは正当（例：技術解説書の **MD版** と **HTML統合ポータル**は用途が違う別成果物）。

---

## Claude Code は各形式を作れる

- **docx / pdf / pptx / xlsx** はそれぞれ専用スキルで生成可能。**MD / HTML** はそのまま作成。
- なので「形式は目的で選ぶ → Claudeがその形式で作る」でよい。

---

- 作成依頼を受けたら、Claudeが **目的・利用者から形式を1つ提案＋一言の理由** を述べて確認してから着手する。
  - 例：「参照用の仕様なので、まず **MD** で作ります。見せ方が要るなら **HTML** 化します」
- 形式が決まったら、HTMLの場合は `_agent/_基盤/_ツール/HTML作成ガイド.md`（キックオフ4問＋作業ルールA〜I）に従う。
