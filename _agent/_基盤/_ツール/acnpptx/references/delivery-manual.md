# デリバリーマニュアルの作法（デッキ生成に効くもの）

アクセンチュアのデリバリーマニュアル（仮説論点設計・サマリストーリー・ワークプラン・リサーチ・スライドライティング・プレゼンディスカッション・戦略思考・財務・ロジ）から、AI がデッキを作るときに守る作法だけを抜き出した。数値基準はマニュアルに書かれたもの。検査に落としたものは規則 ID を付けた。

## 1. 作る順番（いきなりスライドにしない）

1. **サマリ**（テキスト）: 問い（SCQ）＋本日伝えたいこと（主張＋最低限の論拠）。会議・提案のゴールは「XXX を YYY していただく」と**動詞で**書く（例「PoC 予算の確保をご判断いただく」）
2. **ストーリー**: サマリの各命題の **1〜2 階層下**に論拠・根拠を付けたテキスト。上下は So What?（上へ）／Why So?（下へ）でつなぐ。未確定の数値は「XXX」で穴を空けておき、リサーチでその穴を埋める
3. **スケルトン**: ストーリーの各命題をスライドのタイトル・メッセージに写す（Step 3a）。**ロジックツリーの上の階層のスライドから作る**（要旨・キースライドが先、詳細は後）
4. 参考情報（専門家コメント・海外事例・内訳）はメッセージの直下ではなく、それを支えるファクトの下に置く → 参考スライド・Appendix

**本編と Appendix の振り分け**: 論証に不要 → 削除／必要だが自明 → Appendix／必要だが時間内に話せない → Appendix／必要で、論証が求められ、話せる → 本編

## 2. 冒頭と並べ方

- **SCQA**: Situation は誰もが合意できる事実だけ（「商品 A は売上の 80%」は可、「当社の強みはマーケティング力」は不可）。Complication は問いの引き金になる変化だけ。Question は相手の権限に合わせる（社長＝全社・企業価値、役員＝部門機能、部長＝部門 KPI）
- **並べ方を読み手で変える**: 判断する人（CXO）には**結論ファースト**（前提は最小、試算の詳細は参考スライドへ）。検証の妥当性を見る現場や、初めての相手には**積み上げ型**（プロセスを丁寧に、最後に結論）
- 提案・報告の型（論点の種類 → 典型の図）
  - 新規事業: Where to play（プロフィットプール・比較表）→ How to win（ビジネスモデル図・バリューチェーン・業務フロー・アーキテクチャ）→ ROI（コスト構成・ウォーターフォール・ビジネスケース・累積 FCF）→ ネクストアクション（ロードマップ・体制）
  - 機能戦略・実行支援: 問題の特定（ツリー・パレート・因果ループ）→ 改革方法（業務フロー・体制・As-Is/To-Be）→ ROI → ネクストアクション
- 反論を先回りするページを入れる: 「需要はあるのか」→ 調査結果（N 数を書く）／「儲かるのか」→ アグレッシブ版とコンサバ版の 2 案／「お金がない」→ 小さく始める場合の投資額／「急ぐ理由は」→ 競合動向から見た期限／「イメージが湧かない」→ 他社事例・業務フロー
- 末尾: 合意したいこと・ご判断いただきたいこと → 次のステップ（**誰が（名前）・いつまでに・何を**）

## 3. 論点と打ち手の質

- 「仮説が立った」＝ 問題・課題・打ち手を（間違っていてもよいので）一通り説明できる状態。価値基準 → 問題 → 発生のしくみ → 課題（介入点） → 解消された状態 → 打ち手の計画、の鎖で書く
- **ダメな打ち手**: ①問題の裏返し（「シェアが低い」→「シェアを上げる」）②根本原因に届かない ③副作用を考えていない
- 論点ツリー: 横は MECE（対立・分割・数値・因数分解・段階・時間の切り口か、3C・4P・5 フォース・バリューチェーンなど）。縦は**一次データで検証できる粒度**まで割る（「市場は魅力的か？」で止めない）
- 戦略の提言は 3 つの基本戦略（コストリーダーシップ・差別化・集中）のどれかを明示し、差別化なら**捨てる機能**まで書く。どこにも属さない提言（スタック・イン・ザ・ミドル）にしない。シナリオはベース・リスク・楽観の 3 本で、リスクには影響額と対策

## 4. メッセージ（リード）

- **解釈を必ず含める**: 「以下の通り」は書いていないのと同じ。良い・多い／悪い・少ない／最小でも〜／最大でも〜 のどれかで言い切る
- 前提 → 事象 → 結論の三段で組む（「〜を踏まえても〜は大きく、〜すべき」「〜だけでは不十分で、〜により年 xx 億円の可能性」）
- 数字は**比較の基準と対象の両方**を入れる（「通常 15% の管理工数が、X 社では 30% を超える」）
- 3 行以上は禁止。2 文にするなら「結論＋その手段・数字」の関係がはっきりしているときだけ
- **構成の説明を書かない**（「左に〜、右に〜を記載」「下表の通り」）→ MSG-15。見方の説明が要るスライドはボディの構造がおかしい
- **改行を入れない**（枠の幅で自然に折り返す）→ MSG-14
- 跳ねる表現は言い換える: 「合意した」→「おおむね認識を合わせた」／「〜していなかった」→「十分ではなかった」／「劣っている」→「伸びしろがある」。なじみの無い横文字は日本語にする
- タイトル・メッセージ・ボディ（パネル名）が食い違うなら、論理が破綻している。ボディから言い切れないメッセージはファクトが足りない

## 5. ボディとパネル

- 1 スライド 1 メッセージ。並列の複数メッセージや、メッセージとそのファクト（階層違い）を 1 枚に混ぜない
- 視線は左上 → 右下。展開は縦か横の一方向
- チャートだけで論証が閉じないときに限りパネルを足す: **前提**（左 1/3）／**処理の過程**（右 1/3）／**結果・解釈**（右 1/3）。「定量チャート＋解釈＋ネクストステップ」の 3 段は情報過多
- 上下のつながり: サマリ・観点整理のページの番号（❶❷・Ⓐ〜Ⓓ）を詳細ページのタイトルや見出しで引用する（「【Ⓐ 人員最小化｜各社の人件費比較】」）。対比・並列のページは同じタイトルの付け方・同じボディの構成にし、差分だけ強調する
- スライドのラベル: 「再掲」「初期的仮説」「初期的試算」「MM/DD 討議を踏まえ更新」「他社事例」「[補足]」は、タイトル脇かパンくずに小さく付ける（「イメージ」の札とは別。札は成果物・画面の見本だけ）

## 6. 表・チャート・数字

- 表: 列名を必ず付け、**一列一意**（同じ列には同じ種類の中身）。「概要・内容・備考・その他・イメージ」のような曖昧な列名にしない → TBL-01。**数字は右揃え・文字は左揃え・区分の見出しは中央**
- 数字: 4 桁以上は**桁区切り**（1,089・10,260万円）→ NUM-01。英数字は半角、カタカナは全角でデッキ内を統一
- 単位は軸・列見出し・グラフタイトルに書く（「（億円/年）」「（単位: 百万円）」）
- 図解の型（定性）: ツリー（分解・KPI）／ステップ（バリューチェーン・アプローチ）／因果ループ／評価テーブル／マトリクス（独立な 2 軸。象限の移動を語れる）／ロードマップ／業務フロー／分岐図（判断基準を明記）／ビジネスモデル図（モノ・金・サービスの流れ）／組織図／レイヤー（業界構造）
- 定量チャート: 要素の比較 → **横棒**（並べ順は降順か前ページの分類順。時間軸を置かない）／時系列 → **縦棒**（横軸がシーケンシャルなときだけ）／構成 → 積み上げ棒／**施策による変化の分解だけウォーターフォール**（下向きしか無いなら単なる分解なので積み上げ棒）／傾向 → 折れ線（具体的な値を示すならマーカー）
- 全チャート: **縦軸は 0 始まり**・単位を書く・目盛り線と数値ラベルを重ねない・複数のチャートを合体させた独自チャートを作らない・出典必須
- **実績と予測を描き分ける**（実績は塗り、予測は破線枠など）。「2026 年以降は予測値」と注記する

## 7. リサーチと出典

- 先に骨子（サブ論点ごとの回答サマリ、未確定は XXX）を書き、穴を埋める順に調べる
- **仮説を支持する情報と棄却する情報の両方を調べる**（「急成長」→ 市場全体が伸びているだけでは？ もっと強い競合はいないか？）
- 主要な数値は 2 つ以上の機関で確かめる。1 機関だけなら「単一機関の推計」と書く。将来予測は 1 社のレポートをそのまま結論にしない（過去の予測は実績から大きく外れることが多い）
- 発信者から情報源を当てる: 政府（会議体の議事録）／当事者企業（自社 HP・プレスリリース）／コンサル・仲介（事例）／メディア。企業の本音は中計より M&A・組織再編・採用ページに出る
- **鮮度と日付**: 作成日（今日）を確かめ、題材の製品・機能・制度の**提供開始日・版・料金を一次情報で調べて** outline の `as_of` / `anchors` に書く。実績・事例はその開始日以降かつ作成日以前、スケジュールは作成日以降にする（DATE-01〜03）。記事の公開日も `sources[].published` に残し、古い情報を最新として書かない
- 出典は第三者が辿れる粒度で: 「出典: 日経ビッグデータ 2019 年 6 月号 P.10 よりアクセンチュア整理」（「日経ビッグデータよりアクセンチュア整理」は不可）。系列ごとに上付きの番号を振り、`Source1:` `Source2:` と対応させる。算出の前提（単価・推計方法）は脚注に書く

## 8. 試算・効果・財務

- 効果の試算は「**目標 → 必要な変化量 → 施策ごとの効果 → 不足分**」の順に分解して示す（例: 年収 650 万→1,000 万には人件費 1.5 倍＝付加価値 30% 向上が必要。DX で 20%、残り 10% を別の打ち手で）
- 前提（人数・単価・稼働・立ち上がり率）は必ずページに書く（`source` の行に「試算の前提: …」）。**試算は「イメージ」の札で示さない**
- 楽観・保守の 2 案を並べると「本当に儲かるのか」に答えられる。過去の成長率から大きく外れた伸びを根拠なく置かない
- 指標は定義どおりに書く: ROI＝利益÷投下資本／ROIC＝NOPAT÷投下資本（NOPAT＝営業利益×(1−税率)）／EBITDA＝営業利益＋減価償却費／労働生産性＝付加価値÷従業員数。PL が黒字でも CF は別に見る
- デッキ内の数値は互いに合わせる: 合計＝内訳の和、要旨・効果・見積の金額と人月、期間（「8 か月」とスケジュールの月数）

## 9. ワークプラン・スケジュール

- 着手時に確かめる 4 つ: 背景／論点（どんな結果なら答えたと言えるか）／成果物（媒体・形式・量）／期限（欲しい線と、過ぎるとまずい線）
- タスクは「情報の取得 → 加工 → 仮説の更新」の単位で切り、リスクとプラン B、確認の節目（時間 20%・完成度 60% でアプローチ確認、40%・80% で方針確認）を置く
- 外部手配の所要: 社外データ依頼 3 日〜、エキスパート 2 日〜1 週間、現場訪問 1 週間〜、調査会社のアンケート 1 週間〜1 か月。スケジュールの初週にこれらを詰め込まない

## 10. 仕上げのセルフチェック（マニュアルの一覧）

- 文字: メッセージ・1 箇条は 2 行以内／重要な文は 16pt 以上、基本 12pt 以上／桁区切り／なじみの無い横文字が無い／**グラフの中までフォントを統一**（全体が日本語なら Meiryo UI、英語なら Graphik → verify_pptx の FONT-01）／英数字の全角半角が混ざらない／語の途中で改行しない・1 文字だけの行が無い／数字は右揃え
- 図形: 無駄な図・絵・写真が無い／整列し間隔が均等／パレット外の色が無い／本文がガイドの内側に収まる／線が交差しない／安っぽい素材・粗い画像が無い
- 強調は 1 方式（太字か色）に絞り、メッセージに直結する所だけ。程度は同系色の濃淡で表す。テキスト・写真・画面・ピクトグラムを 1 枚に混ぜすぎない
- デッキ全体: ①早送り（1 枚 1 秒で何の処理のページか・視線が流れるか）②声に出して読む（1 枚 1 分。キーフレーズが強調されているか）③誤字脱字・クライアントに伝わる表現か
