# 型の選び方（layout-selection）— いつ・何のために・どの型を選ぶか

人が作ったアクセンチュアの資料 52 本・本文 1425 枚の注釈から集計（参照元・本文は含まない）。各スライドに「目的・時機・話の段・内容の形・前とのつながり・デッキの種類」と、人が選んだ型（family）を注釈し、その集計から判断の規則を作った。`scripts/layout_select.py` がこの規則でスライドごとに型の上位 3 案と理由を出し、`grammar_select.py` はその型に入る構成パターン・骨格を優先する。

## 1. 使い方

1. outline の各 content スライドに `purpose`・`story_step`・`shape`・`from_prev`（と `intent`・`materials`・`density`）を書く（[outline-schema](outline-schema.md)）
2. `$PY …/layout_select.py outline.json` で型の上位案と理由・描き方（部品・骨格）を見る（`grammar_select.py` の出力にも「型:」の行が出る）
3. 1 位を基本に選ぶ。違う型にするのは、シグネチャー・実物（実データ）・内容の論理（2 軸の分類など）を優先するときだけで、その理由を `layout_reason` に 1 文で書く
4. `grammar_check` の SEL-01（人の資料が避ける選択）・SEL-02（その場面でほぼ選ばれない型）・SEL-03（同じ型の連続）を直す（`layout_reason` のあるスライドは除く）

**当たる率（デッキ単位の交差検証。人が実際に選んだ型を当てる率）**

| 手がかり | 1 位で的中 | 上位 3 位以内 |
|---|---|---|
| v6.2 までの選択（構成パターンの表引き） | 44% | 63% |
| 同じ手がかり（intent・relation・density・materials）で学習 | 60% | 83% |
| 目的・時機・話の段・内容の形だけ | 55% | 79% |
| **すべて＋直前の型（v6.3）** | **67%** | **87%** |

型を一番強く決めるのは**話の段（何の話か）と内容の形（要素数・属性数・データの種類）**。目的と時機は、同じ内容で型が割れるとき（紹介か比較か、章頭か章中か）の決め手になる。

## 9. 型ごとの選び方

### 表（`table`） — 12%（174 枚）
- 形: 行×列の表（文字主体）
- いつ: 多数の項目を3つ以上の同じ観点で横に読み比べ、後で参照させる時
- 選ぶ理由: 項目と観点の1対1の対応を行で保ち、横に比べられる
- 選ぶ理由: 7件以上・多属性でも1枚に網羅でき、参照用の一覧になる
- 選ぶ理由: 目標値・件数・担当・時期など数値や条件を同じ行に置ける
- 選ぶ理由: 同格のページが続く時、同じ列構成を保ち読み方を変えさせない
- 代わりを選ばない理由: カードは観点の横比較ができず、7件を超えると収まらない
- 代わりを選ばない理由: ツリーや工程図は目標値・条件など多属性を書き込めない
- 使わない場面: 観点が1つ、項目が1〜2個、流れや順序が主役の時
- 規則: mat_table_data=1（54%） / n_items=7+・attrs=3+（60%） / purpose=参照させる・attrs=3+（57%）
- 描き方: 部品 M-TABLE, M-ROWHEAD／骨格 K-006, K-011, K-015, K-050

### 画面・実物＋注釈（`screen`） — 11%（155 枚）
- 形: 画面キャプチャ・実物（帳票・コード・成果物）＋注釈
- いつ: 実物の画面・成果物・帳票を見せ、操作や出力の具体像を示す時
- 選ぶ理由: 実物で実在を証明し、文章より強い裏付けにする
- 選ぶ理由: 番号や赤枠で手順と画面の操作箇所を1対1で対応させる
- 選ぶ理由: 指示と出力を並べ、何を渡すと何が返るかを再現可能にする
- 選ぶ理由: 成果物の粒度・量感を縮小画像のまま伝える
- 代わりを選ばない理由: 文章や箇条では画面のどこを操作するかが分からない
- 代わりを選ばない理由: 表に書き起こすと実物感と量感が消える
- 使わない場面: 章頭で全体を掴ませる時、観点3つ以上や項目7件以上を比べる時
- 規則: mat_screenshot=1（60%） / deck_type=training・story_step=事例（68%） / story_step=事例・relation=flow（78%）
- 描き方: 部品 M-SCREEN, M-SCREEN-MOCK, M-CODE／骨格 K-053

### 工程・フロー（`process`） — 9%（123 枚）
- 形: 矢羽根・シェブロン・矢印でつないだ工程・フロー（2〜7 段。2 段でも矢印でつないでいれば process）
- いつ: 手順・工程・処理の流れなど順序のある2〜7段を示す時
- 選ぶ理由: 段の順序と、前段の出力が次段の入力になる関係を見せる
- 選ぶ理由: 全体工程を示し、後続の詳細ページの地図・現在地表示に使う
- 選ぶ理由: 工程の下に成果物・担当・判断主体を列で揃えて対応させる
- 選ぶ理由: 同じ工程配置で色や範囲だけを変え、拡大や短縮を見せる
- 代わりを選ばない理由: カードだと段が同格に見え、順序と流れが消える
- 代わりを選ばない理由: 箇条や表だと何が次工程へ渡るかの関係が見えない
- 使わない場面: 要素が並列・階層・対比の関係の時、参照用の一覧や冒頭の要旨
- 規則: relation=sequence・attrs=2（58%） / story_step=全体像・relation=sequence（74%） / deck_type=techvision・relation=sequence（77%）
- 描き方: 部品 M-CHEVRON, M-PHASE, M-DIAGRAM-FLOW／骨格 K-002, K-056, K-057, K-058

### 見出し付き文章（`text_blocks`） — 7%（94 枚）
- 形: 見出し付きの文章・箇条のブロック（図解しない）
- いつ: 論理のつながりや条件・定義を、図解せず文章で読ませる時
- 選ぶ理由: 背景→目的など因果や逆接の論旨を文章のまま保つ
- 選ぶ理由: 公式の文言・条件・計算式など細部を正確に残す
- 選ぶ理由: 固定の見出し枠を反復し、同格の紹介や逆引き資料にする
- 選ぶ理由: 演習の問題文や依頼など、読み手の行動を指示する
- 代わりを選ばない理由: 図解すると論理の接続が矢印だけになり中身が落ちる
- 代わりを選ばない理由: 表は属性が少ないと空白が目立ち、説明文が窮屈になる
- 使わない場面: 項目が7件以上ある時、数値・構造・流れを見せたい時
- 規則: story_step=手順・purpose=参照させる（100%） / deck_type=report・story_step=前提（83%） / story_step=手順・relation=parallel（60%）
- 描き方: 部品 M-BULLETS, M-HEADCOL, M-DEFBOX／骨格 K-022

### 並列カード（`cards`） — 6%（93 枚）
- 形: 同格の要素を同じ大きさの枠で 3〜6 個並べる
- いつ: 同格の要素3〜8個を同じ書式で並べ、全体を一望・記憶させる時
- 選ぶ理由: 要素が同格であることを同じ大きさの枠で形として示す
- 選ぶ理由: 章頭で全体像を見せ、後続ページの目次・入口にする
- 選ぶ理由: 見出しやアイコンで拾い読みでき、要点を記憶に残す
- 選ぶ理由: 全体の中で今回の対象だけを枠で強調し、位置づけを示す
- 代わりを選ばない理由: 表だと要点が行に埋もれ、識別子として覚えにくい
- 代わりを選ばない理由: 箇条だと同格の並びが形で伝わらない
- 使わない場面: 要素が1〜2個の時、順序や流れのある内容の時
- 規則: story_step=全体像・relation=parallel（41%） / purpose=覚えさせる・focus=False（46%） / purpose=覚えさせる・n_items=5-6（55%）
- 描き方: 部品 M-CARD, M-HEADCOL, M-BADGECOL／骨格 K-026, K-037, K-038, K-039

### 行見出し＋本文（`row_header`） — 6%（86 枚）
- 形: 左に見出し列、右に説明の行（2〜6 行）
- いつ: 性質の違う2〜6観点を左の見出しで揃え、説明を1行ずつ読ませる時
- 選ぶ理由: 定義・目的・範囲など性質の違う観点を区切って読ませる
- 選ぶ理由: 見出しと説明の対応を保ちつつ、説明の文章量を確保できる
- 選ぶ理由: 冒頭で範囲・期間・金額など提案の枠組みを1枚で確認させる
- 選ぶ理由: 課題と解決など同じ行構成で前後のページを見比べさせる
- 代わりを選ばない理由: カードだと説明文が短く切れ、同格の並びに見える
- 代わりを選ばない理由: 工程図だと観点に順序があるように見える
- 使わない場面: 同格の要素を記憶させたい時、7行超の多属性を比べる時
- 描き方: 部品 M-ROWHEAD／骨格 K-008, K-017, K-024, K-028

### 事例（`case`） — 6%（83 枚）
- 形: 事例（属性＋背景・取組・成果）
- いつ: 主張の根拠として実在の取組を属性・課題・取組・成果で示す時
- 選ぶ理由: 主張を実例で裏付け、他社の実績で納得させる
- 選ぶ理由: 固定見出しの定型で複数事例を揃え、横比較・拾い読みさせる

- 選ぶ理由: 推進の仕組みと運営のリズムを1枚で合意させる

- 代わりを選ばない理由: スケジュール図だと目的と参加者が書き込めない
- 使わない場面: 会議体の運営を合意する必要がない時
