# 情報量の多いページ（v6.5・v6.6）

人の提案書は、1 枚に 400〜900 字（中央値 639 字）を載せても読みやすい。理由は「面で区切る・段を 4 つに絞る・隙間を 3 段階に固定する・強調を 1 句に絞る」の 4 つ。生成デッキは 1 枚 149 字で、アイコンと線を主役にしていたので薄く見えた。数値はすべて人の資料（提案書・営業資料 138 枚と全 1,166 枚）の実測。

## 1. なぜ読めるのか（原則）

| 原則 | 人の資料の値 | 部品での実装 |
|---|---|---|
| 面で区切る（線は補助） | ゾーンの面は灰 F2F2F2・淡紫。枠線は 0.75pt の灰 | M-ZONE の面、M-RHMATRIX のセル |
| 文字の段は 4 つまで | ゾーン見出し 16〜18 → 小見出し 14 太字濃紫 → 本文 12（11〜14）→ 補足 9〜11。隣り合う段の差は 2pt 以上 | リッチ本文 `rich()` の段（`TYPE`） |
| 隙間は 3 段階 | セル・行 0.05〜0.11 ／ カード・列 0.08〜0.21 ／ ゾーン 0.4〜1.0 | 部品の既定値 |
| 強調は 1 句 | 本文ボックスの 38% に部分強調、うち 25% は色付き。1 ブロック 1〜2 句、1 枚 6〜10 か所 | `**語**`（太字）、特に効かせる 1 句だけ `==語==`（太字＋濃い紫）。EMPH-01/02/03 |
| 主張する側を広く・淡紫で | 比べる 2 列は 1.5〜1.7 倍、淡紫で塗る。比べられる側は白か灰 | M-RHMATRIX `col_ratios`・`emph_col` |
| ゾーン間は灰の三角 | 高さはパネルの 60〜70%、幅は隙間の 4 割、文字は入れない | `connectors: ["R-TRI"]`、M-ROWHEAD の ◀ |
| 線は役割で太さを決める | 枠 0.75 ／ 組織図 1.0 ／ 図中の矢印 1〜1.5 ／ 強調の囲み 2.25 ／ 主な流れ 6（箱の高さの 6〜17%） | figures.LINE_W。LINE-01 |
| アイコンは脇役 | 中央値 0.47in（p75 0.81in）、単色。文字の左か見出しの上 | dense.ICON・figures.ICON_IN。ICON-03 |

## 2. 11pt が許される場合

人の資料で 11pt 以下の字が出るのは、本文が 700 字以上のスライドの 79%、400〜700 字の 63%、200 字未満では 23% だけ。使う場所は限られる。

- 出典・注記・凡例（下端に 1 行）
- 太字の小見出しのすぐ下の補足（30〜110 字。2 段目の箇条書き）
- 狭い格子のセル（1.5〜1.7in 幅）、図の中のラベル、吹き出しの本文
- **使わない**: メッセージ・タイトル・ゾーン見出し・数字・字数の少ないページ

スキルでは、補足（`sub`・`note`）・出典・凡例は常に 11pt。本文の 1 段目を 11pt まで下げるのは `density: "high"` かつ本文 400 字以上のときだけ（compose が自動で判定）。TYPE-01: 11pt が本文の半分を超える／字数の少ないページで 11pt を使う。

## 3. リッチ本文（M-ZONE・M-RHMATRIX・M-STEPS・M-ROWHEAD の detail・M-CARD/M-HEADCOL の body）

```json
"body": [
  {"h": "① 記録の一元化"},                                   // 小見出し（14 太字・濃紫）
  {"p": "点検アプリ・台帳の移行・入力ルールを整える"},          // 文
  {"b": ["要点は **1 句だけ** 強調", {"text": "親の項目", "sub": ["補足（11pt）"]}], "mark": "□"},
  {"n": ["番号付きの項目", "…"]},                             // ①②
  {"concl": "2027 年度の全社展開に向け、見通しを揃える"},       // ⇒ 太字の結論
  {"note": "※ 補足（11pt・灰）"}
]
```
文字の大きさは、面を埋める最大（16 → 14 → 12、密なページは 11 まで）を自動で選ぶ。横に並ぶ M-ZONE は同じ大きさにそろう。

## 4. 型と寸法（人の例の再現）

| 型 | outline の書き方 | 寸法の要点 |
|---|---|---|
| 要旨（エグゼクティブサマリー） | `M-ZONE` `style: "summary"`、`b` に長文 3〜5 項目 | 16〜20pt、項目間 16pt。各項目 2〜3 行、要点を太字 |
| 目的と骨子 | `G-11`＋`M-ZONE`×2＋`connectors: ["R-TRI"]`、`bullet: "□"` | 帯 0.4in・濃紫・白太字、灰の面を下まで。最後に `concl` |
| Why（課題 → 強み） | `M-ROWHEAD` に `columns`・`rows[].head/sub/badge/lead/detail` | 番号 0.4 ／ 課題（淡紫）／ ◀ 三角（行の 70%）／ a/b/c 0.36×0.32 ／ 要約（太字 14）／ 縦線 0.75 ／ 詳細 |
| パッケージ概要 | `G-N3`、`ratios: [23, 50, 27]`、`M-ZONE`×3（左は `sections`、中央は `icons`） | 中央の上にアイコン 0.55in＋11pt のラベル、下に ①②③ の小見出し＋説明 |

| 行見出し × 2 列（両輪） | `M-RHMATRIX`、`title`（列の上の帯）、`columns[].label/sub`、`rows[].head/cells` | 行見出し 1.35in・灰、列見出しは文字＋0.75pt の下線、セルは灰の面。主張する列は `emph_col` |

| 実績（数字の格子） | `M-ICONGRID` の `items[].value`、`cols: 2`、左に `M-ZONE`（`emph: true`） | アイコン 0.55 ／ 数字 20 太字紫 ／ 説明 12〜14 |

## 5. 書くときの目安

- 1 枚 400〜650 字（提案書の中身のページ）、最も密なページは 600〜900 字（`density: "max"`）。DENS-01: 本文ページの字数の中央値が 300 字未満
- ゾーン 1 つに 100〜350 字。面の下が 5 割以上空く（警告「面の下が空く」）なら、根拠・数字・例を足すかゾーンを減らす
- 1 ブロックの強調は 1〜2 句。強調の語は「そのブロックの結論」（メッセージの語と一致しなくてよい）
- 1 枚の型は 1 つ（ゾーン 2〜3 個＋三角、またはマトリクス 1 つ）。部品を 3 種類以上混ぜない
