## 何をするツールか

台帳②（ONS問い合わせ管理台帳・厚労省エスカレ分）の「ONS問い合わせ」シートと、技術解説書2.1.0版の原本PDFを読み、会議の回の対象の件ごとに**下調べのひな形（Markdown）**を1本出す。1件ごとに次を並べる。

| 欄 | 中身 | 自動か |
|---|---|---|
| 経緯 | 同じ行の前回までの質問（J列・回の順）、機構コメント・ND/FJ回答・ONS回答済などの区切り（K列・古い順。見出しの名前もそのまま）、厚労省回答（L列・古い順）。すべて全文 | 自動（台帳の写し） |
| 今回のご質問 | J列の最新回の原文 | 自動（台帳の写し） |
| 基金コメント・回答案(仮) | K列の最新回と依頼区分（作成依頼／確認依頼） | 自動（台帳の写し） |
| 台帳のメモ・既存案 | L列の既存案（厚労省回答の見出しより前）、S・T列のメモ | 自動（台帳の写し） |
| 既存案の根拠の照合 | 「【参考：…P.nn 抜粋】」の各文が、**文頭から文末まで**（空白・記号を除いて）書かれたページの文字と一致するか（✅全文一致／⚠️一部の文が食い違う・別ページ〔どこから食い違うかを表示〕／❌どのページにもない）。抜粋のない「P.nnに記載のとおり」は、その文の「」の言葉（全文）がページにあるか | 自動（**文字が一致するかまで**。言い回しの正しさは見ない） |
| 似た過去回答 | 先頭に「台帳に書かれた参照」（K・S・T列の「#nnn」「INC番号」をD列で#に引き当てたもの）、続けて検索の上位5件。#・問合せ者・回答日・根拠ページ・回答の冒頭。未回答の行は「（未回答）」 | 自動（**候補・未確認**） |
| 根拠ページの候補 上位8件 | ページ・見出し・該当箇所・同じページを使った過去回答 | 自動（**候補・未確認**。□は原本で目視した印） |
| A/B区分の候補 | 台帳のメモ・依頼区分・似た過去回答・テーマの言葉・照合結果から | 自動（**推測**。決めるのは人） |
| 聞かれていること・回答案・基金仮案との比較・本田さん確認事項（相談文）・★厚労省様への相談事項（L列）・機構への連携事項（K列）・想定質問・言い回しの突き合わせ | 枠だけ（相談文・相談事項・連携事項は「要否：□」付きでいつも出す。不要なら空欄でよい） | **人が書く** |

結論・言い回しは書かない。台帳①②には書き込まない。

## 動かし方

前提：Windows の Python 3。PyMuPDF と openpyxl を使う（`python -c "import fitz, openpyxl"` で確かめる）。入っていなければ一度だけ次を実行する（このときだけネットワークを使う。ツール自体はネットワークを使わない）。

```
pip install pymupdf openpyxl
```

1. SharePoint から台帳②の最新を落とし、`Downloads` に置く（今の運用どおり。手で行う）
2. 会議の回のフォルダ（例：`ONS問合せ会議/20261020/`）があることを確かめる
3. このフォルダで実行する

```
cd "<Claudeプロジェクト>/_agent/07_ONS問合せ対応/ONS問合せ会議/00_共通/03_scripts"
python ons_shitashirabe.py --ledger "C:\Users\<ユーザー>\Downloads\(原本)【電カル共有】ONS問い合わせ管理台帳（厚労省エスカレ分）.xlsx" --round 20261020 --ids 539,540
```

- 出力：`ONS問合せ会議/20261020/02_output/20261020_ONS下調べ_v1.md`。同じ名前があれば `_v2`、`_v3`…にする（上書きしない）
- 出力したら、管理文書（その回の `更新履歴.md`・`プロジェクト状況.md`）に1行足す（ツールは更新しない）
- 読み合わせ資料（`YYYYMMDD_ONS読み合わせ資料_vN.md`）は今までどおり別に作る。下調べMDから必要な所を写す

| オプション | 意味 | 省略したとき |
|---|---|---|
| `--round YYYYMMDD` | 会議の回。出力先とファイル名に使う | 必須 |
| `--ledger <xlsx>` | 台帳② | `Downloads/(原本)【電カル共有】ONS問い合わせ管理台帳（厚労省エスカレ分）.xlsx` |
| `--ids 539,540` | 対象の#。**10/20回からは `--ids` で対象を指定して使う**（省略時の対象はユーザーに確認中） | M列（回答状況）が「ONS回答済」「取り下げ」以外の全件（差し戻し・本田さん確認中・古い未回答の#469・#508・#509なども入る） |
| `--out <フォルダ>` | 出力先を変える（試験用。過去の回のフォルダに書かないため） | `ONS問合せ会議/<回>/02_output/` |
| `--pdf <pdf>` | 技術解説書2.1.0版のPDF | `02_仕様・技術/20260723_技術解説書2.1.0版/01_input/` のPDF |

所要：1回 約10〜30秒（台帳の読み込みが大半）。初回だけPDFのページ索引を作る（`_cache/pages_index.sqlite`。PDFが変わると自動で作り直す。消してもよい。gitには入れない）。

## 台帳を壊さないための仕組み

- 台帳は**一時フォルダにコピーしてから** openpyxl の読み取り専用（`read_only=True, data_only=True`）で開く。保存の処理は書いていない（Excelで開いたままでも読める）
- 実行の前後で台帳のSHA-256を比べ、変わっていれば出力を止める。一致したことは出力の冒頭に書く
- 実行中に出る「Data Validation extension is not supported」の警告は、読み取りには影響しない（保存しないため）。画面には出さないようにしている
- 台帳の保存が3日以上前なら、出力の冒頭に⚠️を出す
- 問い合わせ者名（G列）・アドレス（H列）は出力しない

## 試験（作り直したとき・新しい回で確かめるとき）

```
python test_shitashirabe.py --ledger "<台帳xlsx>"
```

- 所要：約30秒（2026-10-16 実測 約28秒）

- 10/6回・10/13回の10件（#519・#524・#525・#530・#533〜#538）で、実際に回答に使ったページ・人が参照した過去回答と突き合わせる。結果は画面に出すだけ（過去の回のフォルダには書かない）
- 正解データはスクリプト冒頭の `GT_PAGES`・`GT_SIMILAR`。新しい回で試すときは、読み合わせ資料・台帳L列の確定回答から足す
- ほかに、抜粋の照合（台帳L列の全行）、ページを1つずらした・言葉を変えた抜粋の検出、#534（「P.132に記載のとおり『患者同意済』」）の再現、J・K列を見出しで分けられなかった行の一覧、台帳のハッシュの一致を見る

| 処理 | 関数（`ons_shitashirabe.py`） | 方法 |
|---|---|---|
| 台帳の読み込み | `load_ledger` | 1行目の見出しで列を探す（カテゴリ・#・起票日・ID・問合せ者・件名・問合せ内容・要約・内部履歴・回答案・回答状況・更新日付）。S・T列は見出しなしのメモ列として固定位置で読む |
| 往復の分割 | `split_record` | J列「【お問合せN回目】（日時）」、K列「【お問合せN回目に対する支払基金様／DX審査支払機構様コメント】」「【お問合せN回目に対するND様回答】」「【ONS回答済(…)】」、そのほか「…回答】」「…コメント】」で終わる見出し（「【お問合せ1,2回目に対するONS回答】」は2回目として扱う）等、L列「【厚労省回答】（日付）」「【お問合せN回目に対する厚労省様回答】」等。見出しの揺れは正規表現（`J_Q_RE`・`K_COMMENT_RE`・`L_ANS_RE`）で吸収。L列で最初の厚労省回答の見出しより前を「既存案」とみなす |
| ページ索引 | `build_pages`・`load_pages` | PyMuPDFで1ページずつ文字にし、ページ先頭の印刷上の番号・見出し（機能N：・表N・図N・(n)・◼の次の行）をsqliteに保存 |
| 似た過去回答 | `Engine.similar` | 件名（2倍）＋最新回の質問＋最新回の機構コメントと、各行の件名・J・K・L列を、2文字単位のTF-IDFで比べる。同じページ（技術解説書2.1.0版）を引いていれば少し加点。同じ言葉（IF番号・リソース名等）は理由の表示だけ（加点すると順位が下がったため） |
| ページ候補 | `Engine.page_candidates` | ①質問・機構コメント・同じ行の前回までの往復で引用されたページ（最大5）を先頭に置き、②残りを全文検索の順で埋めて8件。前後のページも「続きの候補」として示す |
| ページ参照の読み取り | `page_refs` | 「P.132」「p.132-133」「P.95、P.177」。直前60字に他の資料名（手引き・記述仕様・共通表・別紙・IG等）が技術解説書より近くにあれば除く。版の書きがなく起票日が2026-06-01以降なら2.1.0版と**推定**（出力に「推定」と出す） |
| 抜粋の照合 | `extract_excerpts`・`check_excerpt` | 「【参考：<資料><版> P.nn 抜粋】」から「-----」の行までを抜粋とし、文ごとに空白・記号を除いた**文全体**を、書かれたページ（＋次ページの冒頭400字）から探す。一致しない文は、文頭から何字目まで一致したかと、その先の台帳側・PDF側の文字を示す（`_diverge`）。ページ先頭の印刷上の番号は除いてから比べる |

## 分かっている限界

- 根拠にするのは**技術解説書2.1.0版だけ**（2026-10-09 ユーザー決定）。FHIR記述仕様・共通表・患者サマリー編・外部IF仕様書・別紙・保険者向け手引き・Webの資料を引いた抜粋は「―（対象外）」。FHIRの細かい質問では候補が外れやすい
- 旧版（2.0.0版・1.3.0版など）を引いた抜粋は照合できない（PDFがない）
- 図・表の画像の中の文字はPDFから取れないため、図の中身を書いた抜粋は❌・⚠️になる（例：#519「P.42 図7」）
- P.2（改版の経緯）は多くの質問の言葉と重なり、候補に入りやすい（実際に使うこともある：#537）
- 似た過去回答は件名・質問の文字の重なりが中心。言い方が違う同じ論点は落ちやすい（試験で#519→#487が検索では7位。S列のメモ「#487に類似問合せあり」があるので「台帳に書かれた参照」としては先頭に出る）。他の行の確定回答を含めて検索するため、試験の数字は当時より少し有利
- ✅は「抜粋の各文が文頭から文末まで、書かれたページの文字と一致した」ことだけを示す。抜粋の中の誤字・書き換えは⚠️で拾える（試験：#501の書き換え、#532の誤字「ステース」）が、回答の言い回しが根拠と合っているか（#519・#524の事例）は人が見る
- S・T列（見出しなしのメモ列）は位置で読む。1行目の見出しでR列が「ナレッジ化」、S・T列が空であることを確かめ、違えば出力の冒頭に⚠️を出す
- J列に回の見出し（【お問合せN回目】）がない行は全体を1回分として扱う。2026-10-15時点で230行（#1〜#230のうち221行と、#330〜#333・#355・#427・#469・#490・#491）。出力では⚠️を出す

## よくある失敗と対処

| 症状 | 原因 | 対処 |
|---|---|---|
| `ModuleNotFoundError: No module named 'fitz'`（または `openpyxl`） | ライブラリが入っていない | `pip install pymupdf openpyxl` |
| `台帳が見つかりません` | `--ledger` のパス違い・ファイル名の全角括弧の打ち間違い | エクスプローラーでファイルを Shift＋右クリック→「パスのコピー」で貼る |
| `シート「ONS問い合わせ」が見つかりません` | 別のブック（台帳①など）を指定した | 台帳②（厚労省エスカレ分）を指定する |
| `回のフォルダがありません` | `ONS問合せ会議/<回>/` がまだない | 先に回のフォルダを作る（`/new-project` 等）か、`--out` で出力先を指定 |
| `台帳に見つからない#` | `--ids` の番号が台帳にない（手元の台帳が古い） | SharePointから最新を落とし直す |
| 出力の冒頭に「⚠️ 台帳の手元コピーがN日前の保存」 | 手元の台帳が3日以上前 | 最新を落とし直してから再実行 |
| 出力の冒頭に「⚠️ 台帳の列の並びが想定と違います」 | 台帳に列が足された・消された | S・T列のメモが正しく出ているか台帳で確認し、`load_ledger` の列位置（18・19）を直す |
| `台帳のハッシュが実行前後で変わりました` | 実行中に台帳をExcelで保存した・同期で置き換わった | 台帳を閉じて再実行（ツールは保存しない） |
| `PermissionError`（台帳） | ExcelやOneDrive同期が掴んでいる | 少し待って再実行。ツールはコピーして読むので、通常はExcelで開いたままでも動く |
| 画面の文字化け・`UnicodeEncodeError` | コンソールの文字コード（cp932） | 本体・試験とも冒頭でUTF-8に切り替えている。それでも化けるときは `chcp 65001` を実行してから動かす。出力のMDはUTF-8で正しく書かれている |
| 候補のページが的外れ | 技術解説書以外の資料（記述仕様・共通表など）が根拠の質問 | 最小版の対象外。人が原本で探す |
