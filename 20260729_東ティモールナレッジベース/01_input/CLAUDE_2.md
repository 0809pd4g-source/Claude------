# Timor-Leste Knowledge Base — Claude Code向けプロジェクト指示

## プロジェクト概要

- 現行基準版：**v32.2**（2026-07-28）
- 製品：東ティモールについて、観光・生活・仕事・研究の各用途を扱う日本語の総合ナレッジベース
- 現在の元ファイル：`TimorLeste_Knowledge_Base_v32_2.html`
- 推奨するリポジトリ構成：

```text
/
├─ index.html
├─ CLAUDE.md
└─ CHANGELOG.md
```

- 正式なHTMLは**常に1ファイルだけ**とする。リポジトリへ取り込む際は、版名付きHTMLを一度だけ`index.html`へ変更し、同一内容の複製を残さない。
- 人が読む編集履歴の正本は`CHANGELOG.md`。リリースごとに必ず更新する。

## 製品目標

次の利用者が、必要な情報へ短時間で到達できることを優先する。

1. 観光・短期訪問者
2. 移住・駐在・長期滞在者
3. 求職者・雇用主・事業者
4. 研究者・現地調査者
5. 更新・運用担当者

運用担当向け機能より、一般閲覧者の情報到達を常に優先する。

## UIの必須ルール

- ヘッダーはコンパクトに保つ。1366×768、Windows表示倍率125%で、ヘッダーとサブナビを合わせて本文開始までおおむね**120px以内**を目安とする。
- 最初に見える本文の順序は原則として次を維持する。
  1. `#start-guide`
  2. `#quick-answer-search`
  3. `#key-indicators`
  4. 要旨
  5. 概要
- JSON管理、品質監査、鮮度台帳、公開判定などの運用機能を一般コンテンツより上へ移動しない。
- `.ops-section`は通常表示で非表示とし、**設定 → 運用管理を開く**を選んだ場合だけ表示する。
- 日本語の見出しやカード文言が1文字ずつ縦に折り返されないよう、中間的なPC幅でも確認する。
- 3カラムを無理に維持して中央本文を狭くしない。まず右側目次を収納し、その後に左ナビをモバイル化する。
- 装飾や管理情報を増やして、国情報への到達を遅らせない。

## 単一HTML構成

`index.html`は次をすべて内包する。

- HTML本文
- CSS
- JavaScript
- 地図画像・データ
- 主要・変動情報JSON
- 検索、絞り込み、計算機、チェックリスト、監査、書出し機能

利用者の明示的な承認なしに、フレームワーク、ビルドツール、CDN、必須API、複数ファイル構成へ変更しない。

## 重要な内部構造

### 主要・変動情報JSON

- 既定データ：`<script id="tlkb-volatile-data-default" type="application/json">`
- スキーマ：`tlkb-volatile-data`
- 複数箇所で使う変動値は、本文を個別に書き換えず、原則としてJSONレコードを更新する。
- `data-live-field`を持つ要素はJSONから描画される。未解決パスを残さない。
- 税率、料金、現職者、査証、路線、医療機関などを変更する場合、次を同時に更新する。
  - 値・説明
  - `asOf`
  - `reviewed`
  - `nextReview`
  - 出典名・URL・品質
  - `targets`

### セクションの更新メタ情報

新しい本文セクションには、既存と同じメタ情報を付ける。

- `data-reviewed`
- `data-next-review`
- `data-owner`
- `data-criticality`
- `data-information-basis`
- `data-source-quality`
- `data-update-cycle`
- `data-review-trigger`

### 概説と正式参照先

- 概説は入口、詳細セクションを正式参照先とする。
- 内容が重なる場合、概説側を短くし、詳細側へリンクする。
- 検索対策だけを目的に同じ長文を複製しない。

## 情報・出典ルール

- 出典の優先順位：東ティモール政府・公的機関 → 他国政府 → 国連・世界銀行・ADB等 → 査読研究 → 専門NGO → 信頼できる報道 → 一般二次資料。
- 実測、推計、予測、法的規定、編集上の計画値を区別する。
- 再利用する統計には、対象年、対象集団、単位、丸め方、出典を保持する。
- 価格、運航、法制度、現職者、病院、治安、気象を「現在」と書く場合は確認日を付ける。
- 利用・申請・渡航直前に公式情報へ戻る警告を削除しない。
- 確認できない現地情報を推測で埋めず、明示的に「要確認」とする。

## バージョン管理

- パッチ版（例：v32.2 → v32.3）：UI、文言、軽微な不具合修正
- 次版（例：v32.x → v33）：新しい運用能力、大規模データ更新、大きな機能追加
- メジャー版：基本構成または製品目的の根本変更

リリース時は次を整合させる。

- `<title>`
- `.brand-version`
- フッターの版・更新日
- ページ内の版履歴
- 運用履歴テーブル
- データ変更を伴う場合はJSONの`datasetId`、`datasetVersion`、`publishedAt`、title、description
- `CHANGELOG.md`

画面上の版だけを更新し、JSON内の版名を古いまま残さない。

## 完了前の必須検証

### 組込み監査

1. **設定 → 運用管理を開く**を選択する。
2. 品質・整合性監査を実行する。
3. 意味整合性監査を実行する。
4. 次を確認する。
   - 重複ID：0
   - 内部アンカー切れ：0
   - `data-live-field`未解決：0
   - メタ情報不足：0
   - JSON検証エラー：0
   - 高類似長文警告：0、または意図的な理由を記録

### 目視確認

- 1366×768、Windows表示倍率125%
- 1920×1080
- 390×844
- ブラウザ拡大100%・200%
- ヘッダー高さ、スタートカード、表の横スクロール、モバイルメニュー、右目次の収納、印刷、横方向のはみ出しを確認する。

### 機能確認

- 全文検索
- 5つの利用目的フィルター
- クイック回答
- 設定メニュー
- 運用機能の非表示／表示
- 14自治体地図
- 生物データ検索
- 旅程フィルター
- 各計算機
- チェックリスト保存
- JSON書出し・取込・復元
- 更新済み単一HTMLの書出し

## 編集手順

1. `CHANGELOG.md`の最新項目を読む。
2. 現行HTMLを調査してから構造変更を提案する。
3. 必要な範囲だけを変更し、理由なく全体を書き換えない。
4. 削除指示がない限り既存本文を保持する。
5. 重複表示値より先に構造化JSONを更新する。
6. 必須検証を実行する。
7. `CHANGELOG.md`へ、追加・変更・修正・データ・検証・残課題を追記する。
8. ユーザーが別途求めない限り、改訂HTMLは1ファイルだけ出力する。

## v32.2時点の既知の制約

- 全文対応言語は日本語のみ。ENとTETは準備中表示。
- 自治体地図は位置把握用であり、法的境界・測量・GIS用途には使えない。
- 航空便、船便、病院、査証、税務、治安、気象、求人は自動APIではなく、確認日付きの静的データ。
- ローカル保存されたチェックや確認記録は端末間で同期しない。
- スクリーンリーダー実機、iPhone・Android、実印刷の人手確認は継続運用項目。
- 埋込JSONの説明文に古いパッチ版名が残る可能性があるため、次のデータ更新版で統一する。

## 禁止事項

- 公開用・版名付き・作業用として同じHTMLを3つ生成しない。
- JSON管理や監査画面を一般ページ上部へ出さない。
- 根拠のある記述を未確認の内容へ置き換えない。
- UI簡略化を理由に、出典、確認日、警告、出典品質を削除しない。
- オフライン閲覧を壊さない。
- 明示的なデザイン依頼なしに、赤・金・ダークを中心とする東ティモールの視覚テーマを変更しない。
