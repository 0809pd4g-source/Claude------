# 作業前提：プロジェクト管理規約 ＋ 東ティモールナレッジベース固有指示

このプロジェクトは共通の管理規約に従う。作業開始時にこの前提を読み込むこと。詳細は同梱の `README_プロジェクト管理規約.md`。KB固有の詳細指示は `01_input/CLAUDE_2.md` を参照。

## フォルダ・命名
- 直下に `01_input`（原本・改変しない）／`02_output`／`03_scripts`／`04_reference`（任意）＋ `プロジェクト状況.md` ＋ `更新履歴.md`
- 成果物ファイル＝ `YYYYMMDD_名称_vN.拡張子`。改訂ごとに vN を +1、旧版は削除せず残す

## 管理文書の更新（重要・既定運用）
- **成果物を新規作成・改訂したら、明示指示がなくても同じ作業の中で必ず両方を更新する：**
  - `更新履歴.md`：版の行を追加し、最新版を **太字＋（最新）** に
  - `プロジェクト状況.md`：成果物・変更履歴（必要なら未確認事項）
- セッション開始時は、既存プロジェクトなら両文書を読んでから最新版の続きに入る

## 記述原則
出典・根拠を明記／事実と推論を区別／未確認事項を隠さない／成果物末尾に「やったこと・やっていないこと」／日付は絶対日付で記載

## KB固有：製品目標と必須ルール（`01_input/CLAUDE_2.md` より抜粋）

- 現行基準版：**v32.2**（2026-07-28）
- 正式HTMLは**常に1ファイルだけ**。改訂時は版名付きで保存し、同一内容の複製を残さない。
- CHANGELOG は `01_input/CHANGELOG.md` を正本とする。リリースごとに必ず更新する。

### UIの必須ルール
- ヘッダーはコンパクトに保つ（1366×768 / 125%で本文開始まで120px以内を目安）。
- `.ops-section`は通常表示で非表示。**設定 → 運用管理を開く**を選んだ場合だけ表示。
- 日本語の見出しやカード文言が1文字ずつ縦に折り返されないよう中間幅でも確認する。
- 3カラムを無理に維持して中央本文を狭くしない。右目次 → 左ナビの順で収納する。

### 単一HTML構成
- CSS・JavaScript・地図・JSON・各種機能をすべて1ファイルに内包する。
- ユーザーの明示的な承認なしに、フレームワーク・CDN・必須API・複数ファイル構成へ変更しない。

### バージョン管理
- パッチ版（v32.2 → v32.3）：UI・文言・軽微な不具合修正
- 次版（v32.x → v33）：新しい運用能力・大規模データ更新・大きな機能追加
- リリース時は `<title>`・`.brand-version`・フッター・ページ内版履歴・運用履歴テーブル・JSONの datasetId/publishedAt・CHANGELOG をすべて整合させる。

### 禁止事項
- 公開用・版名付き・作業用として同じHTMLを3つ生成しない。
- JSON管理や監査画面を一般ページ上部へ出さない。
- 根拠のある記述を未確認の内容へ置き換えない。
- UI簡略化を理由に出典・確認日・警告・出典品質を削除しない。
- オフライン閲覧を壊さない。
- 明示的なデザイン依頼なしに東ティモールの視覚テーマ（赤・金・ダーク）を変更しない。
